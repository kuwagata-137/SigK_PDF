# 仕様書: Phase 1 塊③-a サムネイルとテキスト

- ステータス: **草案**（2026-08-31 起草。確定前）
- 関連: `docs/05_開発ロードマップ.md` Phase 1 塊③-a ／ `docs/spec-1-1-viewer.md` ／ `docs/spec-1-2-tabs.md` ／ `docs/04_UI設計.md` 第4-1章・第10章
- 対応要件: F-01-4（サムネイル一覧）／F-01-6（テキスト選択・コピー）
- 実装: `renderer/viewer-layout.js`・`renderer/page-render.js`・`renderer/text-layer.js`・`renderer/text-layer.css`・`renderer/thumbnails.js`・`renderer/viewer.js`・`renderer/tabs.js`・`renderer/shell.js`・`index.html`・`renderer/shell.css`
- テスト: `test/viewer-layout.test.js`・`test/thumbnails.test.js`・`test/text-layer.test.js`・`test/shell.test.js`・`test/harness.js`

## 目的

塊②までで **PDF を開いて読める**ところまでは動く。ただし読むための道具が2つ欠けている。

- **長い文書のどこに居るのかが分からない。**サイドパネルは「文書を開くとページの一覧が出ます」
  という文言のまま止まっている。`docs/04` 第10章の決定2 は、サイドパネルを畳んでも読める面積が
  増えないことを実測したうえで「サムネイルは長い文書の現在位置を示す地図として効く」ことを
  既定を開いた状態にする根拠にしていた。その地図がまだ無い。
- **文字を1つも選べない。**canvas に描いているだけで、テキストは画面上に存在しない。
  引用したい1行をコピーできないのは、常用を始めるうえで痛い。

塊③-a はこの2つを埋める。**検索と印刷は塊③-b**（`docs/spec-1-4-find-print.md`）へ回す。

## 塊③ を2本に割った理由

| 理由 | 内容 |
|---|---|
| 量 | 塊② はレンダラー5本追加・テスト77件増だった。サムネイル・テキストレイヤー・検索・印刷の4本立てはそれを明らかに超え、決定7 の「終われば何かが新しくできる」単位として大きすぎる |
| 依存の向き | **テキストレイヤーは検索ハイライトの土台**である。pdf.js の検索ハイライトは、テキストレイヤーの `span` に `.highlight` を付けて表現する。先に作れば後半が素直に載る。逆は成り立たない |

## 含めるもの / 含めないもの

| 含める | 含めない |
|---|---|
| サムネイルのサイドパネル（閲覧モード・1列） | テキスト検索（塊③-b） |
| テキストレイヤーと選択・コピー | 印刷（塊③-b） |
| `viewer.js` から描画ライフサイクルの切り出し | ページモードの多列グリッド・並べ替え（塊④） |
| サイドパネルの状態とモードの保存・復元 | リンク注釈のクリック（`AnnotationLayer`。F-01 の要件に無い） |
| | 見開き表示（`spec-1-1` 確定事項12 のまま保留） |
| | サムネイルのドラッグ・複数選択（塊④） |

## 確定事項

### A. サムネイル（F-01-4）

| # | 論点 | 決定 |
|---|------|------|
| 1 | 置き場所 | `#side-scroll` の中。**閲覧モードのときだけ**出す。ページモード・注釈モード・ツールモードは従来のプレースホルダーのまま。多列グリッドは塊④ |
| 2 | 枠の作り方 | ページビューと同じ思想（`spec-1-1` 確定事項9）。**全ページ分の枠を先に置き、見えている範囲だけ描く。**総高さが最初から正しくなり、読み進めてもスクロールバーの長さが跳ねない |
| 3 | レイアウトの法則 | ページビューは「**倍率が一律で、幅は紙ごとに変わる**」。サムネイルは「**幅を揃えて、高さが紙ごとに変わる**」。法則が違うので `layoutPages` は流用せず、`layoutThumbnails()` を `renderer/viewer-layout.js` に足す。返す形は同じ（`{ index, top, height, ... }`）にして、`visibleRange()` と `currentPageIndex()` を**そのまま再利用**する |
| 4 | `renderTargets` の再利用 | 改修不要。既に `ahead` と `max` を引数で受ける（`viewer-layout.js:112`）。サムネイル側は別の値を渡すだけでよい |
| 5 | 幅 | サイドパネルの実幅に追従する（`#side-scroll` の `clientWidth` から余白を引く）。固定値にしない。サイドパネルは 180〜420px でドラッグできるため、固定だと広げても大きくならない |
| 6 | 同時に持つ canvas の上限 | **24枚。**240px 幅のパネルに A4 が約2.2枚見え、前後1ページ先読みで4〜5枚。24枚あればスクロールを少し戻したときに描き直しが起きない。**実測に基づかない初期値である**（タブ上限20と同じ扱い。`docs/07` 第6章）。常用して足りない／重いと分かった時点で見直す |
| 7 | 描画の解像度 | `thumbnailScale()` ＝ サムネイル幅 ÷ ページ幅 × `min(devicePixelRatio, 2)`。**上限はページビューの3より低い 2 にする。**サムネイルは地図であって読むものではなく、24枚を同時に持つため |
| 8 | 見た目 | `_mockup_sigkpdf.html` の `.thumbs1` に揃える。紙（`.sheet`）＋その下にページ番号（`.cap`）、間隔 10px。現在ページは枠を `--accent`、背景を `--select`、番号も `--accent`（モックの `.thumb.current`）。**モックで確定済みの意匠であり、新たに決め直さない** |
| 9 | ページ番号を出すか | **出す。**モックにあり、地図として使うなら番号が要る。紙だけでは何ページ目か分からない |
| 10 | クリック | `viewer.goToPage(index)`。ページビューが動けば、現在ページの表示は既存の経路（`syncPage`）で戻ってくる |
| 11 | 現在ページの追従 | ページビューをスクロールして現在ページが変われば、サムネイル側の枠も動かす。枠が見えていなければ `scrollIntoView({ block: 'nearest' })` で寄せる（タブと同じ作法。`spec-1-2` 確定事項21） |
| 12 | 追従で人の操作を奪わないか | 奪う。サムネイルを自分でスクロールして別の場所を見ている最中に、ページビューが動いて勝手に戻る。**ただし塊③-a では受け入れる。**現在ページが見えないサムネイルは地図として役に立たない。常用して煩わしければ「人が触った直後は一定時間追従しない」を足す |
| 13 | タブを切り替えたとき | **canvas は捨てる**（`spec-1-2` 確定事項1 の思想）。非アクティブなタブがサムネイル24枚分の canvas を持ち続けたら、タブ上限20と掛け算になる。サムネイルの**スクロール位置だけ**タブの session に持ち、戻ったときに同じ場所から見えるようにする |
| 14 | サイドパネルを畳んでいるとき | **描かない。**枠も作らない。開いた時点で作って描き始める。畳んでいる間の描画は誰にも見えない |
| 15 | サイドパネルの幅を変えたとき | 幅が変われば紙の寸法が変わるので作り直す。`renderer/shell.js` の `notifyViewportChanged()` が既に `viewer.refit()` を呼んでいるので、そこへ相乗りする。**ドラッグ中は1フレームに1回へ間引く**（ページビューと同じ `requestAnimationFrame` の作法） |
| 16 | サムネイルにテキストレイヤーを付けるか | **付けない。**サムネイルの文字を選びたい場面が無く、24枚分の `span` を作るのは無駄である |

### B. テキストレイヤーと選択・コピー（F-01-6）

| # | 論点 | 決定 |
|---|------|------|
| 17 | 実装の土台 | **pdf.js の `TextLayer` クラスを使う。自前でテキストを配置しない。**`vendor/pdf.mjs` が `TextLayer` を export していることを確認済み。`constructor({ textContentSource, container, viewport })`・`render()`・`update({ viewport })`・`cancel()`・`textDivs` を持つ。文字の位置・回転・横方向の伸縮を PDF の座標から合わせる処理は、自前で書けば必ずずれる |
| 18 | CSS の出所 | `node_modules/pdfjs-dist/web/pdf_viewer.css` の **`.textLayer` ブロックだけ**（約150行）を `renderer/text-layer.css` へ写し、先頭に出典と Apache-2.0 を明記する。`pdf_viewer.css` は全体で 6,409 行あり、使わない注釈エディタ・署名・ページめくりの CSS まで抱えることになるため `vendor/` には入れない。`THIRD-PARTY-NOTICES.md` には pdfjs-dist が既に入っている。`docs/06_ライセンス・商標チェックリスト.md` に「一部を複製した」旨を1件記録する |
| 19 | 必要な CSS 変数 | `TextLayer` の内部が呼ぶ `setLayerDimensions()` は、寸法を `round(down, var(--total-scale-factor) * Npx, var(--scale-round-x))` として書き込む。**`--total-scale-factor`・`--scale-round-x`・`--scale-round-y` が未定義だと寸法が無効になる。**`.pdf-page` へ JS から設定する（`--total-scale-factor` は `zoom × 96/72`、丸めは `1px`） |
| 20 | 貼る場所 | `.pdf-page` の中、canvas の**後ろ**（DOM 順で後ろ＝重なりで上）。`.textLayer` は `position:absolute; inset:0` なので `.pdf-page` の枠にぴったり重なる |
| 21 | 破棄 | `releasePage()` で `cancel()` を呼ぶ。canvas と同じ寿命にする。世代トークン（`state.token`）の陳腐化判定に相乗りし、遅れて届いたテキストレイヤーが、もう見ていないページに貼られないようにする |
| 22 | 倍率を変えたとき | 作り直す。`TextLayer` は `update({ viewport })` を持つが、倍率変更時は canvas ごと捨てる作りになっている（`setZoom` が `releaseAll()` する）ので、テキストレイヤーもそれに従う。経路を1本に保つ |
| 23 | コピー | **ブラウザ既定の Ctrl+C に任せる。**独自の実装を持たない。`viewer-controls.js` の `handleKey` は Ctrl+C を見ていないので奪っていない（`viewer-controls.js:122-133`） |
| 24 | ドラッグ＆ドロップとの競合 | テキストを選ぶドラッグが、ドロップの受け入れ表示を誤って出さないことを確かめる。`file-drop.js` の `carriesFiles()` が `dataTransfer.types` に `Files` があるかを見ているので通るはずだが、**推測で済ませず実測する** |
| 25 | 選択の見た目 | pdf.js の CSS がそのまま持っている（`::selection` を `AccentColor` の半透明にし、文字自体は透明のまま）。**独自に上書きしない。**canvas に描かれた文字の上に、透明な文字の選択色だけが乗る仕組みである |
| 26 | jsdom でのテスト | `TextLayer` は**スタブに差し替える**。jsdom は CSS を解釈せず、`TextLayer` は内部で canvas の 2D コンテキストを使ってフォントの高さを測るため本物は動かない。`test/harness.js` の `createPdfjsStub()` に `getTextContent()` と `TextLayer` のスタブを足す（`spec-1-1` 確定事項18 と同じ扱い） |
| 27 | 本物の描画をどこで担保するか | `npm start` の起動確認。`SIGK_SMOKE_TEXT=1` を足し、テキストレイヤーの `span` の数・ページ枠に対する位置・`window.getSelection().toString()` の実測を出す。jsdom では位置の正しさを確かめられない（`spec-0` 確定事項12） |

### C. `viewer.js` の分割

| # | 論点 | 決定 |
|---|------|------|
| 28 | なぜ今割るか | `renderer/viewer.js` は現在 507 行あり、状態・レイアウト適用・描画ライフサイクル・倍率・ページ移動・文書の開閉・セッションの退避を1本で持っている。**テキストレイヤーを足す場所がまさに描画ライフサイクルである。**足してから割るより、割ってから足すほうが差分が読める |
| 29 | 何を切り出すか | `renderPage()`・`releasePage()`・`releaseAll()`・`update()`・`scheduleUpdate()`・`canDrawCanvas()` を `renderer/page-render.js` へ。`viewer.js` に残るのは、文書の開閉・セッションの退避と復元・倍率・ページ移動 |
| 30 | 切り出しの進め方 | **振る舞いを1つも変えない。**先に切り出して既存の208件が緑のままであることを確かめ、そのあとでテキストレイヤーを足す。2つを同じコミットに混ぜない |

### D. サイドパネルの状態を覚える

| # | 論点 | 決定 |
|---|------|------|
| 31 | なぜ今か | `settings.js` にスキーマ（`sidePanel`・`mode`）と `mergeDefaults` の処理はあるのに、**保存も復元もしていない**。`main.js` は `window` と `recent` しか書かず、`renderer/app.js` は `shell.init(doc)` を引数なしで呼ぶため、毎回ハードコードの既定値（閲覧モード・開いた状態・240px）で起動する。**サムネイルが入るとサイドパネルの重みが増す**ので、半分だけ作ってある状態をここで閉じる |
| 32 | 経路 | preload に `settingsAPI`（`getUi()` / `setUi(patch)`）を足し、IPC は `settings:getUi` / `settings:setUi` の2本。`sandbox: true` のため、`fs` に触るのはメインだけ（`docs/02` 第6章） |
| 33 | 何を覚えるか | モード（`view`/`pages`/`annot`/`tools`）、サイドパネルの開閉、サイドパネルの幅の3つ。**サムネイルのスクロール位置は覚えない**（タブごとの一時的な状態であり、`settings.json` に置くものではない） |
| 34 | 書き込みの頻度 | 幅のドラッグ中に毎回書かない。**ドラッグが終わった時点で1回**。`settings.js` はアトミック書き込み（一時ファイル＋rename）なので、毎フレーム呼ぶとディスクを叩き続ける |
| 35 | この項目は切り離せる | A・B・C とは独立している。**分量や検証の都合で外す判断があってよい。**外す場合は `docs/07` 第6章の積み残しに戻す |

## 画面の動き

| 操作 | 結果 |
|---|---|
| PDF を開く | サイドパネルに全ページのサムネイルが並ぶ。1ページ目に枠が付く |
| ページビューをスクロール | 現在ページの枠が動く。枠が見えていなければサムネイルが自動で寄る |
| サムネイルをクリック | そのページの先頭へ飛ぶ |
| サイドパネルを畳む | サムネイルを捨てる。開くと作り直す |
| サイドパネルの幅を変える | サムネイルの寸法が追従する。離した時点で幅を覚える |
| タブを切り替える | サムネイルは切り替え先の文書のものに変わる。前に見ていた位置から出る |
| ページビューの文字をなぞる | 選択できる。Ctrl+C でコピーできる |
| モードを ページ／注釈／ツール に切り替える | サイドパネルは従来のプレースホルダーへ戻る（中身は塊④以降） |
| 次に起動したとき | 前回のモード・サイドパネルの開閉・幅で開く |
