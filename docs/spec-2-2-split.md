## 目的

塊① で、ツールモードと最初のツール（結合）ができた。逆向きの操作、**1つの PDF を複数に分ける**手段は
まだ無い。塊② で分割画面を載せ、塊① が部品だけ作って経路を通していなかった2つ、**出力先をアプリが
組み立てる**（出力フォルダ＋ファイル名の規則）と、**同名確認の3択に画面から到達する**を初めて使う。

## 事前調査（2026-09-03・Windows 実機・Node 24 単体・`test/fixtures/` のみ）

塊① と同じく、推測で仕様を書かないため先に実物で測った。実ファイルは使わない（`.claude/CLAUDE.md` 付則C）。
結合のワーカーと同じ道具（`copyPages` → `cleanInsertedPage` → `writeLabels` → `save` → `writeDocument`）で、
part ごとに新規文書を作って書いた。

### A. 分割の時間とメモリ

| 入力 | 分け方 | 出力数 | load | copy | save | write | 合計 | RSS の山 | 出力の合計 |
|---|---|---|---|---|---|---|---|---|---|
| huge-pages（1,000ページ） | 20ページごと | 50 | 251ms | 42ms | 387ms | 1,550ms | 2.2秒 | 85MB | 273KB |
| 同 | 4ページごと | 250 | 295ms | 53ms | 145ms | 1,892ms | 2.4秒 | 125MB | 406KB |
| 同 | 1ページごと | 1,000 | 311ms | 148ms | 483ms | 7,240ms | 8.2秒 | 130MB | 894KB |
| perf-10mb-50p | 5ページごと | 10 | 3ms | 1ms | 15ms | 104ms | 0.1秒 | 140MB | 10.2MB |
| many-pages（40ページ） | 10ページごと | 4 | 1ms | 1ms | 3ms | 38ms | 0.04秒 | 133MB | 13KB |

**分割は軽い。時間はほぼ `writeDocument` の回数に比例する**（一時ファイルへ書いて rename する2手が
1本あたり 7〜30ms）。メモリは元文書を1本抱えるぶんだけで、part は書き終えるたびに手放せる。
したがって進捗は **part 単位（書き終えた本数）** で刻む（確定事項24）。

出力数の上限を **500** に置く根拠はここにある（確定事項13）。1,000ページを1ページごとに分けても 8秒で
済むので時間が理由ではなく、「間違って1ページごとを指定したときに、気づかないまま数百本を作らせない」
ためである。結合の入力上限100（`spec-2-1` 確定事項16）・印刷の上限100ページと同じ性格である。

### B. 部品はすべて揃っている

| 要るもの | ある場所 | 足すもの |
|---|---|---|
| ページ範囲の解析（範囲抽出） | `renderer/page-range.js` `parsePageRange` | なし |
| 複製・抜け殻の掃除・ラベルの引き継ぎ | `worker/op-merge.js` の作法、`op-insert.js` `cleanInsertedPage`、`op-page-labels.js` `readLabels`／`writeLabels` | part ごとに新規文書へ写す `op-split.js` |
| 一時ファイル → rename・後始末 | `pdf-write.js` `writeDocument`、`task-runner.js` `removeLeftovers` | 後始末を出力先の**配列**に対応させる |
| 進捗の帯（n / N ファイル）・中止 | `task-runner.js` `phaseStep` の `done`／`of`、`renderer/save.js` `runTask` | なし |
| 同名確認の3択 | `renderer/confirm-replace.js`、`tools-merge.js` `resolveTarget` | 「N 件」の文言 |
| 入力ファイルのページ数を読む | `tools-merge.js` の私有 `inspect` | `tool-source.js` へ移して共用 |
| ファイル選択・存在確認 | `file-io.js` `pickMergeSources`・`exists` | `pickFolder`（フォルダ選択）、1本選ぶ口 |
| フォルダを開く | — | `shell.showItemInFolder` を IPC 1本で |

### C. `showItemInFolder` は Electron の `shell` にある

`shell.showItemInFolder(fullPath)` はエクスプローラーでそのファイルを選択した状態で開く。同期・戻り値なし。
メインだけが呼べるので `shell:showInFolder` を1本足し、**実在するファイルのパスのときだけ**呼ぶ
（レンダラーから任意のパスでエクスプローラーを開かせない）。

## 確定事項

### A. 対象ファイル（ユーザー確定①）

| # | 項目 | 決定 |
|---|---|---|
| 1 | 入力の数 | **1ファイルだけ**。画面には対象を1行（ファイル名・ページ数・フルパスのツールチップ）で出す |
| 2 | 対象の決め方 | 3経路。「開いているファイル」（アクティブなタブの文書）、「ファイルを選ぶ…」（`pdfAPI.pickSplitSource`。1本）、PDF のドロップ（`file-drop.js` はツールモードで**選択中のツール**へ渡す。塊① は結合固定だったのを直す） |
| 3 | 開いているファイル | タブが無ければ帯で「開いているファイルがありません。」。未保存のタブなら行に「未保存の編集は反映されません」（`spec-2-1` 確定事項11 と同じ文言・同じ理由。ファイルを読み直して分けるため） |
| 4 | ページ数を読む | `renderer/tool-source.js` の `inspectPdf(path)`（塊① の `inspect` を移す）。pdf.js で `numPages` だけ読んで手放す。暗号化は `{ encrypted: true }`、壊れていれば `{ error }` を返し、文言は呼ぶ側が決める。分割では「保存できない PDF です（パスワード付き）」「この PDF を開けません」で、対象にはなるが**実行できない** |
| 5 | 差し替え | 対象は1つなので、新しく決めれば前のものと入れ替わる。方式と出力の設定は**そのまま残す**（同じ設定で別のファイルを分ける使い方があるため） |
| 6 | `--split` への備え | `SigK.toolsSplit.useFromLaunch(paths)`：ツールモードへ切り替え、分割を選び、**先頭の1本**を対象にする。2本以上来たら帯で「1つ目のファイルだけを対象にしました」（文言は Phase 5 で見直す）。塊② では呼ぶ側を作らない（`launch.js`・`launch-args.js`・`main.js` の `queueLaunch` は触らない） |

### B. 分け方（F-03-3〜F-03-5・ユーザー確定②）

| # | 項目 | 決定 |
|---|---|---|
| 7 | 方式の選び方 | ラジオ3つ。「N ページごと」「指定したページの前で切る」「範囲を取り出す」。既定は「N ページごと」 |
| 8 | N ページごと（F-03-3） | 数値欄。1 以上の整数。既定 1。N がページ数以上なら**1本**になる（誤りではない。出力の例で「1 ファイル」と見せる） |
| 9 | 指定したページの前で切る（F-03-4） | 文字列欄。`3,7` のようにカンマ区切りでページ番号を書く。**そのページの前**で切る。`3,7` → `1-2 / 3-6 / 7-末尾`。受ける番号は 2〜ページ数。1 は「前で切れない」ので誤り、ページ数超えも誤り、重複も誤り（黙って畳まない）。順不同は許し昇順に並べ直す。全角は `page-range.js` の `normalize` で寄せる |
| 10 | 範囲を取り出す（F-03-5） | 文字列欄。`1-3,5,8-` を `parsePageRange` で読み、**書いた順にページを並べた1本**を出す（ユーザー確定②）。空欄は「全ページ＝そのまま1本」で、誤りではないが意味が無いので出力の例に「元と同じ 40 ページ」と出す |
| 11 | 解析の場所 | `renderer/split-plan.js`（新設・純関数・依存なし）。`planSplit({ mode, every, at, range }, pageCount)` → `{ parts: number[][] }`（0始まり）か `{ error }`。方式ごとの誤りの文言もここで返す |
| 12 | 誤りの扱い | 入力欄を赤くし、欄の下に文言を出し、「実行」を押せなくする（結合の確定事項20 と同じ作法）。選んでいない方式の欄は検証しない |
| 13 | 出力数の上限 | **500 本**。超えると誤り「500 ファイルまでです（いまの指定では 1,000 ファイルになります）」。根拠は事前調査 A |

### C. 出力先とファイル名の規則（F-03-6・ユーザー確定③）

| # | 項目 | 決定 |
|---|---|---|

| 16 | 連番の桁 | 出力数の桁数と 3 の大きいほう（12 本なら `001`〜`012`、1,000 本は上限で弾かれる）。1 本でも `_001` |

| 20 | 出力先が対象と同じ | 規則上あり得ない（必ず接尾辞が付く）が、念のため実行前に照合して断る（結合の確定事項24 と同じ） |

### D. 実行と同名確認（2-5・`docs/04` 第7章）

| # | 項目 | 決定 |
|---|---|---|
| 21 | 実行前の判定 | 出力パスの配列を組み、`pdfAPI.exists` を**全件**見る。1件でもあれば `confirmReplace.ask({ name: 最初の同名, count: 同名の数 })` を**1回だけ**出す（本数ぶん聞かない） |

## 実装の記録（2026-09-04・`claude/phase-2-split` ブランチ）

確定事項1〜41 をそのまま実装した。仕様書から変えた点・足した点は次のとおり。

| 項目 | 仕様書 | 実装 | 理由 |
|---|---|---|---|
| 中止時の「書き出し済み N 本」 | 結果の `written` | `save.js` に最後の進捗を覚える `lastProgress()` を足し、`write` の `done` を読む | 中止の結果 `{ canceled }` に本数は無い。出力先の有無で数えると、上書き前からあったファイルまで数える（起動確認で空の下地を1本と数えた） |
| ワーカーの進捗 | `apply`・`save` は合図だけ | 同じ。`write` の `done` は 0 から始める（`advance('write', 0, n)`） | 帯が「0 / 12 ファイル」から出て、1本目の書き出し中も動いていると分かる |
| 「開いているファイル」のアイコン | — | `modeView`（閲覧のアイコン）を流用 | 新しい絵を増やさない |
| `tools-merge.js` の `inspect` | `tool-source.js` へ移す | 移した。`inspectPdf` は `{ reason, error }` を返し、「外してください」「選び直してください」の続きは呼ぶ側が足す | 文言の違いを共用側に持たせない |
| 入力欄のフォーカス | — | 欄にフォーカスが入ったらその方式を選ぶ | ラジオまで戻らせない |
| 起動確認 | `SIGK_SMOKE_SPLIT` ＋ `_MODE`・`_OUT`・`_RULE`・`_CANCEL`・`_STAY` | `_STAY` は作らなかった（分割はタブを開かず画面に留まるので要らない）。出力先は省略時に一時フォルダー（fixtures の隣に散らかさない）。3択を通すため、メインが先頭の出力先を空で作ってから画面の `run()` を回す | 保存ダイアログは無いので、画面の「実行」と同じ `run()` をそのまま呼べる |
