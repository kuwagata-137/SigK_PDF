## 1. 基本方針

### 1-1. 1つのウィンドウで作業が続くこと

製品の位置づけ（`docs/01_製品要件定義.md` 第1章）どおり、ツールごとに画面が切り替わって終わる作りにはしない。文書を開いたまま、ページ操作・注釈・書き出しを行き来できることを最優先にする。

そのために画面を「モード」で切り替える。モードが変わっても中央のページ表示は残り続け、左のパネルと右のパネルだけが入れ替わる。

### 1-2. 見た目は CheckListMaker と揃える

同一作者の Windows デスクトップアプリとして、配色・角丸・影・タイポグラフィを CheckListMaker の「モダンUI仕様」から引き継ぐ。ユーザーが2つのアプリを行き来したときに、同じ製品群だと分かることを狙う。

ただし**ダークモードは引き継がない**（ユーザー判断 2026-08-29）。CheckListMaker はダークを持つが、本アプリはライト1本で作る。使う予定がないものを二重に保守しないためである。

副次的な効果として、これは調査要件レポート第7-3章（トレードドレスの模倣回避）への回答にもなる。既存の商用 PDF 製品の視覚的語彙を参照せず、自分たちの既存アプリの語彙を使うためである。

### 1-3. 依存を増やさない

CheckListMaker の方針をそのまま引く。**外部 CDN・Web フォント・アイコンライブラリを使わない。**

- フォントは OS 標準（`Segoe UI`、`Yu Gothic UI`、`Meiryo`）を指定する。
- アイコンはインライン SVG を自作する。`assets/icons.js` に 24×24 の `viewBox` で定義し、`currentColor` で塗る。
- アイコンの形は、機能を素直に示す幾何形状にとどめる。他社製品のアイコンを参照しない。

## 2. デザイントークン

CheckListMaker `docs/モダンUI仕様.md` のライトの値をそのまま使う。**ダークは持たない**（1-2）。
`<meta name="color-scheme" content="light">` を置き、OS がダーク設定でもフォーム部品・スクロールバー・
既定の配色が暗転しないようにする。

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` | `#eef1f5` | ウィンドウ背景 |
| `--surface` | `#ffffff` | パネル面 |
| `--surface-2` | `#eff2f6` | 補助面・ホバー |
| `--text` | `#1c2430` | 本文 |
| `--muted` | `#5f6b7a` | 補助テキスト |
| `--border` | `#dfe3e8` | 境界線 |
| `--border-strong` | `#c4cbd3` | 強めの境界 |
| `--primary` / `--accent` | `#2f6feb` | アクセント（1色） |

### 本アプリで足すトークン

PDF ビューアに固有の面がいくつかある。CheckListMaker には無いため新設する。

| トークン | 値 | 用途 |
|---|---|---|
| `--canvas` | `#8b93a1` | ページの背後の台。紙が浮いて見える濃さにする |
| `--page` | `#ffffff` | ページ（紙） |
| `--page-shadow` | `0 1px 3px rgba(16,24,40,.28), 0 8px 20px rgba(16,24,40,.22)` | ページの落ち影 |
| `--select` | `rgba(47,111,235,.14)` | サムネイルの選択状態 |
| `--danger` | `#d64545` | 削除・破棄など戻せない操作 |

影（`--shadow` `--shadow-hover` `--shadow-item` `--topbar-shadow`）は CheckListMaker のライトの値をそのまま使う。
角丸は `--radius: 10px` を基本とし、小さな部品は 6〜8px を使う（CheckListMaker と同じ）。

## 3. 画面の構成

```
┌──────────────────────────────────────────────────────────────────────┐
│ タイトルバー（OS 標準の枠。独自に描かない）                          │
├──────────────────────────────────────────────────────────────────────┤
│ タブバー   [ 報告書.pdf ×][ 見積書.pdf ×][ ＋ ]                      │
├──────────────────────────────────────────────────────────────────────┤
│ ツールバー [開く][保存] │ [◀ 3 / 24 ▶] │ [－ 100% ＋][幅][全体] │ [🔍]│
├────┬──────────────┬──────────────────────────────────┬───────────────┤
│ツー│ サイドパネル │  ページビュー                    │ プロパティ    │
│ルレ│              │                                  │（注釈モード   │
│ール│ モードごとに │  ページを縦に連続表示            │  のときだけ） │
│    │ 中身が変わる │  --canvas の上に --page が浮く   │               │
│閲覧│              │                                  │               │
│ペー│ 閲覧: サムネ │                                  │               │
│ ジ │ ページ: 一覧 │                                  │               │
│注釈│ 注釈: 注釈一覧│                                  │               │
│ツー│ ツール: 一覧 │                                  │               │
│ ル │              │                                  │               │
├────┴──────────────┴──────────────────────────────────┴───────────────┤
│ ステータスバー  報告書.pdf │ 24ページ │ 2.4MB │ 変更あり             │
└──────────────────────────────────────────────────────────────────────┘
```

| 領域 | 幅・高さ | 内容 |
|---|---|---|
| タブバー | 36px | 開いている文書。中クリックで閉じる。未保存は名前の右に点を出す |
| ツールバー | 44px | 常に同じ並び。モードで内容を変えない。`--topbar-shadow` で前面に見せる |
| ツールレール | 72px | モード切り替え。アイコン（21px）＋ラベル（10.5px）。選択中はアクセント色の縦棒を左端に出す。モックで実測し、ラベルを出しても 72px で収まることを確認した |
| サイドパネル | 240px（ドラッグで 180〜420px） | モードごとに中身が入れ替わる。折りたたみ可。**起動時は開いた状態を既定とする** |
| ページビュー | 残り全部 | `--canvas` の上にページを並べる |
| プロパティ | 260px | 注釈モードで、注釈を選んでいるときだけ出る |
| ステータスバー | 26px | ファイル名・ページ数・サイズ・変更の有無 |

ツールバーの内容をモードで変えないのは、モードを切り替えるたびにボタンの位置が動くと、狙って押せなくなるためである。モード固有の操作はサイドパネルとプロパティに置く。

## 4. モード

ツールレールで切り替わる4つのモード。中央のページビューは常に残る。

### 4-1. 閲覧モード（既定）

- サイドパネル: ページのサムネイル（1列）。現在ページを枠で示す。
- ページビュー: 連続スクロール。テキスト選択が有効。
- 対応要件: F-01-1〜F-01-8

### 4-2. ページモード

- サイドパネル: サムネイルの多列グリッド。ドラッグで並べ替え、Ctrl/Shift で複数選択。
- サムネイルにホバーすると、その場に回転・削除の小さなボタンが出る。
- サイドパネル下部に、選択中のページに対する操作（回転・削除・抽出・挿入）を並べる。
- ページビュー: 選択中のページへ追従する。
- 対応要件: F-02-1〜F-02-7

ページモードでは、削除しても即座にファイルへ書き戻さない。操作は `ops`（`docs/02_アーキテクチャ設計.md` 第2-3章）として積まれ、保存したときに初めて反映される。取り消しは Ctrl+Z で戻せる。

### 4-3. 注釈モード

- ツールレールの下に、注釈の道具（ハイライト・下線・取り消し線・テキスト・図形・ペン・ノート）を並べる。
- サイドパネル: 文書内の注釈一覧。クリックで該当箇所へ飛ぶ。
- プロパティ（右）: 選択中の注釈の色・線幅・不透明度・フォントサイズ。
- 対応要件: F-05-1〜F-05-7

### 4-4. ツールモード

結合・分割・変換・透かしを置く。右クリックメニューからの起動（`--merge` など）は、このモードの該当画面を直接開く。

- サイドパネル: ツールの一覧。
- ページビュー領域: 選んだツールの作業画面に置き換わる。ここだけは中央がページ表示でなくなる。
- 対応要件: F-03-1〜F-03-6、F-04-1〜F-04-4、F-05-8〜F-05-10

## 5. 右クリックメニューから起動したときの見え方

`docs/03_Windowsシェル統合設計.md` 第3章のとおり、起動要求は `{ intent, paths }` として届く。

| intent | 起動直後の画面 |
|---|---|
| `open` | 閲覧モード。渡されたファイルをタブで開く |
| `merge` | ツールモードの結合画面。渡されたファイルが一覧に入っている |
| `split` | ツールモードの分割画面。渡されたファイルが対象に入っている |
| `toPdf` | ツールモードの画像→PDF 画面。渡された画像が一覧に入っている |

結合画面には**並び順に関する注記を出す**。シェルから渡されるパスの順序は、エクスプローラー上の並び順と一致する保証がないためである（`docs/03_Windowsシェル統合設計.md` 第3-2章）。

> 並び順はエクスプローラーの表示順と異なることがあります。ドラッグで入れ替えてください。

この注記は、右クリックから起動したときだけ出す。アプリ内でファイルを追加した場合は追加順で確定するため不要である。

## 6. 進捗と中止

重い処理の間もウィンドウを固まらせないことが非機能要件にある。進捗の見せ方を統一する。

- 1秒を超えそうな処理は、ページビューの上に帯状の進捗を出す。モーダルで画面全体を塞がない。
- 進捗には「何をしているか」「何件中何件か」「中止」を出す。
  例: `結合しています  3 / 5 ファイル  [ 中止 ]`
- 中止はワーカープロセスの終了で行う。中止した場合、出力ファイルは作らない。書きかけがあれば削除する。

## 7. 戻せない操作の扱い

`.claude/CLAUDE.md` 付則C を画面に落とす。

| 操作 | 扱い |
|---|---|
| ページ削除 | 確認を出さない。`ops` に積むだけで、Ctrl+Z で戻せるため |
| 注釈のフラット化 | **確認を出す。**「注釈を書き込みとして焼き付けます。以後この注釈は編集できません」 |
| 上書き保存 | 確認を出さない。ただし保存前に、元ファイルと同名の `.bak` を残すかどうかを設定で選べるようにする |
| 出力先に同名ファイルがある | **確認を出す。**「上書き」「別名で保存」「中止」の3択 |
| タブを閉じる／アプリを終了（未保存あり） | **確認を出す。**「保存」「保存しない」「キャンセル」の3択 |

確認のダイアログは、破棄・上書きにあたるボタンを `--danger` で塗る。既定のフォーカスは安全側（キャンセル）に置く。

## 8. キーボード操作

| キー | 動作 |
|---|---|
| Ctrl+O / Ctrl+S / Ctrl+Shift+S | 開く / 上書き保存 / 名前を付けて保存 |
| Ctrl+W / Ctrl+Tab | タブを閉じる / 次のタブ |
| Ctrl+F / F3 / Shift+F3 | 検索 / 次を検索 / 前を検索 |
| Ctrl+Z / Ctrl+Y | 元に戻す / やり直し |
| Ctrl+P | 印刷 |
| Ctrl+＋ / Ctrl+－ / Ctrl+0 | 拡大 / 縮小 / 100% |
| PageUp / PageDown / Home / End | ページ移動 |
| Delete | 選択中のページ（ページモード）／注釈（注釈モード）を削除 |
| Esc | 選択を解除。検索バーを閉じる |

`:focus-visible` のリングを全操作要素に出す。`prefers-reduced-motion: reduce` でトランジションを止める。いずれも CheckListMaker と同じ扱いである。

## 9. アイコン

`assets/icons.js` に定義する。24×24 の `viewBox`、線幅 1.75、`stroke="currentColor"`、`fill="none"`、端は丸める。

## 10. モックと確定の経緯

配置の確認用モックは `_mockup_sigkpdf.html` として作る。`.gitignore` は `_mockup_*.html` を
無視する一方で、`!_mockup_sigkpdf.html` でこの1本だけを例外にしてある（コミット済み）。
**使い捨てにはしない。**Phase 0 の作業 0-4「デザイントークンと画面の骨組み」の下地として
そのまま育て、`index.html` と `renderer/*` へ移す（`docs/07_開発計画の決定事項.md` 決定11）。

1280×800（`docs/spec-0-foundation.md` 確定事項12 の初期ウィンドウサイズ）で描画し、
スクリーンショットで確認した。以下は 2026-08-29 に確定した。

**2026-08-31 追記。**Phase 0 以降は実機の `npm start` で確認する（`docs/07` 決定17）。
`SIGK_SMOKE=1` を付けると `getBoundingClientRect()` と `getComputedStyle()` の実測値が
出るので、モックとの一致を目でなく数値で確かめられる。`SIGK_SMOKE_SHOT=<path>` で
スクリーンショットも残せる（`screenshots/phase0-shell.png` がその出力）。

Phase 0 の実装では、モックの**画面の枠組み**だけを移した。疑似的なページ内容
（`.page` / `.ln` / `.t-ln` / `--ink`）は移していない。Phase 1 で pdf.js の実描画に
置き換わるため、移すと必ず消すことになるからである。ツールレールはモックの
56px 既定＋`data-rail` による分岐をやめ、72px 固定にした（決定14 で確定済みであり、
分岐する理由がない）。
