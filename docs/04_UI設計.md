## 1. 基本方針

### 1-1. 1つのウィンドウで作業が続くこと

製品の位置づけ（`docs/01_製品要件定義.md` 第1章）どおり、ツールごとに画面が切り替わって終わる作りにはしない。文書を開いたまま、ページ操作・注釈・書き出しを行き来できることを最優先にする。

そのために画面を「モード」で切り替える。モードが変わっても中央のページ表示は残り続け、左のパネルと右のパネルだけが入れ替わる。

### 1-2. 見た目は CheckListMaker と揃える

同一作者の Windows デスクトップアプリとして、配色・角丸・影・タイポグラフィを CheckListMaker の「モダンUI仕様」から引き継ぐ。ユーザーが2つのアプリを行き来したときに、同じ製品群だと分かることを狙う。

ただし**ダークモードは引き継がない**（ユーザー判断 2026-08-29）。CheckListMaker はダークを持つが、本アプリはライト1本で作る。使う予定がないものを二重に保守しないためである。

副次的な効果として、これは調査要件レポート第7-3章（トレードドレスの模倣回避）への回答にもなる。既存の商用 PDF 製品の視覚的語彙を参照せず、自分たちの既存アプリの語彙を使うためである。

### 1-3. 依存を増やさない

CheckListMaker の方針をそのまま引く。**外部 CDN・Web フォント・アイコンライブラリを使わない。**

- フォントは OS 標準（`Segoe UI`、`Yu Gothic UI`、`Meiryo`）を指定する。
- アイコンはインライン SVG を自作する。`assets/icons.js` に 24×24 の `viewBox` で定義し、`currentColor` で塗る。
- アイコンの形は、機能を素直に示す幾何形状にとどめる。他社製品のアイコンを参照しない。

## 2. デザイントークン

CheckListMaker `docs/モダンUI仕様.md` のライトの値をそのまま使う。**ダークは持たない**（1-2）。
`<meta name="color-scheme" content="light">` を置き、OS がダーク設定でもフォーム部品・スクロールバー・
既定の配色が暗転しないようにする。

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` | `#eef1f5` | ウィンドウ背景 |
| `--surface` | `#ffffff` | パネル面 |
| `--surface-2` | `#eff2f6` | 補助面・ホバー |
| `--text` | `#1c2430` | 本文 |
| `--muted` | `#5f6b7a` | 補助テキスト |
| `--border` | `#dfe3e8` | 境界線 |
| `--border-strong` | `#c4cbd3` | 強めの境界 |
| `--primary` / `--accent` | `#2f6feb` | アクセント（1色） |

### 本アプリで足すトークン

PDF ビューアに固有の面がいくつかある。CheckListMaker には無いため新設する。

| トークン | 値 | 用途 |
|---|---|---|
| `--canvas` | `#8b93a1` | ページの背後の台。紙が浮いて見える濃さにする |
| `--page` | `#ffffff` | ページ（紙） |
| `--page-shadow` | `0 1px 3px rgba(16,24,40,.28), 0 8px 20px rgba(16,24,40,.22)` | ページの落ち影 |
| `--select` | `rgba(47,111,235,.14)` | サムネイルの選択状態 |
| `--danger` | `#d64545` | 削除・破棄など戻せない操作 |

影（`--shadow` `--shadow-hover` `--shadow-item` `--topbar-shadow`）は CheckListMaker のライトの値をそのまま使う。
角丸は `--radius: 10px` を基本とし、小さな部品は 6〜8px を使う（CheckListMaker と同じ）。

## 3. 画面の構成

```
┌──────────────────────────────────────────────────────────────────────┐
│ タイトルバー（OS 標準の枠。独自に描かない）                          │
├──────────────────────────────────────────────────────────────────────┤
│ タブバー   [ 報告書.pdf ×][ 見積書.pdf ×][ ＋ ]                      │
├──────────────────────────────────────────────────────────────────────┤
│ ツールバー [開く][保存] │ [◀ 3 / 24 ▶] │ [－ 100% ＋][幅][全体] │ [🔍]│
├──────────────────────────────────────────────────────────────────────┤
│ 道具の段（編集モードだけ） [ハイライト][下線]…[四角][丸]…[ノート]    │
├────┬──────────────┬──────────────────────────────────┬───────────────┤
│ツー│ サイドパネル │  ページビュー                    │ プロパティ    │
│ルレ│              │                                  │（注釈モード   │
│ール│ モードごとに │  ページを縦に連続表示            │  のときだけ） │
│    │ 中身が変わる │  --canvas の上に --page が浮く   │               │
│閲覧│              │                                  │               │
│ペー│ 閲覧: サムネ │                                  │               │
│ ジ │ ページ編集:  │                                  │               │
│    │  一覧        │                                  │               │
│編集│ 編集: サムネ │                                  │               │
│    │ か注釈一覧   │                                  │               │
│ツー│ ツール: 一覧 │                                  │               │
│ ル │              │                                  │               │
├────┴──────────────┴──────────────────────────────────┴───────────────┤
│ ステータスバー  報告書.pdf │ 24ページ │ 2.4MB │ 変更あり             │
└──────────────────────────────────────────────────────────────────────┘
```

| 領域 | 幅・高さ | 内容 |
|---|---|---|
| タブバー | 36px | 開いている文書。中クリックで閉じる。未保存は名前の右に点を出す |
| ツールバー | 44px | 常に同じ並び。モードで内容を変えない。`--topbar-shadow` で前面に見せる |
| 道具の段 | 約 62px | 編集モードのときだけ出す（ほかのモードでは場所も取らない）。CheckListMaker の画像エディタと同じく、35px の四角いボタンの下に名前。ハイライト・下線・取り消し線｜テキスト｜矢印・直線・四角・丸｜ペン・ノート（2026-09-29。`docs/07` 決定47 ⑩⑪、`docs/spec-4b-1a-edit-mode.md`） |
| ツールレール | 72px | モード切り替え（閲覧・ページ編集・編集・ツール。2026-09-29 決定47 ⑫）。アイコン（21px）＋ラベル（10.5px）。選択中はアクセント色の縦棒を左端に出す。モックで実測し、ラベルを出しても 72px で収まることを確認した |
| サイドパネル | 240px（ドラッグで 180〜420px） | モードごとに中身が入れ替わる。折りたたみ可。**起動時は開いた状態を既定とする**。編集モードでは見出しの切り替えで「サムネイル」（既定）と「注釈一覧」を替え、選んだ側を覚える（2026-09-29 決定47 ⑬） |
| ページビュー | 残り全部 | `--canvas` の上にページを並べる |
| プロパティ | 260px | 編集（注釈）モードの間は常に出す（何も選んでいないときは「次に付ける」書き込みの種類と色・文字の大きさ。2026-09-15 決定33 ①） |
| ステータスバー | 26px | ファイル名・ページ数・サイズ・変更の有無 |

ツールバーの内容をモードで変えないのは、モードを切り替えるたびにボタンの位置が動くと、狙って押せなくなるためである。モード固有の操作はサイドパネルとプロパティに置く。
編集モードの道具だけは、ツールバーを変えずに、その下へもう 1 段を足して並べる（2026-09-29 決定47 ⑩。モードを替えると表示域の
高さと幅が変わるので、「幅」「全体」で追従していれば倍率を計算し直す。`spec-4b-1a` 確定事項19）。

## 4. モード

ツールレールで切り替わる4つのモード。中央のページビューは常に残る。**2026-09-29 から画面の呼び名は 閲覧・ページ編集・編集・ツール**
（決定47 ⑫。紙に付けたもの 1 つひとつは「書き込み」、一覧の名前は「注釈一覧」）。本書の節の名前と仕様書・コードの中では、
今までどおり「ページモード」「注釈モード」「注釈」と呼ぶ。

### 4-1. 閲覧モード（既定）

- サイドパネル: ページのサムネイル（1列）。現在ページを枠で示す。
- ページビュー: 連続スクロール。テキスト選択が有効。
- 対応要件: F-01-1〜F-01-8

### 4-2. ページモード

- サイドパネル: サムネイルの多列グリッド。ドラッグで並べ替え、Ctrl/Shift で複数選択。
- サムネイルにホバーすると、その場に回転・削除の小さなボタンが出る。
- サイドパネル下部に、選択中のページに対する操作（回転・削除・抽出・挿入）を並べる。
- ページビュー: 選択中のページへ追従する。
- 対応要件: F-02-1〜F-02-7

ページモードでは、削除しても即座にファイルへ書き戻さない。操作は `ops`（`docs/02_アーキテクチャ設計.md` 第2-3章）として積まれ、保存したときに初めて反映される。取り消しは Ctrl+Z で戻せる。

### 4-3. 注釈モード

- ツールレールの下に、注釈の道具（ハイライト・下線・取り消し線・テキスト・図形・ペン・ノート）を並べる。
- サイドパネル: 文書内の注釈一覧。クリックで該当箇所へ飛ぶ。
- プロパティ（右）: 選択中の注釈の色・線幅・不透明度・フォントサイズ。
- 対応要件: F-05-1〜F-05-7

### 4-4. ツールモード

結合・分割・変換・透かし・フラット化を置く。右クリックメニューからの起動（`--merge` など）は、このモードの該当画面を直接開く。

- サイドパネル: ツールの一覧。
- ページビュー領域: 選んだツールの作業画面に置き換わる。ここだけは中央がページ表示でなくなる。
- 対応要件: F-03-1〜F-03-6、F-04-1〜F-04-4、F-05-8〜F-05-10

> **2026-09-24 追記（Phase 4 塊⑤。`docs/spec-4-5-watermark-flatten.md`）。**ツール一覧の PDF→画像の後ろに「透かし」と
> 「フラット化」が増えた。どちらも対象は 1 ファイル（開いているファイル／ファイルを選ぶ／ドロップ）で、結果は別の新しい
> ファイルに書いて新しいタブで開き、元のファイルは変えない。出力先は「実行…」を押したときの保存ダイアログで決める
> （1 本を書き出す結合と同じ）。**透かし**は左に対象・透かし（種類・文字か画像・大きさ・色・不透明度・向き・位置の 3×3）・
> ページの 3 節、右に対象のページへ透かしを重ねたプレビュー。**フラット化**は対象と「焼き込む注釈」（まとまりごとの件数・
> 焼き込まずに残すもの・失うもの）の 2 節で、実行前に確認を出す（第7章）。モックは `screenshots/phase4-watermark.png`・
> `phase4-flatten.png`・`phase4-flatten-confirm.png`、実機の画面は同じ名前の `-app.png`。

## 5. 右クリックメニューから起動したときの見え方

`docs/03_Windowsシェル統合設計.md` 第3章のとおり、起動要求は `{ intent, paths, batch: { id, first } }` として 1 件ずつ届く。右クリックで N 個選ぶと N 件届き、同じ操作が 2 秒以内に続いたものは同じ「束」の印を持つ（2026-09-28 改訂。Phase 5 塊①の実装に合わせた。`docs/spec-5-1-context-menu.md`）。

| intent | 起動直後の画面 |
|---|---|
| `open` | 渡されたファイルをタブで開く。ツールモードにいれば閲覧モードへ移る（ページ・注釈モードは文書が見えているのでそのまま） |
| `merge` | ツールモードの結合画面。渡されたファイルが一覧に入っている |
| `split` | ツールモードの分割画面。渡されたファイル（2 本以上ならファイル名の順の先頭 1 本）が対象に入っている |
| `toPdf` | ツールモードの画像→PDF 画面。渡された画像が一覧に入っている |

画面を切り替えるのは束の最初の要求だけである。同じ束の 2 件目以降は切り替えないので、束が届いている間にユーザーが画面を移っても引き戻さない。

結合と画像→PDF では、束の行を**ファイル名の順**に並べる。シェルから渡されるパスの順序は、エクスプローラー上の並び順と一致する保証がないためである（`docs/03_Windowsシェル統合設計.md` 3-2）。束の行が 2 つになったときに、次の帯を束につき 1 回出す。

> ファイル名の順に並べました。エクスプローラーの並びと違うときは、ドラッグで入れ替えてください。

この帯は右クリックから届いたときだけ出す。アプリの中で足したファイル（ファイルを選ぶ・開いているファイル・ドロップ）は足した順のままで、帯も出さない。

一覧に行が残っているときは、前回の実行を終えていれば（成功し、その後に一覧を変えていなければ）一覧を置き換え、そうでなければ後ろに足す。100 ファイルを超えた分は入れず、上限の帯を束につき 1 回出す。分割に 2 本以上届いたときは、帯「1つ目のファイルだけを対象にしました。」を束につき 1 回出す。`open` でタブが 20 枚あるときは新しいファイルを開かず、帯「タブが多すぎます。20 個まで開けます。使わないタブを閉じてください。」を束につき 1 回出す。

処理の途中・確認の途中・保存ダイアログを開いている間に届いた束は、**手が空くまで預かってから**当てる。その間に一覧が変わると、ダイアログから戻った結合・変換の出力に混ざるためである。

2026-09-28 までこの章は、要求を `{ intent, paths }`、帯を「並び順はエクスプローラーの表示順と異なることがあります。ドラッグで入れ替えてください。」、帯を出す画面を結合だけとしていた。`open` で閲覧モードへ移ることも書いていなかった（`docs/spec-5-1-context-menu.md` 論点2・確定事項9）。

## 6. 進捗と中止

重い処理の間もウィンドウを固まらせないことが非機能要件にある。進捗の見せ方を統一する。

- 1秒を超えそうな処理は、ページビューの上に帯状の進捗を出す。モーダルで画面全体を塞がない。
- 進捗には「何をしているか」「何件中何件か」「中止」を出す。
  例: `結合しています  3 / 5 ファイル  [ 中止 ]`
- 中止はワーカープロセスの終了で行う。中止した場合、出力ファイルは作らない。書きかけがあれば削除する。
- 帯の色は 2 つ。失敗の知らせは赤（`--danger`）、進捗と成功の知らせは青（`--accent`。`data-tone="info"`）で出す（決定48）。中止と注意の知らせの色は決めていない（今は赤）。

## 7. 戻せない操作の扱い

`.claude/CLAUDE.md` 付則C を画面に落とす。

| 操作 | 扱い |
|---|---|
| ページ削除 | 確認を出さない。`ops` に積むだけで、Ctrl+Z で戻せるため |
| 注釈のフラット化 | **確認を出す。**「注釈 N 件をページの内容として焼き込み、「<出力名>」に書き出します。書き出したファイルでは、これらの注釈を選んだり直したりできません。元のファイルは変わりません。」（ノートがあれば「ノート N 件の本文と作成者は、書き出したファイルに残りません。」）。「焼き込む」を `--danger`、既定のフォーカスはキャンセル（2026-09-24 改め。フラット化は元のファイルを残して別のファイルへ書くツールになったため。`spec-4-5` 確定事項10） |
| 上書き保存 | 確認を出さない。ただし保存前に、元ファイルと同名の `.bak` を残すかどうかを設定で選べるようにする |
| 出力先に同名ファイルがある | **確認を出す。**「上書き」「別名で保存」「中止」の3択 |
| タブを閉じる／アプリを終了（未保存あり） | **確認を出す。**「保存」「保存しない」「キャンセル」の3択 |

確認のダイアログは、破棄・上書きにあたるボタンを `--danger` で塗る。既定のフォーカスは安全側（キャンセル）に置く。
