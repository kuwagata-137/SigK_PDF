# ページの削除・右クリックメニュー・コピーと貼り付け（第2版 7-5）の仕様と記録

作成: 2026-11-12。作業ブランチ `claude/image-edit-menu`（7-3・7-4 と同じブランチ。版は 1.2.0 のまま）。
決定の元: `docs/07_開発計画の決定事項.md` 決定92。質問 PG1 の図: `screenshots/question-pg1-paste-position.png`。質問 PG2 の図: `screenshots/question-pg2-page-edit-mode.png`。

## 目的

ユーザーの依頼（2026-11-12。1 通目）による。

> ツール画面の改修です
> * 帯の中でページを選択中（複数可）の時にdeleteキーを押したらそのページを削除するようにしてください（警告も出す）
> * 選択したページ（複数も可）のところにカーソルを当てた状態で右クリックすると、シェルコンテキストメニューが表示されてコピー、切り取り、削除が選択できるようにしてください

同じ日の 2 通目による。

> * 編集の画面でサムネイルのところでctrl+選択やshift+選択で複数のページを選択できるようにしてください
> * 編集の画面のサムネイルをドラッグアンドドロップすることでページの入替ができるようにしてください
> * 編集の画面のサムネイルでdeleteキーを押したらページの削除をしてください（警告あり）
> * 編集の画面のサムネイルで選択したページ（複数も可）のところにカーソルを当てた状態で右クリックすると、シェルコンテキストメニューが表示されてコピー、切り取り、削除が選択できるようにしてください

ユーザーの言う「シェルコンテキストメニュー」は、アプリの中で右クリックしたときに表示するメニュー（この文書では「右クリックメニュー」）と読んだ。
Windows のエクスプローラーのメニューではない。「編集の画面」は編集モード、「ツール画面」はツールモードの帯の画面。

## 対象の画面

| 画面 | ページの一覧 | 今の動き（2026-11-12） |
|---|---|---|

| 編集モード | 左パネルのサムネイル | クリックでそのページへ移るだけ。Ctrl・Shift・ドラッグ・右クリックは何もしない。Delete・Backspace は選択した書き込みを削除する |
| ページ編集モード | 左パネルのサムネイル | 選択・ドラッグでの並べ替え・Delete と［削除］での削除（確認画面なし。spec-1-5 確定事項40）はある。右クリック・Ctrl+C/X/V は何もしない |

## 実装記録（2026-11-12）

### 追加したファイル

### 実装で決めたこと（Claude の案）

仕様書に書いていなかった所を、実装のときに次のとおり決めた。

1. 削除確認画面には［×］ボタンを付けない（ほかの確認画面に合わせた）。
2. 右クリックメニューの項目にはアイコンを付けない。［削除］の文字は危険色にした。
3. 通知バーに表示する文を 3 件追加した:「N ページをコピーしました。」「N ページを切り取りました。」「切り取りを中止しました。」。
4. ツールモードで分割を選んでいる間は、どの帯でも右クリックメニューと Delete・Ctrl+C/X/V を使わない（T2 を分割画面の外の帯にも広げた）。
5. 「変換する画像」の帯に枠があるときに PDF の帯を右クリックすると、枠を PDF の帯へ移してからメニューを表示する（T1）。
6. 編集モードのサムネイルには、カーソルを合わせると表示するボタン（［このページを削除］など）を付けない。
7. 編集モードの Esc では、サムネイルのページの選択を解除しない（Esc は今までどおり書き込みの選択・書き込みツールの選択を解除する）。
8. 帯をクリックすると、フォーカスを帯の画面（`#strips`）へ移す（K1 の「帯をクリックした後」を作るため）。
9. パスワード付きのタブでも、ページ編集モードの［削除］ボタンとサムネイルの［このページを削除］は、今までどおり押せる（削除確認画面を表示する）。Delete キーは R1 のとおり何もしない。
