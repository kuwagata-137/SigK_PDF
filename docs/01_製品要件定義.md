# SigK PDF 製品要件定義

作成日: 2026-08-29
前提資料: `docs/00_調査要件レポート.md`

---

## 1. 製品の位置づけ

SigK PDF は、単機能ツールを並べた無償PDFユーティリティと、統合型の商用PDF編集ソフトの中間を狙う Windows デスクトップアプリケーションである。

両者の違いは機能数ではなく、**作業がひとつの画面で完結するかどうか**にある。無償ユーティリティは「結合する」「分割する」といった操作ごとに独立した画面を持ち、開いて処理して閉じる、という単発の使い方を前提にしている。商用統合ソフトは1枚のドキュメントを開いたまま、閲覧・ページ操作・注釈・書き出しを行き来できる。

SigK PDF は後者の操作感を採りつつ、機能の範囲は前者に近い水準に絞る。すなわち次のとおりである。

| | 無償ユーティリティ型 | **SigK PDF** | 商用統合型 |
|---|---|---|---|
| 操作の単位 | ツールごとの単発処理 | **開いたまま連続作業** | 開いたまま連続作業 |
| 閲覧機能 | 簡易またはなし | **常設のビューア** | 高機能ビューア |
| ページ操作 | あり | **あり（サムネイル直接操作）** | あり |
| 注釈・透かし | 限定的 | **あり** | あり |
| 既存テキストの直接編集 | なし | **持たない** | あり |
| 高精度なOffice形式変換 | 限定的 | **持たない** | あり |
| 電子証明書による署名 | なし | **持たない（将来検討）** | あり |
| 動作 | ローカル完結またはクラウド | **ローカル完結** | ローカル完結 |

「持たない」と決めた3機能は、調査要件レポート第4章で「難しい」に分類されたものと一致する。ページ内の既存テキストの書き換えはPDFの構造上そもそも困難であり、レイアウトを保った Office 形式への変換も専用エンジンなしには実用水準に届かない。ここに手を出すと開発規模が跳ね上がるため、第1版のスコープから明確に外す。

## 2. 対象環境

| 項目 | 内容 |
|---|---|
| 対象OS | Windows 10 (21H2以降) / Windows 11 |
| アーキテクチャ | x64（arm64 は将来検討） |
| 配布形態 | NSIS 形式のセットアップインストーラー |
| インストール権限 | ユーザー単位インストール（管理者権限を必須としない） |
| ネットワーク | 不要。すべての処理をローカルで完結させる |
| 想定ファイルサイズ | 1ファイル 200MB / 1,000ページ程度までを実用範囲とする |

macOS への対応は第1版のスコープ外とする。ただしアーキテクチャ設計では、OS依存処理を `platform-win.js` に隔離し、将来の移植時に改修範囲が限定されるようにする（`docs/02_アーキテクチャ設計.md` 参照）。

技術構成は既存プロジェクト CheckListMaker（同一作者・同一配布形態）を踏襲する。Electron ＋ 素の HTML/CSS/JavaScript とし、ビルドステップを置かない。理由と詳細は `docs/02_アーキテクチャ設計.md` 第1章に記す。

## 3. 機能要件

### 3-1. 第1版に含める機能

#### F-01 閲覧

| ID | 機能 | 内容 |
|---|---|---|
| F-01-1 | ページ表示 | 連続スクロール表示。単ページ／見開き表示の切り替え |
| F-01-2 | ズーム | 25%〜400%。幅に合わせる／全体を表示のプリセット |
| F-01-3 | ページ移動 | ページ番号入力、前後移動、先頭／末尾へ移動 |
| F-01-4 | サムネイル一覧 | 左ペインに全ページのサムネイルを表示。クリックで該当ページへ移動 |
| F-01-5 | テキスト検索 | 文書内の文字列検索。ヒット箇所のハイライトと前後移動 |
| F-01-6 | テキスト選択・コピー | 表示中ページからのテキスト選択とクリップボードへのコピー |
| F-01-7 | 文書情報の表示 | ページ数、ファイルサイズ、作成日時、PDFバージョン、暗号化の有無 |
| F-01-8 | 印刷 | OSの印刷ダイアログ経由での印刷 |

| F-02-3 | 削除 | 選択ページの削除 |
| F-02-4 | 抽出 | 選択ページを別のPDFとして書き出し |
| F-02-5 | 挿入 | 別のPDFまたは画像を指定位置に挿入 |
| F-02-6 | 複数選択 | Ctrl／Shift クリックおよび矩形選択による複数ページ選択 |
| F-02-7 | 元に戻す／やり直し | ページ操作に対する undo / redo |

#### F-03 結合・分割

| ID | 機能 | 内容 |
|---|---|---|
| F-03-1 | 結合 | 複数のPDFを1つに結合。並び順をリスト上で入れ替え可能 |
| F-03-2 | 結合時のページ範囲指定 | 各入力ファイルについて取り込むページ範囲を指定 |
| F-03-3 | ページ数指定の分割 | N ページごとに分割 |
| F-03-4 | 位置指定の分割 | 指定したページの前で分割 |

#### F-04 変換

| ID | 機能 | 内容 |
|---|---|---|
| F-04-1 | 画像からPDF | JPEG / PNG / BMP / GIF / TIFF（単一ページ）を取り込んでPDF化 |
| F-04-2 | 画像配置の指定 | 用紙サイズ（A4 / A3 / B5 / レター / 画像サイズに合わせる）、向き、余白 |
| F-04-3 | 複数画像の一括変換 | 1つのPDFにまとめる／画像ごとに別PDFにする、の選択 |
| F-04-4 | PDFから画像 | 指定ページを PNG / JPEG として書き出し。解像度（72 / 150 / 300 dpi）指定 |

#### F-05 注釈・テキスト・透かし

| ID | 機能 | 内容 |
|---|---|---|
| F-05-1 | ハイライト | テキスト選択範囲への蛍光ペン。色の選択 |
| F-05-2 | 下線・取り消し線 | テキスト選択範囲への線種の付与 |
| F-05-3 | フリーテキスト | 任意位置へのテキストボックス配置。フォントサイズ・色の指定 |
| F-05-4 | 図形 | 矩形・楕円・直線・矢印の描画 |
| F-05-5 | フリーハンド描画 | ペンによる手描き。線幅・色の指定 |
| F-05-6 | ノート注釈 | ピンを立ててコメントを紐づける |
| F-05-7 | 注釈一覧 | 右ペインに文書内の注釈を一覧表示。クリックで該当箇所へ移動 |
| F-05-8 | 透かし | 全ページまたは指定ページへのテキスト透かし。文字列・角度・不透明度・色・配置を指定 |
| F-05-9 | 画像の透かし | 画像ファイルを透かしとして配置 |
| F-05-10 | 注釈の確定 | 注釈を描画内容としてページに焼き込む（フラット化） |

注釈は第一に PDF の標準注釈オブジェクトとして保存する。フラット化は明示的に指示されたときのみ行う破壊的操作とし、実行前に確認を求める。

#### F-06 ファイル操作

| ID | 機能 | 内容 |
|---|---|---|
| F-06-1 | 開く | ファイル選択ダイアログ、ドラッグ＆ドロップ、コマンドライン引数の3経路 |
| F-06-2 | 保存 | 上書き保存および名前を付けて保存 |
| F-06-3 | 最近使ったファイル | 直近10件の履歴 |
| F-06-4 | 複数文書 | タブによる複数ファイルの同時オープン |
| F-06-5 | 未保存変更の警告 | 閉じる操作時に未保存の変更があれば確認する |
| F-06-6 | パスワード付きPDFの読み込み | 開くときにパスワードを入力して閲覧・編集する |

F-06-6 は「読み込み」のみを対象とする。暗号化してのパスワード保護（書き出し側）は第2版以降で扱う（3-2 参照）。

#### F-07 Windows シェル統合

| ID | 機能 | 内容 |
|---|---|---|
| F-07-1 | 「SigK PDF で開く」 | PDF を右クリックしてアプリで開く |
| F-07-2 | 「選択したPDFを結合」 | 複数のPDFを選択して右クリックし、結合画面へ直行する |
| F-07-3 | 「PDFを分割」 | PDF を右クリックして分割画面へ直行する |
| F-07-4 | 「画像をPDFに変換」 | 画像ファイルを右クリックして変換画面へ直行する |

### 3-2. 第2版以降で検討する機能

第1版のスコープからは外すが、設計上の余地は残しておく機能である。

| 機能 | 外す理由と将来の実現手段 |
|---|---|
| 圧縮（ファイルサイズ削減） | 実用水準の圧縮には Ghostscript の同梱が要る。ライセンス（AGPL）の確認が別途必要 |
| OCR | Tesseract エンジンと日本語学習データの同梱が要る。配布サイズが大きく増える |
| パスワード保護（暗号化） | pdf-lib は暗号化した書き出しに対応していない。別ライブラリまたは外部ツールの選定が要る |
| 墨消し | 見た目を塗るだけでは情報が残るため、テキストオブジェクト自体の削除が要る。実装の確実性を担保する検証工数が大きい |
| フォーム入力 | AcroForm の読み書き。pdf-lib で対応可能だが、第1版の作業量を優先して見送る |
| 電子署名 | 証明書の扱いと長期署名の要件整理が別途必要 |
| Office 形式への変換 | LibreOffice CLI 等の外部エンジン前提。レイアウト再現の品質保証が困難 |

## 4. 非機能要件

| 項目 | 目標 |
|---|---|
| 起動時間 | アプリ単体の起動からウィンドウ表示まで 3 秒以内。**インストール（または作り直し）直後の初回起動は対象外**（2026-09-03 ユーザー判断。4-1 参照） |
| ファイル表示 | 10MB / 50ページ程度のPDFで、開いてから最初のページが描画されるまで 2 秒以内 |
| UIの応答 | 重い処理の実行中もウィンドウが固まらないこと。進捗と中止手段を示すこと |
| メモリ | 上記想定ファイルの編集時に 1.5GB を超えないこと |
| 外部通信 | 行わない。アップデート確認を実装する場合も既定を「無効」とし、明示的な同意を得る |
| 一時ファイル | 処理中の中間ファイルは終了時に削除する。ユーザーの文書を意図せず残さない |
| インストーラー | 管理者権限なしでインストールできること |

### 4-1. 実測（2026-09-02・Phase 1 末）

`docs/05_開発ロードマップ.md` の定めに従い、Phase 1 の終わりに測った。対象は**配布物**
（`dist/win-unpacked/SigK PDF.exe`）で、検体は `npm run fixtures:perf` が作る
`test/fixtures/perf-10mb-50p.pdf`（50ページ・9.93MB・1ページにつき取り込み画像1枚）。
測り口は `main.js` の `SIGK_SMOKE_PERF`。編集は「2ページ選ぶ→回す→移動→削除→元に戻す」。

| 項目 | 目標 | 実測 | 判定 |
|---|---|---|---|
| 起動時間（2回目以降・4回） | 3秒以内 | 0.55〜0.67秒 | ✅ |
| 起動時間（作り直した直後の初回・2回） | ~~3秒以内~~ 対象外 | 5.5秒・6.6秒 | —（2026-09-03 に目標の対象外とした） |
| ファイル表示（4回） | 2秒以内 | 0.15〜0.16秒 | ✅ |
| メモリ・編集時（4回） | 1.5GB 以下 | 0.76〜0.79GB | ✅ |
| メモリ・保存中の山 | 1.5GB 以下 | 1.16GB | ✅ |

表示の内訳は、ファイルを読む 20〜28ms・pdf.js が開く 57〜63ms・1ページ目を描く 68〜75ms。
目標に対して**十数倍の余裕**がある。メモリの内訳は GPU が約400MB でいちばん大きく、
次がレンダラー約200MB、メイン約128MB である。

**初回だけ遅いのは、こちらの起動処理ではない。**冷えた初回は、プロセスが作られてから
`main.js` を読み終わるまでに 5,046ms かかり、全体 5,515ms の 91% を占める。そこから窓が
出るまでは 469ms で、2回目以降の 450ms とほとんど変わらない。つまり**自前の起動処理は
温度に関わらず約0.45秒**で、差はすべて Electron 本体（約200MB）をディスクから読む時間と、
書かれたばかりの実行ファイルに対するウイルス対策の走査である。作り直した2つのビルドで
同じ形が再現した。

**したがって「3秒以内」を初回にも課すと、打てる手が無い。**自前の処理を 0 にしても
5秒は縮まらない。~~インストール直後の初回を別扱いにするかどうかは、常用を始めてから
決める（`docs/07_開発計画の決定事項.md` 手順28）。~~ **2026-09-03 ユーザー判断: 初回起動は
目標の対象外とする**（`docs/07` 決定23）。目標は2回目以降の起動に対して課す。初回の遅さは
インストール直後の既知の挙動として、Phase 5 の使い方ガイドに一言書く。

**保存中の 1.16GB が、これまで宙に浮いていた合算である。**pdf.js（レンダラー）が文書を
抱えたまま pdf-lib（ワーカー）が同じファイルを組み直すため、この瞬間だけ両方が乗る。
`docs/spec-1-5-page-edit.md` と `docs/spec-1-6-save.md` が「未取得」としていた値がこれで、
1.5GB に対して 77% を使う。**いちばん厳しいのは保存中である。**

上の表に無い項目は、ここでは測り直していない。UIの応答はワーカーと進捗・中止
（`docs/spec-1-6-save.md`）、外部通信は `security-policy.js` とそのテスト、一時ファイルの
後始末は `pdf-write.js` とそのテスト、インストーラーの権限は `perMachine=false` で、
それぞれ別に担保している。

## 5. 制約と守るべき方針

調査要件レポート第7章の結論を、開発上の禁止事項として具体化する。運用上のチェック項目は `docs/06_ライセンス・商標チェックリスト.md` に一覧化する。

- 製品名・画面表示・ドキュメント・訴求文言に「Adobe」「Acrobat」「PostScript」および他社製品名を用いない。互換性を示す表現も使わない。
- 既存商用PDF製品の配色・アイコン・ツールバー配置を模倣しない。UI は左ツールレール型を採り、配色は独自に定める（`docs/04_UI設計.md`）。
- PDF の読み書きは ISO 32000-1 の範囲で行う。仕様書に記載のない独自拡張の模倣は行わない。
- 同梱・依存する OSS のライセンスを `THIRD-PARTY-NOTICES` に集約し、リリース物に含める。

## 6. 用語

| 用語 | 定義 |
|---|---|
| 文書 | アプリで開いている1つのPDFファイル。タブ1つに対応する |
| ページ操作 | ページ単位の並べ替え・回転・削除・抽出・挿入の総称 |
| 注釈 | PDF の Annotation オブジェクトとして保存される追記情報 |
| フラット化 | 注釈をページの描画内容に焼き込み、注釈オブジェクトを取り除く操作 |
| シェル統合 | Windows エクスプローラーの右クリックメニューへの項目追加 |
