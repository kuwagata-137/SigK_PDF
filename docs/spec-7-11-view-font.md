## 目的

ユーザーの依頼（2026-11-26。番号は統括役の計画の番号）による。

> * フルスクリーンモードを追加したい（①）
> * 画像変換やPDF変換する時に「範囲」で指定する時に、選択されているページの番号が勝手に入るようにする（②）
> * 入力できるテキストのフォントを変更できるようにする。追加するフォントについては、たくさん入れてもアプリが重くならないか等で要相談。（③）
> * 選択モードで範囲選択した時に画面表示倍率が勝手に変わらないようにしてください（⑪）

## 確定事項

### 質問 ZM3（2026-11-27）

ユーザーの回答（統括役を通して。原文のまま）:「案A 重ね表示（推奨）」

- Z1. プロパティパネルを開閉しても、表示倍率とページの位置を変えない。範囲選択を始めた時（選択を解除してプロパティパネルが閉じる）も、離して書き込みを選択した時（開く）も、［幅］［全体］の倍率と、ページの左右の位置はそのまま。
- Z2. 作り方（Claude が決めたこと）: プロパティパネルを本当に重ねる（`position` を変える）のではなく、ページを並べる幅を「表示域の幅＋開いているプロパティパネルの幅」にした（`renderer/viewer.js` の `layoutWidth`）。［幅］［全体］の倍率と、ページの左右の位置（`#view-pages` の左の余白）を、この幅で計算する。開いている間は、ページの右側がプロパティパネルの所で隠れ、横にスクロールすると表示される。縦のスクロールバーはプロパティパネルの左に残る。見た目は、図の案A（重ねて表示）と同じ。本当に重ねる方法を採らなかったのは、プロパティパネルの位置と大きさを決める CSS と、表示域の幅を使うほかの処理（帯・分割の盤・書き込みの枠）を変えずに済むため。
- Z3. `docs/spec-7-9-shape-marking.md` の確定事項E2（プロパティパネルの開閉で、表示域が変わるので倍率を計算し直す）を改めた。開閉の時は倍率を計算し直さず、`viewer.recenter` で左右の位置と描く範囲だけを合わせる。

### 質問 FS1（2026-11-27）

ユーザーの回答（統括役を通して。原文のまま）:「案Aとし、「見開き」ボタンの右側にボタンを作る。表示を戻すときは「Esc」キー。カーソルは表示されるようにし、左クリック+右クリックでモード切替も可能。クリックホイール操作は、矢印の時は通常通りのページ送り、ハンドツールモードの時はズーム。」

統括役の扱い: 質問 FS2 は出さず、ツールバーの［見開き］の右に［フルスクリーン］ボタンを追加することが決まったものとして扱う。「左クリック+右クリックでモード切替」は［選択］（矢印）と［ハンド］の切り替え、ホイールは「［選択］の時はページ送り、［ハンド］の時は拡大・縮小」。F11 キーで入る・F11 キーでも戻る・Esc キーは今の働きを先に行う、は子B の案のまま。

- F1. 隠すもの: ツールバー・編集ツールバー・モード切り替えバー・左パネル（閉じたパネルの細い欄を含む）・タブバー・ステータスバー・プロパティパネル。ウインドウもフルスクリーンにする（タイトルバー・メニューバー・タスクバーが消える）。通知バーと検索バーは表示域の上に重ねて表示するので、そのまま使える。
- F2. 入る操作: ツールバーの［フルスクリーン］ボタン（［見開き］の右）と F11 キー。閲覧・ページ編集・編集モードで、文書を開いている時だけ入れる。ツールモードではボタンを押せず、F11 キーも効かない。フルスクリーンモードのままツールモードに切り替えたら終了する（［見開き］と同じく、ページの表示だけに効くボタンのため。`docs/07` 決定83）。
- F3. 戻る操作: Esc キーと F11 キー。Esc キーは、今の働き（書き込みの選択の解除・書き込みツールの選択の解除・［ハンド］を［選択］に戻す・検索バーを閉じるなど）を先に行い、何も無い時にフルスクリーンモードを終了する（`renderer/escape-order.js` のいちばん最後の段）。Windows の操作などでウインドウのフルスクリーンが解除された時も、フルスクリーンモードを終了する。
- F4. 入った時に、画面の上に「Esc キーか F11 キーを押すと、フルスクリーンモードを終了します」を 3 秒表示する（Claude の案。質問 FS1 の図の②）。
- F5. マウスカーソルは隠さない。左ボタンを押したまま右クリックすると［選択］と［ハンド］を切り替え、ホイールは［選択］の時はページ送り、［ハンド］の時は拡大・縮小する。どちらも今の仕組み（`renderer/pointer-mode.js` の `chord`、`renderer/viewer-wheel.js` の `wantsZoom`）のままで、回答と同じ動きなので、フルスクリーンモードのための変更はしていない。何を切り替えるかが 1 つに決まったので、質問 FS3 は作らなかった。
- F6. ボタンの文字（統括役の依頼で、実測して Claude が決めたこと）: 幅 1500px 以上のウインドウでは「フルスクリーン」の文字付き、1500px 未満ではアイコンだけにする（名前はツールチップと aria-label に残る）。実測（ウインドウを表示しない起動。閲覧・編集・ツールモードで同じ）は次のとおり。

- F7. フルスクリーンモードの状態は覚えない（次の起動はふつうの画面。Claude の案）。フルスクリーンのままウインドウを閉じた時は、入る前に最大化していたかを、ウインドウの状態として保存する。

### 質問 RG1・RG2・RG3（2026-11-27）

ユーザーの回答（統括役を通して。選んだ選択肢名のまま）: RG1「案A 選択時入力（推奨）」、RG2「案C 入力なし（推奨）」、RG3「案A 4 ツール対象（推奨）」

- R1. ツールモードで、帯のページをクリック（Ctrl・Shift を含む）か Ctrl+A で選択するたびに、選択したページの番号を範囲欄に入力し、［範囲］を選択する。手で入力した番号も置き換える。選択を解除した時（Esc・並びが変わった時）は、範囲欄をそのままにする。
- R2. 番号は「2-4, 7」の形（連続は「-」、ほかは「, 」区切り。`renderer/page-range.js` の `formatPageRange`）。
- R3. 対象は、PDF→画像・透かし・フラット化（選択中の帯が対象）と、結合（ページを選択した帯の行の範囲欄）。分割・画像→PDF には範囲欄が無いので何もしない。結合の行のチェックは変えない（Claude が決めたこと）。

### 質問 FT1（2026-11-27）と、仮に実装した FT2・FT3

ユーザーの回答（統括役を通して。選んだ選択肢名のまま）: FT1「案B Windows フォント使用（推奨）」

- T1. 一覧に並べるフォントは、Noto Sans JP（同梱）と、Windows に入っている游ゴシック・游明朝・メイリオ・MS ゴシック・MS 明朝（一覧の順）。このパソコンに入っていて、埋め込みの決まり（OpenType の fsType）が「編集できる文書にサブセットで埋め込んでよい」フォントだけを並べる（メインの `font-catalog.js`。初めて聞かれた時に 1 回だけ調べる）。
- T2. プロパティパネルの「文字の色」の下に「フォント」の行（一覧）を追加する。テキスト・吹き出しの書き込みツールと、選択中のテキストで表示する。選んだフォントは、選択中のテキストに当て、次に置くテキスト・吹き出しの値として設定に保存する（太字・文字の色と同じ。Claude の案。質問 FT2 の図の経緯の表に書いた）。
- T3. 保存は、書体（フォント×標準・太字）ごとにサブセットで埋め込む。.ttc は PostScript 名でフォントを選ぶ。/DA のフォント名（自分で付けたテキストの印）は、Noto Sans JP が今までどおり SigKJP、ほかは SigKYG・SigKYM・SigKMR・SigKMG・SigKMM。/DS のフォント名は Noto Sans JP・Yu Gothic・Yu Mincho・Meiryo・MS Gothic・MS Mincho。
- T4. ほかのパソコンで付けたテキストのフォントが、このパソコンに無い時は、Noto Sans JP で描き、修正すると Noto Sans JP で保存する（質問 FT1 の案B の説明）。修正しなければ、保存してある外観のまま。
- T5.（質問 FT2 の推奨案A で仮に実装。回答待ち）初めて使う時のフォントは Noto Sans JP。既定の Noto Sans JP は、書き込みにも設定にも font の欄を持たない（今までの形を変えない）。
- T6.（質問 FT3 の推奨案A で仮に実装。回答待ち）太字の書体が無い MS ゴシック・MS 明朝では［B］を押せない。選ぶと太字を外し、次に付ける値も太字なしにする。保存の側も、太字の書体が無いフォントの太字は標準の書体で描く。
- T7. 使い方画面のテキストの節に、フォントの説明を追加した。

## 調べた結果（Web。2026-11-26）

- Microsoft の Font redistribution FAQ（https://learn.microsoft.com/en-us/typography/fonts/font-faq ）: Windows のフォントの再配布（アプリへの同梱）は認めない。埋め込みの決まり（OpenType の fsType）に従うアプリが作る文書（PDF を含む）への埋め込みは認める。`docs/spec-4-2-free-text.md` の事前調査 A（65 行）の「OS のフォント … 再配布・埋め込みの許諾が無い」のうち、埋め込みの部分はこの FAQ と食い違う（FT1 の回答の後に、spec-4-2 に注記する）。
- fsType の値は Microsoft の公式のページに無く、個人が公開した一覧（2020 年）にだけあった: 游ゴシック・游明朝・メイリオ・MS ゴシック・MS 明朝は Editable、Windows の BIZ UD と UD デジタル 教科書体は Preview & Print。
- BIZ UD の Google Fonts 版は SIL OFL 1.1（Windows の版より 4 文字多い版）。
- pdf-lib は `fontkit.create` を PostScript 名なしで呼ぶので、.ttc のフォントはそのままでは埋め込めない見込み（`worker/font-embed.js` の `paddedFontkit` で PostScript 名を渡す形にする案）。
