## 目的

編集モードで、**四角・丸を選ぶと 8 点のつまみと上の丸い回転のつまみが出て、大きさと向きを変えられる。直線・矢印は両端のつまみで
端の位置を変えられる。右パネルの「回転」の行（スライダー・数値・0°/90°/180°/270° のボタン）でも向きを変えられる。どの変形も、
動かしている間は下見で、離すと 1 世代だけ積まれる。保存すると PDF の決まりの欄（外観の `/Matrix`・`/BBox` と外接の `/Rect`）に書かれ、
開き直しても同じ箱・角度・見た目のまま直せる**（F-05-12）。

ほかのアプリで回した四角・丸も、回転が読み取れれば回ったまま直せるようにする。今は開いただけで、回っていない大きな四角に描き
直されてしまう（事前調査 B。今の main にもある潜在的な不具合）。

## 事前調査（2026-10-01・Windows 11 実機・Node 24・Electron 44・pdf.js 6.3.289・pdf-lib 1.17.1・scratchpad の検体のみ）

検体とプローブは scratchpad の `probe/`（静的サーバー＋Browser パネル。倍率 2）。保存は今のワーカーの外観の組み方（`worker/shape-appearance.js`）を
そのまま使い、包み方だけを候補ごとに替えた。

### A. 回した四角・丸の持たせ方 — 外観を `/Matrix` で回し、角度と箱は PDF の決まりの欄から逆算する

| 候補 | 外観 | 角度と回す前の箱 | ほかのアプリが外観を作り直したとき |
|---|---|---|---|
| (a) | 外側の Form に `/Matrix`（箱の中心まわりの回転）、`/BBox`＝回す前の箱、`/Rect`＝回した外接 | 注釈の辞書に独自の欄 | 独自の欄だけが残り、SigK PDF だけが回して描いて食い違う |
| **(b)** | (a) と同じ | **外観の `/BBox`・`/Matrix` と `/Rect` から逆算** | SigK PDF も作り直された外観に従う（回転は消えるが食い違わない） |
| (c) | `/BBox`＝`/Rect`＝外接、外観の中身の先頭で `cm` | 独自の欄（中身は暗号化されると読めない） | (a) と同じ |
| (d) | (a) と同じ | 外観の Form の辞書に独自の欄 | (b) と同じ |

(a)・(b)・(d) は外観が同じなので、絵の比べは (b) と (c) で行った。

- **検体**: 11 通りの見た目（四角: 実線 3pt・破線 3pt・雲形 2pt・塗りと線・線なしの塗り・半透明 50%（塗りと 6pt の線）・40pt、丸: 実線・
  破線・雲形・半透明）× 30°・45°・90°・180°・270°・359° と、ページの `/Rotate` 90・180・270 に 4 通り × 6 角度。計 138 件、箱は 140×80pt。
- **画面の描き方の案**: 回す前の書き込みを今の `shape-graphics.svgOf` で描き、`<g transform="rotate(θ cx cy)">`（表示の座標で、箱の中心まわり）で
  包む。**印刷の案**: canvas を箱の中心まわりに回してから今の `paint` で描く。

| 書き込み | pdf.js と画面の差（差が 32 を超える画素の、比べた範囲に対する割合） | 印刷と画面 |
|---|---|---|
| 四角（実線・破線・塗り・線なし・40pt） | 90°・180°・270° は差 0。30°・45° は 0.002% 以下、359° は 0.07〜0.19%（ほぼ水平な縁のにじみ） | 差 0 |
| 四角（半透明） | 0.04% 以下 | 32 超 0 |
| 雲形（四角・丸） | 0.01〜0.12%（最大の差 156・57 画素） | 0.05% 以下 |
| 丸（実線） | 0.3〜0.96%（ベジェ 4 本と SVG の楕円の違い。①-b 事前調査 D と同じ性質） | 32 超 0 |
| 丸（破線・半透明） | 0.17% 以下 | 0.03% 以下 |

- 回る向きは、画面で時計回り（30° で右上の角が下がる）を目で確かめた。ページが回っていても、表示の座標での `rotate(θ)` で pdf.js と一致する
  （ページの回転は 90° 刻みで、向きを保つため）。
- **逆算**: `/Matrix`（小数 4 桁）から求めた角度は整数から 0.003° 以内、`/BBox` は回す前の箱と差 0、回転の中心のずれ 0。`/Rect`（小数 2 桁）の
  丸めで pdf.js が外観を伸び縮みさせる量は 0.007% 以下。
- **暗号化**（RC4 40bit の検体を手で組んだ）: `/BBox`・`/Matrix`・`/Rect` の数は pdf-lib（ignoreEncryption）で読めた。外観の中身は暗号のまま
  読めない → (c) は暗号化された文書で角度を読み戻せない。
- **フラット化**: (c) は焼く前と差 0〜22（32 超 0）。(b) は線の外側の縁の 1 画素だけが薄くなる（最大の差 69〜103、1 ページ 6 件で 1,500 画素ほど）。
  焼くと外観の `Do` が `/BBox` で切り抜かれ、`/BBox` の縁に重なる線のにじみが削られるため。pdf.js の生の注釈は `/Rect` でしか切らない。
  形のずれではなく、①-b の注記（縁が画素の途中にかかると外側の 1 行が薄い）と同じ種類で、規格どおりのビューアも `/BBox` で切る。
- **結論**: (b) にする（決定51 ①）。独自の欄は要らない。ほかのアプリの `/Matrix` の回転も同じ読みで直せ、ほかのアプリが外観を作り直せば
  SigK PDF もそれに従う。画面は `<g>` の transform、印刷は canvas の回転で描けるので、破線と雲形の始点・向きも保存とそろう。

### C. 独自の欄の名前の付け方（塊⑤へ引き継ぐ。Web 調査）

塊②では独自の欄を使わない（A）。⑤（×印・マーカーの見分け）で使うときのために記録する。

- ISO 32000-2 付属書 E（Extending PDF）E.2: **第二種の名前**は、登録した 4 文字の接頭辞の後に `_`（またはコロン）を付けた名前。登録先は規格の本文が
  指定する公開の一覧（GitHub `adobe/pdf-names-list`）で、Issue で申し込む。費用は無い。登録者の氏名とメールが公開の CSV に載る。2026-10-01 の
  公開の一覧に `SIGK` は無い（2008 年より前の非公開の登録と重なるかは審査で分かる）。**第三種の名前**は `XX` で始まり、登録は要らないが、
  書き手と読み手の内部の処理に限る名前とされる。
- 「読み手は知らないキーを無視する」と一般に定めた ISO 32000 の条文は見つからなかった（PDF/A〔ISO 19005-4 6.1.1〕と PDF/E-2 に近い文がある）。
- `/PieceInfo`（14.5 節）はページ・Form XObject・文書カタログに置け、注釈の辞書には置けない（Form では `/LastModified` が要る）。
- `/Extensions`（7.12 節）は任意。独自の名前を使うときの宣言の決まりは無い。
- 注釈の `/Rotate` は規格に無い（フォームの欄の `/MK /R` だけ）。pdf.js は 90 の倍数のときだけ読み、四角・丸の描き方には使わない
  （`vendor/pdf.worker.mjs` の `getRotationMatrix` はフォームの欄だけ）。あるオープンソースのライブラリは四角・丸に任意の角度の `/Rotate` と
  `/Matrix`（`/Rect` の中心まわり）と外接の `/Rect` を書き、ある商用アプリは独自の `/Rotation` と `/Matrix` と回す前の `/BBox` と外接の `/Rect` を書く。
  どちらも外観の `/Matrix` を読めば (b) と同じ読みで直せる。
- ⑤での推し（起草者）: 注釈の辞書に第二種の名前（登録する。氏名とメールの公開をユーザーに確かめる）。登録しないなら第三種の `XX…`。

### D. 画面

- 紙の器（`.pdf-page`）は `overflow:hidden` なので、層の SVG（`overflow:visible`）ごと紙の外が切られる。紙の上端の近くの図形では、回転の
  つまみが見えず押せない → 枠とつまみは紙の器の外の層に描く（確定事項9）。
- 図形 100 個（雲形・破線を含む）の層の描き直しは中央値 3.0〜3.4ms で、回転の transform を足しても 3.2ms（重さは変わらない）。
- 自作のカーソル（インライン SVG の data URI）は今の CSP（`img-src 'self' data: blob:`）で許される。見え方は目視で確かめる。

## 確定事項

### A. 書き込みの持ち方（`renderer/annotation-entry.js`・`annotation-entry-rules.js`）

1. 四角・丸は `angle`（新）を持てる。画面で時計回りの角度（度）で、0 以上 360 未満の数。0 は持たない（無いものを 0 とする）。つまみと
   回転の行から入るのは整数。読み込んだものは小数 2 桁まで持つ（ほかのアプリの角度を丸めず、開いた時点の見た目を変えない）。
2. `rect` は回す前の箱 `[x1 y1 x2 y2]`（紙の座標）。回転の中心は箱の中心。`quads` は回した箱の 4 隅を 1 つの四角にする
   （`quadOfRect` と同じ UL・UR・LL・LR の順に、回した点を並べる）。
3. 角度は紙が基準で、ページを回しても数字は変わらない。ページの回転は 90° 刻みなので、画面で見ても時計回りのまま（論点9。起草者の判断）。
4. `validEntry`: `angle` は四角・丸だけが持ち、数で 0 以上 360 未満。`PATCH_FIELDS` に `angle` を足し、`copyEntry`・`sameEntry`（無いものは 0 として
   比べる）・`toSaveEntry`（0 でなければ書く）を広げる。
5. `shape-geometry.rectOfShape({ kind, rect, paths, lineWidth, angle })`: 四角・丸は `rect` のまま、`quads` を回した 4 隅にする。呼び口（下見・移動・
   太さ・下書き）すべてに `angle` を渡す（渡し忘れると回した図形の当たりと枠がずれる）。

### B. 画面と印刷の描き方

6. 回した四角・丸は、回す前の書き込みの部品（今の `shape-figure.js` の部品。実線は rect・ellipse、破線・雲形は点列の path）を描き、
   まとまりの `<g>` に表示の座標で箱の中心まわりの `rotate(角度)` を付ける（事前調査 A）。
7. 印刷（`shape-graphics.paint`）は、canvas を箱の中心まわりに回してから描く。不透明度が 1 未満のときの別の canvas は、回した外接の大きさで作る。
8. 描いている途中の下書きは回さない（新しく描く図形は 0°）。

### C. 選択の枠とつまみ（モック `screenshots/phase4b-2-square.png`・`-circle.png`・`-arrow.png`・`-choices.png`）

9. 枠とつまみは、紙の器の外の `#view-pages` に置く 1 枚の SVG の層（`.annot-frame-layer`。`pointer-events:none`・`overflow:visible`）に描き、
   紙の外の灰色の上にもはみ出す（論点6）。選んでいる書き込みのページの位置（紙の器の left・top）に合わせて置く。すべての種類の選択の枠を
   この層へ移す（今は各ページの層の中）。
10. 四角・丸: 枠は回した箱に 3px の余白を足した破線（今の `.annot-frame` と同じ線）。つまみは 8 つ（4 隅と各辺の中点）で、白い丸・青い縁
    1.5px・半径 5px。回転のつまみは、回す前の箱の上の辺（紙の上）の中点から外へ 26px の所に、半径 8px の白い丸・青い縁・中に回転の矢印。
    細い線（1px）で枠とつなぐ。
11. 直線・矢印: 線に沿った破線（枠と同じ線）と、両端のつまみ（論点5）。
12. ペン・テキスト・ノート・マークアップ: 今の枠（外接に余白 3px の破線）。つまみは出さない。
13. 小さな図形: 回す前の箱の辺が表示で 24px より短い向きは、その向きの辺の中点のつまみを出さない（角のつまみと重なり、本体を掴めなくなる
    ため。起草者の判断）。
14. 表示のみの書き込みには、枠だけを出してつまみを出さない（今と同じく選べるが直せない）。

### D. つまみで変える

15. 当たり: つまみの中心から 7px 以内（表示の px）。押したとき、選んでいる書き込みのつまみを本体より先に見る。重なるときは 回転のつまみ →
    角 → 辺 → 端 の順。紙の外（灰色）で押しても、選んでいる書き込みのページの座標で見る。
16. 四角・丸の大きさ: 掴んだつまみの反対側（角なら対角、辺の中点なら向かいの辺）を紙の上で動かさない。回した図形では、押した点を回す前の
    座標へ戻して箱を決め、新しい箱の中心を回して戻す。辺のつまみはその向きだけを変える。辺は最小 1pt で、反対側を越えて裏返さない
    （越えたら最小で止める）。
17. 角のつまみ＋Shift: 押したときの縦と横の比を保つ（正方形は正方形、正円は正円のまま。決定50 ③）。辺のつまみ＋Shift は何もしない。
18. 直線・矢印の端: 掴んだ端を押した点へ動かす。Shift を押している間は、押したときの位置からの動きのうち、小さい方の向き（横か縦）を 0 にする
    （ちょうど等しいときは横を残す。CheckListMaker と同じ。決定50 ④）。描くときの Shift（45° 刻み）は変えない。2 つの端が 0.5pt より近づく位置へは
    動かさない（直前の位置のまま。矢じりの向きが決まらなくなるため）。
19. 回転のつまみ: 押したときの「中心から押した点への向き」からの変化ぶんだけ回す（画面で時計回りが正）。Shift を押している間は 15° 刻み
    （0°・15°・30°…の角度そのものにそろえる）。角度は整数に丸め、360 の余りにする。
20. 動かしている間は下見（履歴に積まない）で、書き込み・枠・つまみを下見の形で描く。離したときに 1 世代積む。下見の形が元と同じなら積まない。
21. 動かしている間の Esc は取りやめ（元の形に戻す）。Ctrl+Z・Ctrl+Y・Delete が押されたら、先に取りやめてから今までどおりに行う。選んでいる
    書き込みが変わった・文書を閉じた・モードを離れた・倍率が変わったときも取りやめる。
22. 押して離すまでの動きが 3px（`CLICK_SLOP`）以下なら何もしない（選択も変えない）。

### E. 掴んで動かす（論点8）

23. 掴んで動かしている間、枠とつまみも書き込みと一緒に動く。今の CSS の `translate` を、枠の層にも同じ量だけ付ける（描き直しは要らない。
    起草者の判断）。離したら今までどおり 1 世代。回した図形は回転の中心ごと動き、角度は変わらない。

### F. カーソル

24. つまみの上では、その向きに合う大きさ変えのカーソル（`ns-resize`・`ew-resize`・`nesw-resize`・`nwse-resize` から、つまみの向きに書き込みの
    角度とページの回転を足して、いちばん近いもの）。回転のつまみの上では自作の回転のカーソル（インライン SVG の data URI、ホットスポットは

## 起草者の判断で決めたもの

- 角度は紙が基準（論点9）。回転の中心は箱の中心。
- 画面は点列を回さず、`<g>` の transform で回す（事前調査 A で pdf.js と一致を確かめた。破線・雲形の始点と向きが保存とそろう）。
- 端のつまみ＋Shift は、押した位置からの動きの小さい方の向きを 0 にする（線の向きを 90° にそろえるのではない。決定50 ④ の「マウスを大きく
  動かした方の向きだけを残す」の読み）。
- 辺のつまみ＋Shift は何もしない。辺の最小は 1pt（描くときの最小と同じ）、裏返さない。
- 小さな図形では辺の中点のつまみを隠す（表示で 24px 未満の向き）。つまみの当たりは 7px、重なりは 回転 → 角 → 辺 → 端。
- 移動中の枠は、描き直さずに CSS の `translate` を枠の層にも付ける（論点8 の実現のしかた）。
- 読み込んだ小数の角度は丸めずに持つ（整数との差が 0.01 未満なら整数）。
- 回した図形には `/RD` を書かない。注釈の `/Rotate` も書かない。
- 中身の `cm` の見分けは、外観とその 1 段下の Form まで（暗号化された文書ではしない）。
