## 目的

塊① は**1文書しか開けない**（`spec-1-1` 確定事項11）。タブバーは無効の見た目のまま置いてある。
塊② はここを本物にし、**エクスプローラーから放り込める・複数の PDF を並べて見比べられる**
状態を作る。Phase 1 の完了時点から常用を始める（`docs/07` 決定5）ため、どちらも常用に直結する。

## 含めるもの / 含めないもの

| 含める | 含めない |
|---|---|
| ドラッグ＆ドロップで開く | サムネイル・検索・印刷（塊③） |
| タブによる複数文書、タブごとの読み位置の保持 | ページ編集・`ops`・undo/redo（塊④） |
| 最近使ったファイル（10件） | 保存・ワーカー・`.bak`（塊⑤） |
| 文書情報（`<dialog>`） | 未保存の警告（塊⑤。確定事項12） |
| Ctrl+W / Ctrl+Tab / 中クリック | Windows のジャンプリスト（確定事項7） |
| | 見開き表示（`spec-1-1` 確定事項12 のまま保留） |

## 確定事項

| # | 論点 | 決定 |
|---|------|------|
| 1 | タブの持ち方 | 開いた文書は pdf.js の `PDFDocumentProxy` ごと保持し、**非アクティブなタブは canvas だけ捨てる**。切り替えのたびに再解析すると大きな PDF で待たされる。canvas は 寸法×`devicePixelRatio` で最も重いので、そこだけ捨てれば効く |
| 2 | タブごとに覚えるもの | 倍率・追従モード（`fit`）・現在ページ・スクロール位置。戻ったときに続きから読める |
| 3 | タブ数の上限 | **20**。超えたら開かずにメッセージを出す。1ファイル最大 200MB（`spec-1-1` 確定事項14）を無制限に積ませない。黙って重くなるより断る |
| 4 | 同じファイルを再度開いたとき | 新しいタブを作らず、既にあるそのタブへ切り替える。同じ文書が2枚並ぶのは事故にしか見えない |
| 5 | ドロップの受け口 | **ウィンドウ全体**で受ける。落とす場所を狙わせない。ドラッグ中はページビューの上に受け入れの表示を出す。複数ファイルは全部タブで開く（上限まで）。PDF 以外は無視し、1件も PDF が無ければメッセージ |
| 6 | ドロップされたファイルのパス取得 | preload に `webUtils.getPathForFile(file)` を包んだ `pdfAPI.pathForFile(file)` を足し、得たパスを既存の `pdf:read` に通す。**`File.path` は Electron 32 で削除済み**であり、現在は 44 のため他に経路がない。`sandbox: true` の preload でも `webUtils` は使える（Renderer 名前空間。`node_modules/electron/electron.d.ts:19864`）。橋が生きていることを起動確認で毎回見る（後述「実測」） |
| 7 | Windows のジャンプリスト | **入れない**（`app.addRecentDocument` を呼ばない）。ファイル関連付けが無い段階ではクリックしても開けない。Phase 5 のシェル統合と一緒に入れる |
| 8 | 最近使ったファイルの持ち方 | `settings.json` の `recent`（`{ path, name, openedAt }` を先頭から新しい順・最大10件）。パスで重複を排除する。書き込みは開くのに成功したときだけ |
| 9 | 最近使ったファイルの見せ方 | **2か所**。①アプリメニュー「ファイル > 最近使ったファイル」②文書が1つも開いていないときのページビューの一覧。起動直後に手が届く場所と、作業中に手が届く場所の両方が要る |
| 10 | 履歴の掃除 | 開こうとして失敗した項目は、その場で一覧から外す。**起動時に全件の存在確認はしない**。`fs.stat` を10回打つと、ネットワークドライブ上のパスで固まる |
| 11 | 文書情報（F-01-7）の見せ方 | アプリ内のモーダル（`<dialog>`）。ネイティブの messageBox は文字を選択・コピーできず、パスや作成アプリは控えたくなる情報である。呼び出しは メニュー「ファイル > 文書情報」（Ctrl+I）とステータスバーのファイル名クリック |
| 12 | 文書情報に出す項目 | ファイル名／パス／ページ数／ファイルサイズ／PDF バージョン／作成日時／更新日時／タイトル／作成者／作成アプリ／暗号化の有無。**取れない項目は「—」と出し、埋めない**。pdf.js の `getMetadata()` が返す `info` から取る（`PDFFormatVersion`・`CreationDate`・`ModDate`・`Title`・`Author`・`Creator`・`Producer`・`EncryptFilterName` の実在を `vendor/pdf.worker.mjs` で確認済み） |
| 13 | PDF の日付形式 | `D:YYYYMMDDHHmmSS+09'00'` を読み、`2026-08-31 12:00` の形に直す。秒以下と時差は出さない。壊れていれば元の文字列をそのまま出す（黙って消すより、読めない値が見えるほうがよい） |
| 14 | ウィンドウのタイトル | レンダラーが `document.title` を `<ファイル名> — SigK PDF` に書き換える。タブが無ければ `SigK PDF`。Electron が `page-title-updated` で拾うため、IPC を1本増やさずに済む |
| 15 | キー操作 | Ctrl+W でタブを閉じる、Ctrl+Tab で次のタブ、Ctrl+Shift+Tab で前のタブ、Ctrl+I で文書情報。タブの中クリックで閉じる、`＋` で開くダイアログ（`docs/04` 第3章・第8章） |
| 16 | 未保存の警告 | **入れない。**塊② の時点で編集手段が無く、`dirty` になる経路が存在しない。タブの CSS（`.tab .dirty`）は置いたまま、点は出さない。F-06-5 は塊⑤ |
| 17 | 閉じたあとのアクティブタブ | 右隣。右端を閉じたときは左隣。最後の1枚を閉じたら空の表示に戻る |
| 18 | 開く経路の一本化 | ダイアログ・ドロップ・最近使ったファイル・メニューのいずれも、最終的に `SigK.tabs.openPath()` の1本へ集まる（`spec-1-1` 確定事項10 の趣旨を引き継ぐ） |

## 画面の動き

| 操作 | 結果 |
|---|---|
| ツールバー「開く」／Ctrl+O／タブバーの `＋` | ダイアログ。選ぶと新しいタブで開く |
| PDF をウィンドウへドロップ | 受け入れの表示 → 落とすと新しいタブで開く。複数なら複数のタブ |
| タブをクリック | その文書へ切り替わる。倍率・ページ位置は前に見ていたまま |
| タブの `×`／中クリック／Ctrl+W | そのタブを閉じる。アクティブは右隣（右端なら左隣）へ |
| Ctrl+Tab／Ctrl+Shift+Tab | 次／前のタブへ巡回する |
| 文書なしの画面 | 最近使ったファイルの一覧。クリックで開く |
| ステータスバーのファイル名／Ctrl+I | 文書情報のモーダル。Esc で閉じる |
| 21個目を開こうとする | 開かず「タブが多すぎます」と出す |
