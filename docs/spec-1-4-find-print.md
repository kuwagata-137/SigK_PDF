## 目的

塊③-a で**読む**ところまでは揃った。ページを並べ、地図（サムネイル）で位置が分かり、
文字を選んでコピーできる。残っているのは**探す**ことと**紙に出す**ことである。

- **文書内を探せない。**ツールバーに虫眼鏡のボタンはあるが `aria-disabled` のまま止まっている。
  100ページの規程集から1語を探すのに、ページを送って目で追うしかない。
- **印刷できない。**ツールバーにボタンすら無い。`docs/04` 第8章は Ctrl+P を印刷に割り当てているが、
  押しても何も起きない。

塊③-b でこの2つを埋め、**Phase 1「閲覧とページ操作」の閲覧側が完成する。**

## 含めるもの / 含めないもの

| 含める | 含めない |
|---|---|
| 文書内のテキスト検索（部分一致・大文字小文字と全角半角の同一視） | 正規表現・ワイルドカード検索 |
| ヒットのハイライトと前後移動、ヒット数の表示 | 複数タブをまたぐ横断検索 |
| 検索バー（Ctrl+F / F3 / Shift+F3 / Esc） | 検索語の履歴・お気に入り |
| 印刷（ページ範囲・進捗・中止 → OS の印刷ダイアログ） | 両面／部数／用紙サイズの指定（OS のダイアログに任せる） |
| 印刷用アイコンと `chevronUp` の追加 | 注釈だけを印刷する／注釈を除いて印刷する（塊④以降） |
| | スキャン画像への OCR 検索（Phase 4 の F-04） |
| | ページをまたぐ語の一致（下の確定事項6） |

## 事前調査

仕様を決める前に確かめたこと。**推測で書いた設計を実装で覆さないため**である。

| 調べたこと | 分かったこと |
|---|---|
| pdf.js の `PDFFindController` を使えるか | **使えない。**`vendor/` に入れているのは `pdfjs-dist/build/pdf.mjs` だけで、`PDFFindController` は `web/pdf_viewer.mjs` 側にある。`build/pdf.mjs` の export 一覧にも無い |
| ハイライト用の CSS はあるか | **ある。**塊③-a で写した `renderer/text-layer.css` に `.textLayer .highlight`（`.selected`・`.begin`・`.middle`・`.end` 込み）が入っている。新たに写す必要はない |
| 正規化の道具はあるか | `normalizeUnicode` が export されている。ただし中身は**リガチャと特殊空白の NFKC 化だけ**で、全角英数の同一視はしない。全角半角は自前で足す |
| 全ページのテキスト取り出しにいくらかかるか | `test/fixtures/many-pages.pdf`（40ページ・751文字・120アイテム）で **25ms**。文書を開く時間は 54ms。**この fixture は1ページ19文字しかなく、下限の目安にしかならない**（下の「実測に残すもの」） |
| ツールバーに口はあるか | 検索ボタンは既にあるが **`id` が無く** `aria-disabled="true"`。印刷ボタンは**無い** |
| アイコンは揃っているか | `assets/icons.js` にあるのは 18個。`search` はあるが **`print` と `chevronUp` が無い**。`docs/04` 第9章の第1版リストには「印刷」が挙がっている |
| キー割り当ては決まっているか | `docs/04` 第8章で **Ctrl+F / F3 / Shift+F3 / Ctrl+P / Esc** が定義済み。`viewer-controls.js` の `handleKey` はいずれも奪っていない |

## 確定事項

### A. 検索の土台とテキストの取り出し（F-01-5）

| # | 論点 | 決定 |
|---|------|------|
| 1 | 土台 | **自前で組む。**`PDFFindController` は `PDFViewer`・`eventBus`・`linkService` と結合しており、自前のビューアへ載せるにはアダプタが要る。`web/pdf_viewer.mjs` を `vendor/` へ入れるとライセンス点検（`docs/06`）の対象も増える。**やることは pdf.js viewer と同じ考え方を、必要な分だけ書く**ことである（`renderer/find.js`） |
| 2 | テキストをいつ取るか | **検索を始めた時に全ページ分をまとめて取る。**開いた時ではない。開くたびに全ページ読むのは、検索しない大多数の場面で無駄になる |
| 3 | 取ったテキストの持ち方 | 文書ごとに1度だけ取り、**タブの session に持つ**（`spec-1-2` 確定事項2 の経路に相乗り）。canvas と違って軽く、タブを戻すたびに読み直す理由がない |
| 4 | 取り出し中の表示 | 検索バーのヒット数の位置に「検索中…」を出す。**進捗の割合は出さない**（ページ数は分かるが、1ページあたりの時間が読めない） |
| 5 | 取り出しの中止 | 世代トークンで捨てる（`viewer.js` の `state.token` と同じ作法）。入力が変わる・タブが変わる・文書が閉じるで、飛んでいる取り出しは無効になる |
| 6 | ページをまたぐ語 | **扱わない。**ページ末尾の「見積」とページ先頭の「書」を「見積書」として拾わない。pdf.js viewer も既定では扱わず、実装が一段重くなるのに対して得られるものが小さい。**既知の限界として書き残す** |

### B. 一致の判定と正規化

| # | 論点 | 決定 |
|---|------|------|
| 7 | 一致の種類 | **部分一致のみ。**正規表現・ワイルドカード・単語単位の一致は入れない |
| 8 | 正規化の作法 | **1文字ずつ正規化し、「正規化後の添字 → 元の添字」の写像を同時に作る。**正規化で長さが変わる文字があるため、写像なしにヒット位置を元のテキストへ戻せない。pdf.js viewer が `diffs` でやっているのと同じ理屈である |
| 9 | 全角半角 | **同一視する**（2026-09-01 のユーザー決定）。`String.prototype.normalize('NFKC')` を1文字ずつ掛ける。全角英数「Ａ」と半角「A」、全角空白と半角空白が同じになる |
| 10 | 大文字小文字 | **既定では同一視し、検索バーの `Aa` で切り替えられる。**同一視するときは `toLowerCase()` を、正規化と同じ1文字ずつの経路で掛ける |
| 11 | ひらがな・カタカナ | **同一視しない。**「けんさく」で「ケンサク」を拾わない。NFKC の範囲外であり、別の写像表が要る。要望が出てから足す |
| 12 | 半角カナの濁点 | **合成しない。**「ｶ」＋「ﾞ」は1文字ずつ処理するため「ガ」にならない。実文書での出現がまれで、合成を入れると2文字→1文字の写像を扱うことになる。**既知の限界として書き残す** |
| 13 | 空の検索語 | 検索しない。ヒット数は空欄、ハイライトは消す。空白だけの語も同じ扱いにする（正規化後に長さ0なら検索しない） |

### C. ハイライトと移動

| # | 論点 | 決定 |
|---|------|------|
| 14 | ハイライトの描き方 | **テキストレイヤーの `span` を分割し、ヒットの範囲を `<span class="highlight">` で包む。**`TextLayer` の `textDivs`（`span` の配列）と `textContentItemsStr`（各 `span` の文字列）の getter を使い、ページ内オフセットを「何番目の `span` の何文字目」へ変換する |
| 15 | 現在のヒット | `.highlight.selected` を付ける。CSS は写した `text-layer.css` が既に持っている（緑の網かけ）。ほかのヒットは `.highlight`（紫の網かけ） |
| 16 | 複数の `span` にまたがるヒット | `.begin` / `.middle` / `.end` を付ける。角丸の付き方が変わり、1つながりに見える。これも写した CSS が持っている |
| 17 | まだ描いていないページ | ハイライトを持てない（`span` が無い）。**そのページを描いた時点で当てる。**`page-render.js` の `attachTextLayer()` の直後に、いま検索中ならハイライトを当てる |
| 18 | ヒットへの移動 | `viewer.goToPage(page)` でそのページへ飛び、テキストレイヤーが揃ってから該当の `span` を `scrollIntoView({ block: 'center' })` で寄せる。**ページの先頭ではなくヒットの位置へ寄せる**（長いページで「飛んだが見えない」を防ぐ） |
| 19 | 端での折り返し | 最後のヒットで「次へ」を押したら先頭へ、先頭で「前へ」を押したら末尾へ回る。**回ったことは知らせない**（第1版。煩わしければ後で足す） |
| 20 | 倍率変更・タブ切替 | テキストレイヤーごと作り直されるので、**当て直す**。確定事項17 の経路と同じ1本で処理する |
| 21 | 検索バーを閉じたとき | ハイライトを消す。検索語は覚えたままにし、次に開いたときの初期値にする |

### D. 検索バーの見た目と操作

| # | 論点 | 決定 |
|---|------|------|
| 22 | 置き場所 | **`#view` の「外」、ページビューの右上に浮かべる。**`#view` はスクロールする器であり、その中で `position:absolute` にすると中身と一緒に流れて画面外へ出る（`spec-1-2` 確定事項20 と同じ理由）。意匠は 2026-09-01 のモックで確定 |
| 23 | 中身 | 左から 入力欄／ヒット数（`3 / 12`）／区切り／`Aa` トグル／前へ（`chevronUp`）／次へ（`chevronDown`）／区切り／閉じる（`close`） |
| 24 | ヒット数の表示 | `現在 / 総数`。0件のときは「0 件」を `--danger` で出す。検索中は「検索中…」 |
| 25 | 開き方・閉じ方 | Ctrl+F またはツールバーの虫眼鏡で開き、入力欄を選択状態にする。Esc または閉じるボタンで閉じる。**F3 / Shift+F3 は閉じていても効く**（開いてから次へ移動する） |
| 26 | 入力中の挙動 | 打つたびに検索し直す。**1フレームに1回へ間引く**（ページビューと同じ `requestAnimationFrame` の作法）。Enter は「次へ」、Shift+Enter は「前へ」 |
| 27 | 状態の持ち方 | 検索語・ヒット一覧・現在位置は**タブごと**に持つ（確定事項3 と同じ session）。検索語だけは閉じても残す（確定事項21） |

### E. 印刷（F-01-8）

| # | 論点 | 決定 |
|---|------|------|
| 28 | 方式 | **印刷用のコンテナへ画像を並べ、`@media print` でそれ以外を隠し、メイン側の `webContents.print()` を呼ぶ。**pdf.js viewer の `PDFPrintService` と同じ考え方である。`webContents.print({ silent: false })` が OS の印刷ダイアログを出す経路で、F-01-8 の「OS の印刷ダイアログ経由」を満たす |
| 29 | なぜレンダラーの `window.print()` にしないか | オプション（`silent`・`printBackground`）を渡せず、結果（成功／取り消し／失敗）も受け取れないため。`docs/02` 第6章の「fs と OS に触るのはメイン」の線とも揃う |
| 30 | 経路 | preload に `printAPI`（`available` ・ `print(options)`）、IPC は `print:run` の1本。`docs/02` 第7章が「`window.printAPI` は Phase 1 塊③-b」と予告しているとおりに足す |
| 31 | 解像度 | **150dpi 相当**（`scale = 150 / 72 ≒ 2.083`）。pdf.js viewer の `PRINT_RESOLUTION` と同じ値である。画面用（`renderScale`）とは別の計算にする |
| 32 | メモリ | **1ページずつ描き、`canvas.toDataURL('image/png')` で `<img>` へ移して canvas を捨てる。**A4・150dpi の canvas は 1240×1754px ＝ 約8.7MB（RGBA）で、100ページ分を同時に持てない。PNG にすれば1枚あたり数百KBに収まる |
| 33 | 一度に印刷できるページ数の上限 | **100ページ。**超える範囲を指定したら、その旨を出して印刷しない。**実測に基づかない初期値である**（タブ上限20・サムネイル上限24と同じ扱い。`docs/07` 第6章）。実測して見直す |
| 34 | ページ範囲 | 「すべてのページ」「現在のページ」「ページ指定」の3択。既定は「すべてのページ」。指定の書式は **`1-5, 8`**（半角カンマ区切り、ハイフンで範囲）。全角のカンマ・ハイフンも受け付ける |
| 35 | 範囲の検証 | 範囲外・逆順・数字でないものはその場で弾き、理由をダイアログ内に出す。**押せてから失敗するのではなく、押す前に分かるようにする** |
| 36 | 進捗と中止 | 「3 / 5 ページを準備しています…」とバーを出す。中止ボタンで止める。止めたら作りかけの画像を捨てる（世代トークン） |
| 37 | 印刷中の操作 | ダイアログを `<dialog>` のモーダルで出すので、背後の操作は自然に塞がれる。文書情報（`spec-1-2` 確定事項11）と同じ作法・同じ意匠にする |
| 38 | 開き方 | Ctrl+P、またはツールバーに足す印刷ボタン。文書を開いていなければ押せない（`DOCUMENT_CONTROLS` に足す） |

## 画面の動き

| 操作 | 結果 |
|---|---|
| Ctrl+F | 検索バーが開き、入力欄が選択状態になる。前回の検索語が入っている |
| 語を打つ | 打つたびに探し直す。ヒット数が出て、最初のヒットへ飛び、そこが緑になる |
| Enter / F3 | 次のヒットへ。最後まで行ったら先頭へ回る |
| Shift+Enter / Shift+F3 | 前のヒットへ。先頭より前は末尾へ回る |
| `Aa` を押す | 大文字小文字の区別を切り替え、探し直す |
| ヒットが無い | ヒット数の位置に「0 件」が赤で出る。ハイライトは消える |
| Esc | 検索バーが閉じ、ハイライトが消える。検索語は残る |
| 別のタブへ移る | そのタブの検索状態に切り替わる（探していなければ検索バーは閉じている） |
| 倍率を変える | ハイライトはページの描き直しに追従する |
| Ctrl+P | 印刷ダイアログが開く。既定は「すべてのページ」 |
| ページ指定に `1-5, 8` と書く | 6ページ分を印刷する。範囲外を書くとその場で理由が出る |
| 「印刷…」を押す | 1ページずつ画像にする。進捗が進み、終わると OS の印刷ダイアログが出る |
| 「中止」を押す | 準備を止め、ダイアログを閉じる。何も印刷しない |
| 100ページを超える範囲 | その旨を出して印刷しない（確定事項33） |

### 実測に残すもの

- **文字の多い文書での取り出し時間。**いまある `many-pages.pdf` は40ページで751文字しかなく、
  25ms という値は下限にしかならない。`test/fixtures/build.js` に**1ページ1,500文字×40ページ**の
  fixture を足して測り直す。確定事項2（検索時にまとめて取る）の根拠がここで確かめられる
- ヒット数と、最初のヒットが出るまでの時間
- 150dpi で1ページを画像にする時間と、PNG 1枚のバイト数（確定事項32・33 の根拠）
- 100ページを印刷したときのメモリの増え方（確定事項33 の上限を見直す根拠）
- 検索バーと印刷ダイアログの実寸（`getBoundingClientRect`）
