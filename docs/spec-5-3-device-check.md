## 事前調査（2026-10-08・Windows 11 Pro 実機〔ビルド 26200。25H2〕・Electron 44）

塊②の D〜I に続けて J〜N。どれもユーザーの画面に窓を出さずに調べた。台本は `~/.claude/plans/phase-5-3-probe/`（`winpdf-render.ps1`・`DeskShot.cs`・
`m-find.js` ほか）。

### J. SigK（pdf.js）とは別の描き方 — **Windows 標準の描き方で全ページを絵にできる。PDFium もこの窓で描ける**

- Windows 標準の PDF の描き方（`Windows.Data.Pdf`。Windows に入っている）を Windows PowerShell 5.1 から呼び、ページを PNG にできた
  （3 ページで 2 秒。窓は出ない）。`test/fixtures/sigk-annotated.pdf`（SigK が書いた注釈）では、ハイライト（下の文字が透けて暗く残る）・下線・
  日本語のテキスト・四角・丸・矢印（塗った矢じり）・ペン・付箋の印を、どれも描いた。付箋の印は Windows 自前の絵（赤い丸）で描く。
- 起動確認の口で作った検体（日本語のテキスト 2 行・吹き出し・矢印）も、文字の欠けなく描いた。
- この窓の中の Browser パネル（Chromium の PDF の表示＝PDFium。Microsoft Edge・Google Chrome と同じ描き方）でも検体を開けた。付箋の印は
  PDFium 自前の絵（黄色い吹き出し）。画面写真はパネルの大きさ（800×600 前後）までしか撮れない。
- 決めたこと: 見比べの本体は Windows 標準の描き方（全ページを高い解像度の PNG にでき、台本で回せる）にし、PDFium は要所で添える（確定事項 B）。
  Adobe Acrobat での見え方は「あなたの画面で見る項目」①に残す。

### K. インストーラーの画面 — **別のデスクトップで開いて撮れる。インストールの種類のページは出ない**

- `CreateDesktop` で作った別のデスクトップ（ユーザーの画面には出ない）でインストーラーを起こし、主窓を `PrintWindow` で撮り、ボタンは
  `WM_COMMAND` で押せた（`DeskShot.cs`）。窓の枠は、別のデスクトップでは Windows の画面の合成が働かないため古い形（角の四角い枠）で写るが、
  ページの中身（文字・部品の位置）はそのまま撮れる。
- 最初のページは「インストール先を選んでください。」（入れ先の欄に常用の入れ先 `%LOCALAPPDATA%\Programs\SigK PDF`、必要な容量 385.6 MB）。
  **インストールの種類（自分だけか全員か）を選ぶページは出なかった**（spec-5-1 判定12 の前半）。
- 「キャンセル」を押すと、確かめの窓なしで終わった。この調べでは「インストール」を押していない（ファイルもレジストリも書いていない）。
- 決めたこと: 本物の上書きインストールを、この形（別のデスクトップで「インストール」→完了ページを撮る→「完了後に起動」の印を外して「完了」）で
  行い、完了ページの 7 行の文を撮る（確定事項 C）。
- **2026-10-08 追記（確定事項 C の上書きのとき）**: `PrintWindow` の描かせ方で写り方が違った。flags 0（窓に自分を描かせる）は、完了ページの透明の地の文字（題と文）を
  描かず、窓の枠が古い形になる。flags 2（`PW_RENDERFULLCONTENT`）は Windows 11 の枠で完了ページを全部描くが、インストール先のページの説明の文と
  容量の行を描かない。そこで完了ページは flags 2 で撮り、インストール先のページは枠を flags 2・中身を flags 0 で撮って重ねた（`compose-frame.ps1`）。
  部品の文字は `WM_GETTEXT` で全部読める。ガイドの絵のために、入力欄の文字を入れ替える `settext`・選ぶ範囲を決める `sel`・部品が出るまで待つ `until`・
  窓の中を押す `click`・持ち主の窓を全部撮る `shotall` を `DeskShot.cs` に足した。

### L. 起動の跡 — **開いたファイルは設定の「最近使ったファイル」に残る。本物のシェルからの起動は別名で行う**

- アプリは、開いたファイルを設定の置き場（`%APPDATA%\SigK PDF\settings.json`）の「最近使ったファイル」（10 件）に書く（`recent-documents.js`・
  `settings.js`）。Windows のジャンプリスト（`app.addRecentDocument`）には書かない。
- 右クリックの項目に登録されたコマンドは `"<入れ先>\SigK PDF.exe" --open "%1"` の形で、`--user-data-dir` を付けられない。エクスプローラーと
  同じ呼び出しで本物の入れ物を起こすと、常用の設定に跡が残り、ユーザーが SigK PDF を開いていればそこへ転送される。設定の置き場を
  環境変数で変える口も `main.js` に無い。
- 決めたこと: 本物の入れ物では、登録されたコマンドの文字をそのまま使い、後ろに `--user-data-dir=<scratchpad>` を足して起こす（確定事項 C）。
  エクスプローラーと同じ呼び出しからの起動（`docs/03` #2〜#5・#7・#8）は、別名のインストーラー「SigK PDF Probe」（設定の置き場が
  `%APPDATA%\SigK PDF Probe` で常用と別）で行う。塊①の S8 と同じ作り（確定事項 D）。

### M. 「その他のオプションを確認」の項目名 — **Windows のファイルから読み出せた**

- `C:\Windows\System32\ja-JP\Windows.UI.FileExplorer.dll.mui`（Windows 11 の新しい右クリックメニューの日本語の資源）に、
  「ZIP ファイル(&Z)に圧縮する」と並んで **「その他のオプションを確認(&W)」** がある。同じファイルには「その他のオプションを表示」という文字も
  あった（別の場所。使われる場面は分からない）。メニューの項目名は、アクセスキー付きの前者と読める。塊①で公開の解説記事から書いた項目名
  （決定45 ⑤）と一致する。

### N. 検体を作る口 — **起動確認の口で、全部の機能の出力を作れる**

- 結合 `SIGK_SMOKE_MERGE`・分割 `SIGK_SMOKE_SPLIT`・画像→PDF `SIGK_SMOKE_CONVERT`（`SIGK_SMOKE_CONVERT_JPEG=1` で JPEG の検体を足す）・
  PDF→画像 `SIGK_SMOKE_TO_IMAGE`・透かし `SIGK_SMOKE_WATERMARK`・フラット化 `SIGK_SMOKE_FLATTEN`・書き込み `SIGK_SMOKE_ANNOTATE`
  （ハイライトから吹き出し・図形・マーカー・トリミング・モザイクまで、道具ごとの操作を流して保存する）。どれも出力先を指定できる。
- 隠した窓で、日本語のテキスト・吹き出し・矢印を置いて保存できた（13 秒・problems なし・`window.hidden: true`）。
- 「PDF を画像に」は、pdf.js が書き込みの見た目ごと描く（spec-3-3 確定事項14）。これを SigK の描き方の絵として使える。
- 入力は `test/fixtures/` の検体だけ（付則 C）。JPEG の検体は起動確認が作る合成の画像。

### 計画外の直し（決定75 ⑤。確かめの道具の側の不具合で、アプリの動きは変わらない）

1. **起動確認の `inspectTexts` が、外観（/AP）の無い FreeText で止まる**（`6239d63`）。`test/fixtures/annotated.pdf` には他のアプリが作った外観の無い
   FreeText があり、これを開いて保存した検体（`g2-annotdel`）の起動確認で `Cannot read properties of undefined (reading 'contents')` が problems に出た。
   保存そのものは正しかった。外観が流れでないときは外観の欄を「無い」の値で返し、外観の有無を示す `appearance` の欄を足した。
2. **配布物で `SIGK_SMOKE_CONVERT_JPEG=1` を使うと止まる**（`797e4ed`）。JPEG の検体を `test/fixtures/image-wide.png` から作っていたが、配布物には
   `test/` を同梱しない。無いときは `smokeSampleBitmap` が描く横長の絵（400×240。白地に濃い枠・上に青の帯・左下に赤の四角）から作る。
   作り直した配布物で、400×240 の JPEG が A4 横に置かれることを確かめた。
