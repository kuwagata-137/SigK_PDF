# 画像を開いて編集し、画像のまま保存する（第2版 7-1）の仕様と記録

作成: 2026-11-07。作業ブランチ `claude/compassionate-davinci-n9zg2u`（`origin/main` = `c608936` から）。
決定の元: `docs/07_開発計画の決定事項.md` 決定86。計画: `~/.claude/plans/melodic-hugging-ladybug.md`（2026-11-07 にユーザーが承認した）。

## 目的

ユーザーの依頼「編集機能では画像も編集して保存できるようにしたいです。」（2026-11-06）による。

編集モードの道具は CheckListMaker の画像エディタ（スクリーンショットに描き込む機能）を手本にした（`docs/05` Phase 4B）。ところが、開けるのは PDF だけで、
スクリーンショットや写真に描き込むには、いったん画像→PDF で PDF にしてから開き、PDF→画像で画像に戻す必要があった。そこで、PNG・JPEG などの画像を
タブで開き、編集モードの道具で書き込み、書き込みを画素に焼き込んで画像のまま保存できるようにする。

PDF の中に埋め込まれた画像を動かしたり差し替えたりする機能は、この仕様に含めない。

## 事前調査（2026-11-07・クラウドの Linux・Chromium と pdf.js 6.3.289）

### A. pdf.js で倍率 1 に描いた画素は、元の画素と同じか

画像を 1 画素＝1pt の紙に、白を敷かずに載せた PDF を pdf-lib で作り、pdf.js で倍率 1 に描いて、ブラウザで読み解いた元の画像と画素ごとに比べた。

| 画像 | 違った画素 | 透明さ（アルファ） |
|---|---|---|
| `test/fixtures` の PNG 4 枚（300×200 の透明な PNG・1200×800・600×900・64×64） | 0 | 背景を塗らずに描くと（`background: 'rgba(0,0,0,0)'`）すべて元のまま。既定の描き方では白く塗られる |
| 画素がばらばらの PNG（333×257） | 0 | — |
| 同じ画素の JPEG（品質 0.95） | 85,581 画素のうち 84,354（RGB の差は平均 4.9、最大 47） | — |

- PNG（と、ワーカーが画素へ展開して可逆圧縮で載せる BMP・GIF・TIFF）は、pdf.js で倍率 1 に描けば元の画素と一致する。
- JPEG は、pdf.js が自前で読み解くため、ブラウザ（と Windows のビューア）が読み解いた画素とずれる。画素がばらばらの画像は JPEG にとって最も厳しい条件で、
  写真ではずっと小さい見込みだが、上書きのたびにずれが積み重なるのは避けたい。そこで JPEG だけは、保存のときにブラウザで読み解いた元の画像を下に敷き直す
  （確定事項 B4）。

## 確定事項

### A. 開く

1. **開ける画像は PNG・JPEG・BMP・GIF・TIFF**（拡張子は画像→PDF と同じ 7 つ）。GIF は最初のコマだけ、複数ページの TIFF はページごとに 1 ページとして開く
   （画像→PDF と同じ）。プログレッシブ形式の JPEG は、画像→PDF と同じ理由（pdf-lib が埋め込めない）で開かない。大きさの上限も画像→PDF と同じ
   （100MB・4,000 万画素）。
2. **ページの大きさは 1 画素＝1pt**（画像→PDF の「画像サイズに合わせる」と同じ）。テキストの 12pt は 12 画素になる。
3. **紙を白で塗らない。**画像→PDF は紙を白で塗ってから画像を置く（`worker/image-page.js`）が、画像を開くときは塗らずに置く。保存のとき透明な部分を
   透明のまま残すためである。画面では、紙の白の上に透けて見える。
4. **画像を PDF に組み立てるのはワーカー**（`kind: 'image-open'`。`worker/image-open-task.js`）。メインの「パスで読む口」（`pdf:read`）と「開く窓」（`pdf:open`）が、
   拡張子が画像ならワーカーに組み立てさせ、PDF と同じ形 `{ ok, path, name, size, mtimeMs, bytes }` に `image: { kind, frames, original }` を添えて返す
   （`image-open.js`）。こうすると、画面の開く経路（Ctrl+O・ドロップ・最近使ったファイル・起動の引数・保存のあとの開き直し）を 1 本も分けずに画像を通せる。
   `original` は元の画像のバイト列で、JPEG のときだけ添える（確定事項 B4）。
5. **入口**
   - 開く窓（Ctrl+O・ツールバーの［開く］）：フィルターを「PDF と画像」「PDF」「画像」の 3 つにする。
   - ドロップ：閲覧・ページ編集・編集モードでは、画像もタブで開く。ツールモードでは今のまま画像→PDF（透かしを選んでいれば透かしの画像）へ渡す（決定80 ⑱を変えない）。
   - 起動の引数：意図の無い起動（裸のパス）と `--open` で画像も受ける。エクスプローラーの「プログラムから開く」で SigK PDF を選んだときに通る。
   - 最近使ったファイル：画像も残す。
   - ツールモードの帯の受け口の［ファイルを開く…］は、今のまま PDF だけを選ぶ（ツールモードの画像は画像→PDF へ渡す決まりに合わせる）。
6. **画像のタブの中身**：viewer は、組み立てた PDF のバイト列の写しを `file.copy`（鍵 `image`）として持つ。PDF での保存と、帯のページを別の帯へ写す
   機能は、この写しから読む（名前の無い帯と同じ経路。`sourceCopy`）。`untitled` ではないので、書き込みもページの変更も無ければ「変更あり」にならない。
7. **画像のタブでは呼ばない口**：紙全体の大きさを読む口（`pdf:readBoxes`）は呼ばない（紙全体は画像そのもので、`page.view` と同じ）。注釈の辞書を
   読み戻す口は、読み込んだ注釈が無いので呼ばれない。
8. **ツールモードのツールでは使えない。**結合・分割・PDF→画像・透かし・フラット化は、タブのパスからファイルを読み直して動くので、画像のタブは
   「「〇〇.png」は画像なので、PDF として保存すると使えます。」として対象から外す（名前の無い帯の「保存すると使えます」と同じ扱い）。

### B. 保存する

1. **［上書き保存］**
   - PNG・JPEG のタブは、同じ形式・同じ画素数で書く。JPEG の品質は 0.95（PDF→画像の 0.9 より上げ、上書きのたびに画質が落ちるのを抑える）。
   - 書く前に、毎回確認の窓を出す（付則C。ユーザーの確定。`docs/07` 決定86 ①）。文は確定事項 B6。
   - 設定の「控えのファイル（.bak）を作る」が入っていれば、PDF と同じく `.bak` を残す。（2026-11-12 から、設定の最初の値は「作らない」。`spec-7-4` 確定事項BK1）
   - 開いたあとでほかのアプリが画像を書き換えていたら、PDF と同じ確認の窓（`confirm-overwrite.js`）を出す（大きさと更新時刻で照らす）。
   - BMP・GIF・TIFF は同じ形式で書けないので、［名前を付けて保存］の窓を出す。
   - 書き込みもページの変更も無ければ、何もしない（PDF と同じ）。
2. **［名前を付けて保存］**：PNG・JPEG・PDF から選ぶ。既定の名前は、同じフォルダの同じ名前で、拡張子は元の形式（BMP・GIF・TIFF なら `.png`）。
   - PNG・JPEG を選ぶと、書き込みを焼き込んだ画像を書き、タブはその画像になる。元の画像は変わらないので、確認の窓は出さない。開いている画像そのものを
     選んだときは［上書き保存］と同じに扱う（確認の窓と `.bak`）。
   - PDF を選ぶと、書き込みを PDF の注釈のまま書き（あとから直せる）、タブはその PDF になる。中身は今の PDF の保存と同じ経路を通る。
   - 拡張子を付けずに名前を打ったときは、元の形式の拡張子を足す。
3. **画像にできないとき**：ページが 1 枚でないとき（複数ページの TIFF・ページ編集で足した・消した）は、［上書き保存］も［名前を付けて保存］も、PDF だけを
   選べる保存の窓を出し、通知バーで「ページが 2 ページ以上あるので、PDF で保存します。」と知らせる。
4. **描き方**：印刷と同じ描き手（`page-image.js` の `renderToCanvas`）で、倍率 1・ページの回転・トリミングの範囲・モザイク・書き込みを 1 枚に描き、
   背景は塗らない。JPEG のタブでは、pdf.js が描いたあと、モザイクと書き込みを描く前に、ブラウザで読み解いた元の画像を紙の座標に合わせて描き直す
   （事前調査 A。EXIF の向きは画像→PDF と同じく読まない）。
5. **保存したあとはタブを開き直す。**PDF の保存と同じで、元に戻す履歴は保存したところから始まり、書き込みは画像の画素になる。
6. **上書きの確認の窓**（`confirm-image-save.js`）

   | 欄 | 文 |
   |---|---|
   | 題 | 画像に焼き込んで上書き保存しますか |
   | 本文 | 書き込みを「〇〇.png」の画像に焼き込んで、上書き保存します。 |
   | 失うもの | 保存したあとは、書き込みを動かしたり直したりできません。書き込みの下にあった元の画像も元に戻せません。 |
   | 控え | 元の画像は、控えのファイル（〇〇.png.bak）に残します。（控えを作らない設定のときは出さない） |
   | ボタン | ［焼き込んで上書き保存］（危険の色）・［キャンセル］。既定のフォーカスは［キャンセル］ |

   モザイクのある PDF の保存で出す確認（`confirm-mosaic.js`）は、画像の保存では出さない。画像の保存は、モザイクも含めてすべてを画素に焼き込むためで、
   確かめることはこの窓に含まれている。

### C. 画像のタブで使えない道具

1. ハイライト・下線・取り消し線とノートは、画像のタブでは灰色にして押せなくする。ハイライト・下線・取り消し線は紙の文字を選んで引く道具で、画像には
   選べる文字が無い。ノートは、画像に焼き込むと付箋の絵だけが残り、本文が消える。
2. 灰色のボタンにカーソルを当てると、説明の吹き出しで理由を出す。
   - ハイライト・下線・取り消し線：「画像には選べる文字が無いので、使えません。」
   - ノート：「画像に保存すると付箋の本文が残らないので、画像では使えません。」
3. 道具を持ったまま画像のタブへ移ったら、道具を離す。
4. 検索は当たらない（文字が無いため）。何もしない。

## 既知の限界

- 透明な PNG は、画面では紙の白の上に見える（市松模様は出さない）。保存した画像では透明のまま。
- 透明な所にモザイクを掛けると、その範囲は不透明になる（モザイクは平均の色で塗り、塗った画素を不透明にする。PDF の保存のモザイクと同じ塗り方）。
- JPEG を上書きするたびに、JPEG に書き直すぶん画質は少しずつ落ちる（品質 0.95）。
- プログレッシブ形式の JPEG は開けない（画像→PDF と同じ）。
- EXIF の向きは読まない（画像→PDF と同じ。決定30 ③）。**2026-11-12 追記**: 縦長の写真が横長で開き、回転して上書き保存すると縦横比が崩れたので、
  JPEG の向きのうち回転を読むようにした（`spec-7-4` 確定事項X1〜X3・決定90）。鏡に映した向きは今のまま読まない。
- エクスプローラーの「プログラムから開く」の一覧に、画像のときは SigK PDF が出ない。インストーラーが「対応する形式」（`SupportedTypes`）に `.pdf` だけを
  書いているためで、「PC でアプリを選ぶ」から SigK PDF を選べば開く。一覧に出すには、インストーラーを直して Windows の実機で確かめる必要があり、
  右クリックの「SigK PDF で編集」と一緒に別の PR にする（`docs/07` 決定86 ②）。

## 実装の記録（2026-11-07・`claude/compassionate-davinci-n9zg2u` ブランチ）

### 仕様書から足したこと・変えたこと（起草者の判断）

- **画像の保存のモザイクは、画面の下見と別の塗り方にした。**画面の下見（`mosaicPaint.paintOver`）は、書き込みを描かない絵と比べて色の違う画素を
  「pdf.js が描いた書き込み」とみなして塗らずに残す。画像の保存で JPEG を敷き直したり背景を透明にしたりすると、敷き直した画素や透明な画素が
  書き込みとみなされ、元の画素がモザイクから漏れる。画像のタブには pdf.js が描く書き込みが無いので、PDF の保存の画像と同じく比べる絵を使わずに
  塗る（`mosaicPaint.paint`。`renderer/image-render.js`）。
- **JPEG に書くときは白を敷く。**JPEG は透明を持てず、Chromium は透明を黒にして JPEG にするため。透明な PNG を JPEG で保存したときに黒くならない。
- **画像のタブでは、トリミングの道具が紙全体を読みに行かない。**`page-boxes.js` は画像のタブで鍵を作らないので「まだ読んでいない」のままになり、
  トリミングの道具が読み直しを頼み続けて止まった（`test/image-tools.test.js` を書いて見つけた）。名前の無い帯と同じく、`trim-tool.js` の
  `ensureBoxes` で画像のタブを外した。紙全体は `page.view`（画像そのもの）になる。
- 画面の文の直し：ツールバーの［開く］とタブの「＋」の説明の吹き出し、使い方の窓の「開く・保存する」（1 項目を直し、3 項目を足した）、
  閲覧・編集モードで PDF でも画像でもないものをドロップしたときの文（ツールモードと同じ文にした）。使い方ガイドの 8 章に 2 行、9 章に
  「画像に書き込んで保存する」の節を足した。

| JPEG（1200×800）を［上書き保存］ | 確認の窓が出て、1200×800 のまま書き、`.bak` が残った。線は JPEG の圧縮でにじみ (164, 31, 78) になった（目で見て赤い線） |
| 画素がばらばらの JPEG（333×257）を PNG で保存 | 四角の外の画素が、元の JPEG を読み解いた画素と 1 画素も違わない（敷き直しが効いている。事前調査 A では、敷き直さないと平均 4.9 ずれた） |
| BMP（640×480）を［上書き保存］ | 保存の窓が出て（台本が PNG を選んだ）、640×480 の PNG ができた。元の BMP は変わらない |
| PNG を［名前を付けて保存］で PDF | 1200×800pt の 1 ページで、四角は `/Square` の注釈のまま残った。タブは PDF になった |
| 道具の段 | ハイライト・下線・取り消し線・ノートが灰色で、吹き出しの文は確定事項 C2 のとおり |

PNG・BMP・GIF・3 ページの TIFF を `SIGK_SMOKE_PDF` で開く確認も通した（本物のワーカーで組み立てて、ページ数と紙の大きさが画像のとおり）。
画面の写真（灰色の道具・確認の窓）を撮って目で確かめた。灰色のボタンの吹き出しは、台本から送ったマウスの動きでは出ず、写真には写っていない
（文は画面の部品から引いて確かめた）。

  Windows でしか確かめられない。

- 配布物（`npm run dist`）の起動確認。Windows のインストーラーはこの環境では作れない。
