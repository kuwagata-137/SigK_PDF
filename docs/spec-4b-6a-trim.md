## 目的

編集の道具の段に「トリミング」を足し、ページの見える範囲を切り詰められるようにする。切るのは見え方だけで、ページの中身は消さない。
保存では PDF の決まりの欄 `/CropBox` に書き、開き直したあとでも［トリミングを外す］で紙全体に戻せる。

今の画面は、表示・サムネイル・印刷のどれも pdf.js の `page.getViewport()` で描いており、描く範囲はファイルの `/CropBox`（pdf.js の `page.view`）で
決まっている。保存する前の編集としてトリミングを持つには、描く範囲（箱）を差し替える口を作り、表示・注釈の層・文字の層・サムネイル・印刷・寸法へ
同じ箱を通す必要がある。この口は ⑥-b のモザイクでも、CropBox に関係なく紙全体を描くときに使う。

## 事前調査（2026-10-06・Windows 11 実機・Electron 44・pdf.js 6.3.289・pdf-lib 1.17.1）

試作は `~/.claude/plans/phase-4b-6-probe/`（`make-b.js`・`probe.html`・`probe-c.js`・`probe-e.js`・`mock/scenes-6*.js`・`NOTES.md`）。

### A. CheckListMaker のトリミングとモザイク（`kuwagata-137/CheckListMaker` 574cc68 の `index.html`）

- トリミング: 道具を押すと画像全体の枠（＝切らない）と 8 点のつまみが出る。外側は `rgba(0,0,0,0.45)`。もう一度道具を押すと適用、［取消］・Esc・別の道具で
  取りやめる。最小 10px。全体のままなら履歴を積まない。
- モザイク: ドラッグの間は青い破線の四角。離したら範囲をブロックの平均色で塗る。ブロックは max(8×換算, 線の太さ×2)。
- SigK PDF ではページが縦に何枚も並ぶので、「道具を押すと全体の枠」はどのページに出すかが曖昧になる。引いた所でページが決まる形にした（決定64 ①）。

### B. pdf.js で任意の箱の viewport を作れるか

- `PageViewport` は export されていないが、`page.getViewport()` の戻り値の `constructor` に `{ viewBox, userUnit, scale, rotation }` を渡せば作れる。
- 検体の 1 ページ目（CropBox なし）を viewBox `[100 200 400 600]` で描くと、同じ絵のページにファイルの CropBox `[100 200 400 600]` を書いて
  普通に描いたものと、寸法・`transform`・画素（赤い四角・緑の注釈の外観）・`convertToViewportPoint`／`convertToPdfPoint`・`TextLayer` の
  span の位置まで一致した。90° 回転・2 倍・原点のずれた MediaBox（`[50 60 650 860]`）でも一致した。
- **pdf.js は CropBox で絵を切らない。**CropBox のあるページを viewBox = MediaBox で描くと、CropBox の外の絵も描かれた。→ 保存したあとの
  ［トリミングを外す］も、同じ口で紙全体を描ける（⑥-b のモザイクでも使う）。
- pdf.js は MediaBox を返さない（`page.view` は CropBox と MediaBox の重なり）。紙全体の大きさはワーカー（pdf-lib）で読む。

### C. pdf-lib の `/CropBox` と保存の組み直し

- `setCropBox(x, y, w, h)` で書ける。`getCropBox()` は CropBox が無ければ MediaBox を返す。MediaBox との重なりや並べ直しはしない。
- **既存の不具合（再現した）**: ページ木の中間の `/Pages` に MediaBox・CropBox を置き、ページは受け継ぐだけの PDF を保存すると、保存の組み直し
  （`worker/op-pages.js` の `applyPlan`。`removePage` → `insertPage`）でページの親が根に付け替わり、受け継いでいた MediaBox・CropBox が消える。
  保存し直したファイルは pdf.js で 612×792（Letter の既定）になった（元は 300×400 の表示・600×800 の紙）。Resources・Rotate も受け継げる欄なので、
  Resources を中間に置く PDF では文字や画像が消えるおそれがある（理屈。検体は作っていない）。→ 外す前に、各ページへ受け継いだ欄を直に写す（確定事項 E1）。

### D. 描く範囲を差し替える経路

- 寸法: `renderer/viewer.js` の `sizesFromPlan`（`basePages` の幅・高さ）と `getPaperBox`（テキストの自動の幅の上限）。
- 描く: `renderer/page-render.js` の 3 か所（canvas・注釈の層・文字の層）、`renderer/thumbnails.js`、`renderer/page-image.js` の `viewportFor`（印刷）。
- 保存したファイルから描くもの（PDF→画像・透かしの下見）は対象外（ほかの未保存の編集と同じ）。
- **既存の不具合（コードで確かめた）**: `renderer/page-plan.js` の `rotatePages` は回すページを `{ src, rotate }` で作り直すので、差し込んだ未保存の
  ページ（`{ insert, rotate }`）を回すと差し込みが落ちる。トリミングの欄も同じ所で落ちる。**この不具合は別のセッションが PR #39
  （`claude/fervent-saha-4bcb09`）で直している**（2026-10-06 に気づいた。調べたエージェントの別作業の提案から始まったもの）。⑥-a は、トリミングの欄を
  運ぶのに要る同じ 1 行（`{ ...copyPage(page), rotate }`）を PR #39 と同じ形で入れ、差し込みのテストは PR #39 に任せる（確定事項 A3）。

### E. モザイクの未知（⑥-b の引き継ぎ文書へ写す）

ページの中身を差し替えて保存しただけでは古い中身がファイルに残り、根から辿れない間接オブジェクトを消すと消えること、上書き保存は毎回 `.bak` を残すことを

## 確定事項

### A. 持ち方（`renderer/page-plan.js`・新 `renderer/page-crop.js`）

1. plan の要素 `{ src, rotate }` に、切った範囲 `crop: [x1, y1, x2, y2]` を足せる。PDF の座標（回す前・pt）で、x1 < x2・y1 < y2、小数 2 桁に丸める。
   **欄が無ければ「ファイルのまま」**（pdf.js の `page.view`）。差し込んだページ（`{ insert }`）には付けない。
2. 切った範囲がファイルの見える範囲（`page.view`）と同じ（各辺 0.01pt 以内）になったら、欄を消す（未保存の印が残らないように）。
3. `copyPage`・`clonePlan` は `crop` を写す（配列は新しく作る）。`rotatePages` は `copyPage` で写してから角度だけ替える（PR #39 と同じ行。どちらが先に
   マージされても衝突しない）。
   `movePages`・`deletePages` は今のまま `copyPage` を通る。`samePlan` は `crop` も比べる。`isDirty` は `crop` があれば変更ありとする。
4. 純関数は `renderer/page-crop.js` に置く: 箱の正規化と比較、2 点からの箱、つまみ・中を掴んだときの箱の動かし方（下限 10pt）、表示の向きの余白と
   回す前の箱の行き来（すべてのページ用）、回転込みの寸法。

### B. 描く範囲（新 `renderer/page-viewbox.js`）

5. `viewportFor(page, { scale, rotation, box })`: `box` が無いか `page.view` と同じなら `page.getViewport({ scale, rotation })`。違えば
   `getViewport` の戻り値の `constructor` に `{ viewBox: box, userUnit, scale, rotation }` を渡して作る（事前調査 B）。
6. 表示（`page-render.js` の canvas・注釈の層・文字の層）、サムネイル（`thumbnails.js`）、印刷（`print.js` → `page-image.js` の `renderToCanvas` に `box`）は、
   どれもこの口に plan の `crop` を渡す。書き込みの当たり・つまみ・テキストの入力欄・検索のハイライトは、描いた viewport から座標を取るので、そのままそろう。
7. 寸法: `viewer.js` は開いたときに各ページの `rotate`・`userUnit` も控える（`basePages`）。`sizesFromPlan` は `crop` があればその幅・高さ（回転が 90°・270°
   なら入れ替え、`userUnit` を掛ける）を使う。ページ番号・幅に合わせる・全体・見開き・ページ編集の格子・差し込みの基準の大きさは寸法に付いてくる。
8. `getPaperBox(src)`（テキストの自動の幅の上限）は、そのページの `crop` があればそれを返す。

### C. 紙全体の大きさを読む口（ワーカーの `page-boxes`・新 `renderer/page-boxes.js`）

9. ワーカーに読むだけの種類 `page-boxes` を足す（`worker/tool-tasks.js` の表。`annotation-details` と同じく進捗を送らない）。開いているファイルを
   pdf-lib で読み、ページ順に MediaBox（受け継いだ値も解決し、並べ直した `[x1, y1, x2, y2]`）を返す。
10. レンダラーは、トリミングの道具を持ったときに、その文書でまだ読んでいなければ裏で読む。結果は文書ごと（タブを替えても）に持ち、保存して開き直したら
    読み直す。読めなかった（暗号化・壊れたファイル）ときは、紙全体の代わりに開いたときの見える範囲（`page.view`）を使う。

### D. トリミングの道具（新 `renderer/annotate-trim.js`・`trim-frame.js`・`trim-props.js`。見本 `phase4b-6-trim-frame.png`・`-trim-applied.png`）

11. 道具の段のノートの後ろに区切り線を挟んで「トリミング」を置く（`index.html`。アイコンは CheckListMaker と同じかぎ形 2 本〔`assets/icons.js` の `trim`〕）。
    描かない道具（`annotate-tools.js` の `POINTER_TOOLS`）に足す。段に入りきらなければ「その他」に入る（⑤-b の仕組みのまま）。
12. トリミングを持って紙の上を左ボタンで引くと、そのページに枠が出る（3px を超えて動かしてから）。枠はそのページの今の見える範囲の中に収める。
    枠の外側（そのページの紙の上）は `rgba(0,0,0,0.45)` で暗くし、枠は 2px のアクセント色、8 点のつまみ（白地にアクセント色の縁の 10px の四角）、
    枠の下に「幅 ○ mm × 高さ ○ mm」の札を出す。書き込みは選ばず掴まない。
13. 枠があるとき、つまみを掴むと大きさを、枠の中を掴むと位置を変える（見える範囲の中で、各辺 10pt の下限）。枠の外を引くと引き直す（別のページでも）。
    カーソルは、つまみの上は向きの矢印、枠の中は移動、そのほかの紙の上は十字。
14. Enter か右パネルの［適用］で切る。1 世代（元に戻す・やり直す）にまとめ、枠を消す。道具はトリミングのまま。切ったページの上端へ表示を寄せる。
    枠が今の見える範囲と同じなら、何も積まずに枠だけ消す。
15. Esc（引いている途中なら引く前の枠へ戻し、引いていなければ枠を消す）・［取消］・道具やモードを替える・左＋右・取り消しとやり直しの前・保存と印刷の前は、
    枠を捨てる。倍率が変わっても枠は残す（紙の座標で持ち、描き直す）。引いている途中に倍率が変わったら、引く前の枠に戻す。
16. 差し込んだ未保存のページで引いたら、枠を出さずに帯（黄）「差し込んだページは、保存してから切ってください。」を出す。
17. 右パネル（道具を持っている間）: 種類「トリミング」、当てるページ［このページ］［すべてのページ］（道具を持つたびに［このページ］に戻す）、
    枠があれば「残す大きさ 幅 ○ mm × 高さ ○ mm」と［取消］［適用］、無ければ今のページ（ページ番号の欄のページ）が切ってあるかと［トリミングを外す］、
    ヒント「紙の上を引いて残す範囲を囲み、つまみで整えてください。Enter か［適用］で切ります。Esc でやめます。切った外側は隠れるだけで、［トリミングを外す］で
    戻せます。」。
18. **すべてのページ**（決定64 ②）: 枠を引いたページで、見える範囲の上下左右の端から枠までの幅（表示の向き・pt）を測り、ほかの元のページ（差し込んだ
    ページを除く）の見える範囲の、表示の向きの上下左右から同じ幅を切る。切ると幅か高さが 10pt 未満になるページはそのままにする。適用は全部で 1 世代。
    帯（青）「○ ページを切りました。」に、そのままにしたページ（小さすぎた・差し込んだ）があれば数を添える。
19. **トリミングを外す**（決定64 ③）: このページ（すべてのページなら元のページ全部）の見える範囲を紙全体（C の MediaBox）に戻す。1 世代。紙全体がファイルの
    見える範囲と同じなら `crop` の欄を消す（確定事項 2）。紙全体をまだ読み終えていなければ待ってから当てる。どのページも紙全体のままなら押せない。
20. 切った範囲の外の書き込みは消さない（決定64 ④）。紙の外に隠れるだけで、外すとまた見える。注釈一覧には残る。

### E. 保存（`worker/op-pages.js`・`op-extract.js`・新 `worker/page-box-rules.js`）

21. 保存の組み直しで外す前に、各ページへ受け継いでいる MediaBox・CropBox・Resources・Rotate を直に写す（事前調査 C の不具合の直し。保存のたびに、
    切ったかどうかによらない）。
22. plan の `crop` は、MediaBox との重なりに収めてから `/CropBox` に書く。MediaBox と同じ（各辺 0.01pt 以内）なら `/CropBox` を消す。重なりが無い・幅か高さが
    1pt 未満の値は保存を断る（「ページの切り方が正しくありません。」）。
23. ページの抽出（`op-extract.js`）も、写したページに同じく当てる。
24. 開き直すと、pdf.js の `page.view` が切った範囲になる。plan は開き直しで作り直すので `crop` の欄は無くなる。

### F. その他の経路と画面

25. 印刷は切った範囲で刷る。PDF→画像・透かし・フラット化・結合・分割は保存したファイルを読む（ほかの未保存の編集と同じ）。
26. Esc の順（`annotate-cancel.js`）: 引いている途中の消しゴムの後に、トリミングの引いている途中 → トリミングの枠、を足す。Enter（`viewer-keys.js`）は、
    トリミングの枠があれば適用を先に見る。
27. ヒント（`annotation-hints.js`）・カーソル（`shell.css`）・一覧の名前は「トリミング」。画面の文言では「切る」「トリミングを外す」を使う。

### G. 起動確認（新 `smoke-annotate-trim.js`）

28. 操作を足す: `trim:<page>:<x1>x<y1>-<x2>x<y2>[:all]`（引いて Enter）、`trim-draft:…`（引くだけ）、`trim-move:<dx>x<dy>`（枠の中を掴んで動かす）、
    `untrim:<page>[:all]`、`trim-tool`。報告に、ページの寸法・plan の `crop`・保存して開き直したあとの `page.view` を出す。画面写真を `screenshots/phase4b-6a-app-*.png` に残す。
