## 目的

編集モードで、**書き込みの色をパレット（テーマの色 10・濃淡 5 段・標準の色 10）から選べ、四角・丸は塗りと線なしを選べる。線種は
実線・破線・雲形（雲形は四角・丸だけ）から選び、線の太さは 1〜40pt、不透明度は 10〜100% を、スライダーと数値欄で選べる。スライダーを
動かしている間は下見が出て、離すと 1 世代だけ積まれる。保存すると PDF 標準の注釈（外観付き）の `/C`・`/IC`・`/BS`・`/BE`・`/RD`・`/CA` に
書かれ、開き直しても同じ見た目のまま直せる**（F-05-11）。

右パネルは CheckListMaker の画像エディタに寄せ、色の行には今の色を示すチップを 1 つ置き、押すとパレットが開く（決定47）。①-a の
読み戻しの口の答えを使い、①-a が表示のみにした他のアプリの書き込み（塗り・線なし・破線・雲形・`/RD`）も直せるようにする。

## 事前調査（2026-09-28・Windows 11 実機・Node 24・Electron 44・pdf.js 6.3.289・pdf-lib 1.17.1・fixtures と scratchpad の検体のみ）

### C. 画面 — 図形 100 個の層の描き直しは 0.8ms

- `annotation-layer.draw` で図形 100 個の層を描き直す時間（DOM を組んでスタイルを当てるまで）: 中央値 0.8ms・95% 1.3ms。
  倍率 100% と 400% で同じ。図形を描いている間は今も mousemove のたびに表示中の全ページの層を描き直しており、スライダーの
  input ごとの下見も同じ重さで済む。
- range の input は動かしている間に何度も、change は離したときに 1 回出る。キーボードの矢印では 1 押しごとに両方出る（HTML の
  決まり。人の操作でしか確かめられないので、実装後の目視で見る）。
- `<input type="color">` は、Windows では OS の色の選択が開く見込み（推測）。窓を出さない起動確認では開けないので、値を入れて
  change を流して確かめ、開き方はユーザーの目視で見る。
- 幅 260px の右パネルに、色のチップと値・線種のボタン 3 つ・スライダー＋数値欄＋単位が収まる（モック）。

### D. 塗りと不透明度の見え方 — 塗りと線を別々に薄めると、重なる帯が濃く出る

白紙に 7 通り（塗り付き矩形 50%・塗り付き楕円 50%・線なしの塗り 50%・塗りなしの線 50%・30pt 角に 40pt・塗り付き楕円 100%・
白い塗りに細い線 35%）を置き、外観の組み方を 3 通りにして、pdf.js で描いた画素（倍率 2）と、画面の描き方（SVG の
`<g opacity>` に塗りと線を 1 要素で描く）の画素を比べた。

| 組み方 | 塗り付き矩形 50% | 塗り付き楕円 50% | ほかの 5 通り |
|---|---|---|---|
| v1: `/GS gs` のあと、塗りと線を 1 本の path で `B` | 差 41・15,552 画素 | 差 42・13,526 画素 | 楕円 100% を除き差 0 |
| v2: 透明グループ（`/GS gs /G0 Do`。`G0` は `/Group << /S /Transparency >>` の Form で、中は不透明で描く） | 差 0 | 差 28・906 画素（縁） | 同上 |
| v3: 塗りを線の内側の縁までに限る | 差 0 | 差 27・1,154 画素（縁） | 同上 |

- v1 は、線の内側半分（塗りと重なる帯）が濃く出る（画面の [236,149,149] に対し [236,142,108]）。今の印刷の描き方（要素ごとに
  `globalAlpha`）も同じ帯が出る。別の canvas に不透明で描いてから alpha で重ねると、画面と一致する。
- v2 をフラット化のワーカー関数で焼いた結果は、焼く前と全画素一致（200 万画素中の差 0）。
- 楕円の縁の差は、塗りの有無によらず出る。ベジェ 4 本（κ = 0.5523）と SVG の楕円の違いで、`spec-4-3` 事前調査 E で見た性質と
  同じ。塗り付き楕円 100% でも、差が 32 を超える画素は箱の 1.6%。
- **線が箱より太いと、何も描かれない**（30pt 角に 40pt。画面も pdf.js も白のまま）。線の中心を線幅の半分だけ内へ寄せる今の規則で
  箱がつぶれるためで、今も 8pt の線で 8pt より小さな箱を描けば同じことが起きる。

今の `settings.json` の値（候補の色、太さ 1・2・3・5・8、不透明度 1・0.75・0.5・0.25）は、新しい検証（色は `#rrggbb`、太さは

### H. 雲形・`/RD`・破線 — 雲は弧の式を慣習に合わせて自前で描き、破線は保存と同じ点列で描けば画面と一致する

規格（ISO 32000-1 の表 167〔PDF 2.0 では表 169〕と表 180）、他のツールの描き方（PDFBox の雲形。Apache-2.0）、pdf.js の扱いを確かめた。
そのうえで雲形と破線の試作を scratchpad で作り、pdf.js で描いた画素と、同じ点列で描いた画面（SVG）・印刷（canvas）の画素を
倍率 2 で比べた。

**規格と pdf.js**

- `/BE` の `/S` は `/S`（効果なし。既定）か `/C`（雲形）。`/C` でも `/BS` の太さと破線は守ると書かれている。強さ `/I` は 0〜2 で既定は 0、
  `/S /C` のときだけ意味を持つ。`/BE` は四角・丸・多角形・テキストに付く。
- `/RD` は `/Rect` と「実際の四角・丸」との差を表す 4 つの数で、規格の文は **左・上・右・下** の順。どれも 0 以上で、左右の和は幅より、
  上下の和は高さより小さい。雲形のように効果で `/Rect` が広がるときに使う。PDFBox は、読むときは規格の順だが、雲形の `/RD` を書くときは
  左・下・右・上 の順で組んでおり、実装の間で揃っていない。
- pdf.js は `/BE` も `/RD` も読まない（外観の無い雲形は普通の四角で描く）。破線は `/BS /D` と古い形の `/Border` の 4 つ目を
  `borderStyle.dashArray` にまとめて返す。無ければ `[3]` で、負の数が混ざるかすべて 0 の配列なら線幅を 0 にする。

**他のツールの描き方（PDFBox の雲形）**

- 弧の半径は 強さ × 4 ＋ 線幅 / 2（丸は 強さ × 4.75 ＋ 線幅 / 2）。弧の中心は輪郭の上に 2r·cos 34° 以下の間隔で並べ、隣の円と 34° で交わる。
- 各弧は、前の弧との外側の交点から次の弧との交点まで外へふくらみ、頭を前の弧の内側へ 22° 延ばす（しっぽ）。弧は 90° 以下に割ってベジェにする。
- 四角は輪郭の上に中心を並べ、描いたあとで弧の外接に線幅の半分を足した箱を `/Rect` と `/BBox` にして、`/RD` を取り直す。丸は楕円を
  折れ線にして周りを歩き、弧を置く。破線と雲形は同時に選べない前提で、雲形には破線を当てない。

SigK PDF は、この式（慣習の値）だけを借りて自前で書く。コードは写さない。

**試作と画素の比較**

試作では弧の中心を箱の内側に置き（確定事項33。雲を箱の内側に収める）、次の検体を比べた。

| 検体 | 差が 32 を超える画素（箱の面積に対する割合） |
|---|---|
| 四角（強さ 1・2、線 2・8・12pt、塗りと不透明度 50%、線なし） | 0.01〜0.11% |
| 丸（強さ 1・2、線 1・2pt、塗り） | 0.00〜0.04% |
| 12pt 角・10pt の丸・高さ 3pt の細い箱 | 0.00〜1.39% |
| 90° 回したページ（線 2・40pt、塗りと不透明度 50%） | 0.00〜0.20% |

- 差は、弧のいちばん外側と、しっぽで線が折り返す継ぎ目の 1 画素ずつ（縁のにじみの違い）で、形のずれは無い。印刷（canvas）も同じ程度。
- 破線は、四角と直線が画面・印刷とも pdf.js と全画素一致（差 0）。楕円は縁の 2 画素、矢印は矢じりの縁の 13 画素が差 32 を超え、印刷は差 0。
  **ただし始点と向きをそろえたときの話である。**画面の `<rect>`（左上から時計回り）と `<ellipse>`（右端から時計回り）は、保存の外観
  （左下から反時計回り・右端から反時計回り）と始点や向きが違い、切れ目の位置がずれる。画面も保存と同じ点列の `<path>` で描く（確定事項41）。
- 雲形の点列を作る時間は、A4 いっぱいの四角で 0.19ms（ベジェ 1,092 本）、200×100pt で 0.026ms で、ドラッグ中に描き直してよい。
  高さ 1pt の細い箱では弧の半径が縮んでベジェが 8,680 本になり 1.1ms かかった。半径が 1pt を切るほど小さな箱は雲形をやめる（確定事項33）。

**見た目の候補**

雲形は、強さ 1・2 としっぽの有無の 4 通りを見比べた（`screenshots/phase4b-1b-cloud-choices.png`）。強さ 1・しっぽありを推し、ユーザーが
選んだ（決定47 ⑮）。破線の間隔は、線の太さの 3:2・2:2・3:3・4:2 倍を 1・2・4pt で見比べ（`screenshots/phase4b-1b-dash-ratios.png`）、
普通の破線に見える 3:2 にした（起草者の判断）。どの候補も、太い線の小さな四角では角が欠けることがある。path に沿って続けて引くためで、
他の作図ソフトと同じ性質である。

**読み込んだものの持ち回り**

- 破線は、pdf.js の `dashArray` を線の太さで割った倍数で持てば、開いたときに元と同じ間隔で出て、太さを変えると SigK PDF の破線と同じく
  伸び縮みする（確定事項37）。
- 他のアプリの雲形の外観は、必ず `/Rect` の中に描かれる。`/Rect` を外形の箱にして SigK PDF の描き方で描き直せば、外形・強さ・太さは元と
  同じになり、弧の位置と数だけが少し違って見える。直すまで元の絵を見せる案もあるが、ページの描き直しの仕組みを足すことになる。推しは
  描き直す案にし、ユーザーが選んだ（決定47 ⑯）。
- ①-a の読み口は雲形かどうか（`cloudy`）だけを返し、強さ `/I` を返していない。①-b で足す（確定事項38）。

## 確定事項（〔H〕の印は事前調査 H で決めたところ）

### A. 右パネル（モック `screenshots/phase4b-style.png`・`-selected.png`・`-palette.png`・`-text.png`）

1. 行の並び: 種類 → 色 → 塗り → 線種 → 線の太さ・文字の大きさ → 不透明度 → 本文 → 作成者 → ページ → 対象の文字 → ヒント。色の行の
   見出しは、図形・ペンが「線の色」、テキストが「文字の色」、それ以外が「色」。
2. 色の行: 今の色を示すチップ（幅 44px の色見本と ▼）を 1 つ置き、右に値（`#RRGGBB`）か「なし」を添える。押すとパレットが開く
   （決定47 モック。CheckListMaker と同じ）。今の候補の丸は外す。
3. 「塗り」の行は四角・丸だけに出す（選んでいる書き込みか、四角・丸の道具を持っているとき）。チップの形は色の行と同じで、「なし」は
   白地に赤の斜線で示す。既定は「なし」。
4. 線なし: 四角・丸の「線の色」のパレットの下の段に「線なし」を置く。線と塗りは両方「なし」にできない（片方が「なし」のとき、もう片方の
   「なし」は押せない）。四角・丸のヒントに「線と塗りを両方「なし」にはできません。」を足し、塗りがあるときは「塗りは下の文字を隠すだけで、
   文字は検索やコピーで取り出せます。」を添える（論点5）。
5. 「線種」の行: 四角・丸は 実線・破線・雲形、直線・矢印は 実線・破線 のボタン（40×30。絵はインライン SVG）。ペン・テキスト・ノート・
   ハイライト・下線・取り消し線には出さない。既定は実線。
6. パレット（モック `-palette.png`）: チップを押すと、右パネルの左、紙の上に重ねて開く。幅 268px、左端は右パネルの左端から 276px 左、
   上端は行の上端の 40px 上（90px より上には出さず、窓の下にはみ出すなら上へずらす）。中身は 見出し（行の名前）→「テーマの色」→
   テーマの色 10 → 濃淡 5 段（10 列）→「標準の色」→ 標準の色 10 → 下の段［なし］［その他の色…］。［なし］は塗りと、四角・丸の線の色
   だけに出す（押せないときは薄く）。今の色に印を付ける。外を押す・Esc・色を選ぶ、のどれでも閉じる。［その他の色…］は OS の色の選択
   （隠した `<input type="color">`）を開き、選んだ色を当てて閉じる。
7. 線の太さと不透明度（モック）: スライダー＋数値欄＋単位（pt・%）。太さは 1〜40、不透明度は 10〜100 の整数で、スライダーも 1 刻み。
   数値欄は Enter か欄の外で確定し、範囲の外は端へ、小数は四捨五入する（0 → 1、41 → 40、35.4 → 35）。読み込んだ小数の太さ（1.5pt
   など）はそのまま見せ、動かすと整数になる。
8. 下見と確定: 書き込みを選んでいてスライダーを動かしている間（input）は、その書き込みを下見の値で描き直す（履歴に積まない）。離したとき
   （change）と数値欄の確定で 1 世代積む。何も選んでいなければ下見は無く、「次に付ける値」として覚えるだけ。下見の途中で Esc・選択の
   変更・別の欄の操作があれば下見を捨てる。
9. 表示のみの書き込みには、色・塗り・線種・太さ・不透明度の行を出さない（今のまま）。

### D. 書き込みの持ち方（`renderer/annotation-entry.js`）

16. `color` は `#rrggbb`（小文字）。四角・丸に限り `null`（線なし）を許し、そのときは `fill` が要る。
17. `fill`（新）は四角・丸だけが持つ。`#rrggbb` か `null` で、無いものは `null` として扱う。
18. `lineStyle`（新）は、四角・丸が `'solid'`・`'dashed'`・`'cloudy'`、直線・矢印が `'solid'`・`'dashed'`。無いものは `'solid'`。
    〔H〕読み込んだ破線の間隔は `dash`（線の太さに対する倍数の配列。確定事項37）に、雲形の強さは `cloudIntensity`（0 より大きく 2 以下）に
    持つ。SigK PDF で描いた破線は `dash` を持たず（既定の 3:2）、雲形の `cloudIntensity` は 1（決定47 ⑮）。`dash` は `'dashed'` のときだけ、
    `cloudIntensity` は `'cloudy'` のときだけ持つ。線種を替えると `dash` を捨て、雲形にしたときの強さは 1 にする。`/RD` は持たない
    （読み込むときに箱へ織り込む。確定事項38）。
19. `lineWidth` は正の数。画面から入るのは 1〜40 の整数。線なしでも持つ（線を戻したときの太さ）。
20. `opacity` は 0 より大きく 1 以下。画面から入るのは 0.1〜1（小数 2 桁）。
21. `validEntry`・`copyEntry`・`sameEntry`・`PATCH_FIELDS`（`fill`・`lineStyle` を足す。`dash`・`cloudIntensity` は右パネルから変えないので
    足さない）・`validPatchValue`・`toSaveEntry` を広げる。`dash` は 1〜8 個の数で、どれも 0 以上 100 以下、和が 0.1 以上。
    `annotation-state.js` の `updateAnnot` は、変えた後の形を `validEntry` で確かめ、崩れるなら何もしない（線なしのまま塗りを
    なしにする、など）。

### F. 保存（ワーカー）

29. 四角・丸: 線があれば線幅の半分だけ内側の path に線を引き、塗りがあれば同じ path を塗る（`B`・`f`・`S`）。線なしなら箱そのものを
    塗る（`f`）。
30. 太い線: 描く線幅は、四角・丸の短い辺の半分で頭打ちにする（そのとき線が箱をすべて覆う）。`/BS /W` には選んだ太さを書き、開き直すと
    選んだ太さに戻る。画面と印刷も同じ式で描く（`shape-geometry.js` と `worker/shape-appearance.js` の一致をテストで見張る）。
31. 不透明度が 1 未満の図形・ペンは、外観を透明グループで包む。外観の中身は `q /GS gs /G0 Do Q` で、`G0` は
    `/Group << /S /Transparency >>` の Form にして中は不透明で描く。塗りと線、矢印の軸と矢じり、ペンの線どうしが重なっても濃くならない
    （事前調査 D）。1 のときは今のまま。テキスト・ノート・マークアップも今のまま。
32. 破線: `/BS << /W 線幅 /S /D /D [3w 2w] >>` と、外観の `[3w 2w] 0 d`（w は選んだ太さ。間隔は 1 種類で、線の太さに比例させる。
    決定47）。〔H〕倍数は 3:2 にする（事前調査 H。`screenshots/phase4b-1b-dash-ratios.png`）。読み込んだ間隔を持つもの（`dash`）は
    `dash` × w を書く。端は切りっぱなし（`0 J`。実線の直線・矢印の丸い端とは替える）。path は、四角が `re` と同じく左下から反時計回り、丸が
    右端から反時計回りのベジェ 4 本、直線・矢印が始点から終点で、画面・印刷も同じ始点と向きで描く（確定事項41）。矢印の矢じりは破線に
    しない（実線・丸い端と角）。破線は path に沿って続けて引き、角合わせはしない（太い線の小さな四角では角が欠けることがある。事前調査 H）。
33. 〔H〕雲形（四角・丸）: 雲は箱の内側に収める（線を箱の内側に収める今の四角・丸と同じ。選択の枠と当たり判定も箱のまま）。
    - 描く線幅 dw は、短い辺の半分で頭打ちにする（確定事項30 と同じ）。
    - 弧の半径 r = 強さ × 4 ＋ dw / 2（丸は 強さ × 4.75 ＋ dw / 2）。ただし (短い辺 − dw) / 4 を超えない（小さな箱で中心の輪郭がつぶれない
      ように）。r が 1pt を切るときは雲形をやめ、普通の四角・丸として描く（`/BE` は書く）。
    - 余白 m = r ＋ dw / 2。弧の中心は、箱を m だけ内へ寄せた輪郭（四角は辺、丸は内接する楕円）に並べる。四角は左下の角から反時計回りに、
      角に必ず中心を置き、各辺を 2r·cos 34° 以下の等しい間隔に割る。丸は右端から反時計回りに、周の長さを 2r·cos 34° 以下で等しく割り、
      数は偶数で 4 以上（上下左右に対称）。
    - 各弧は、前の中心との外側の交点から次の中心との外側の交点まで、外へふくらむ向きに引く。頭は前の弧の内側へ 22° 延ばしてから戻る
      （しっぽ。決定47 ⑮）。弧は 90° 以下に割ってベジェにし、制御点は半径 × 4/3 × tan(角 / 4)。線の角は丸（`1 j`）。
    - 塗りは同じ path を塗る（しっぽは面積を持たない）。線なしの雲形は、雲の形の塗りになる。
    - 外観の `/BBox` と `/Rect` は箱そのもの。`/RD [m m m m]`（4 つとも同じ値にして、左・上・右・下と左・下・右・上のどちらの順で読まれても
      同じ意味にする）、`/BE << /S /C /I 1 >>`（読み込んだ強さを持つものはその強さ）、`/BS << /W 線幅 /S /S >>`。
    - 同じ式を画面（`renderer/cloud-geometry.js`）とワーカー（`worker/cloud-appearance.js`）に持ち、同じ入力で同じ点列になることを
      テストで見張る（矢じりと同じ扱い。プロセスが違うので読み込み合わない）。
34. 辞書: `/C` は線があるときだけ、`/IC` は塗りがあるときだけ書く。`/BS << /W 線幅 /S /S >>`（線なしは `/W 0`。破線は確定事項32）、
    `/Border [0 0 線幅]`（線なしは `[0 0 0]`。破線でも間隔は書かない。`/BS` があれば `/Border` は使われない）、`/CA`。雲形は `/BE` と
    `/RD` を足す（確定事項33）。
    **2026-09-30 実装で改めた**: 線なしでも `/BS /W` と `/Border` には選んだ太さを書き、`/C` を書かないことで線なしを表す。`/W 0` にすると、
    開き直したときに「線を戻したときの太さ」（確定事項19）が失われ、雲形の弧の並び（線幅で決まる）も変わるため。`/C` の無い枠は規格でも
    透明で、読み込みの側も `/C` が無い四角・丸を線なしとして読む（確定事項36）。
35. 保存の形: 四角・丸は `{ src, kind, color | null, fill | null, lineStyle, opacity, rect, lineWidth }`、直線・矢印は `lineStyle` を足す。
    〔H〕破線で `dash` を持つものは `dash` を、雲形は `cloudIntensity` を足す。

### G. 読み戻し（①-a の口の答えの当て方を広げる）

36. `interior` → `fill`（四角・丸）。`/C` が無いか空、または線幅 0 の四角・丸は、塗りがあれば `color: null`（線なし）にする。塗りも線も
    無いものは表示のみのまま。
37. 破線: pdf.js の `borderStyle.style` が破線（2）の四角・丸・直線・矢印は `lineStyle: 'dashed'`。〔H〕間隔は `borderStyle.dashArray`
    （`/BS /D` と `/Border` の 4 つ目をまとめたもの）を線の太さ（`rawWidth` を使う太さ。①-a 確定事項24）で割った倍数を `dash` に持ち、
    3:2 と同じ（差 0.01 以内）なら持たない。これで開いたときに元と同じ間隔で出て、太さを変えると SigK PDF の破線と同じく伸び縮みする。
    配列が空のものは実線として扱う。倍数が確定事項21 の範囲の外のものと、破線の雲形（`/BE /S /C` で `/S /D`）は表示のみ。
38. 〔H〕雲形と `/RD`（四角・丸）:
    - 口の答えに `cloudIntensity`（`/BE /I`。無ければ 0）を足す（`worker/annotation-dict-reader.js`）。
    - `/BE /S /C` で強さが 0 より大きいものは `lineStyle: 'cloudy'`、`cloudIntensity` は強さ（2 を超えれば 2）。箱は `/Rect` のままにする
      （他のアプリの外観も `/Rect` の中に描かれるので、外形が元と同じになる）。弧は SigK PDF の描き方で描き直し、外形・強さ・太さ・色は
      元のまま、弧の位置と数は元の絵と少し違って見える（決定47 ⑯）。ファイルの中身は、その書き込みを直して保存するまで元のまま。
    - `/BE /S /C` でも強さが 0 か無いものは、雲形でないものとして扱う（規格の既定は 0 で、効果が無い）。
    - 雲形でない四角・丸に 0 でない `/RD` があれば、`/Rect` から `/RD`（規格の順で 左・上・右・下）を引いた箱を使い、線はその内側に描く
      （PDFBox も同じ解釈）。直して保存するときは `/RD` を書かない（線は箱の内側なので見た目は変わらない）。
    - `/RD` が 4 つの数でないもの、負の数があるもの、左右の和が幅以上か上下の和が高さ以上のものは表示のみ。雲形の `/RD` も同じ条件で
      確かめる（位置には使わない）。
39. 灰（1 成分）と CMYK（4 成分）の色は RGB に直す（灰は同じ値、CMYK は 1 − min(1, c + k) などの素朴な式）。

### H. 印刷

40. 印刷の描き手（`shape-graphics.paint`）は、不透明度が 1 未満のとき、別の canvas に不透明で描いてから alpha で重ねる（確定事項31 と
    同じ見え方。事前調査 D）。塗り・線なし・破線・雲形も描く（破線と雲形は確定事項41 の点列で）。

### I. 画面の描き方（事前調査 H）

41. 〔H〕破線と雲形の図形は、画面も印刷も、保存の外観と同じ紙の座標の点列（確定事項32・33）を viewport で表示の座標へ直した path

## 起草者の判断で決めたもの

- 線と塗りの「なし」はパレットの下の段に置き、チップでは白地に赤の斜線で示す（モック）。
- 既定の色の対応は色差でいちばん近いパレットの色にした（確定事項14・15）。桃は近い色が無いのでそのまま。
- 移し替えは 1 回だけにし、済んだ印を設定に書く（その後に自分で同じ値を選んでも、置き換えない）。
- 線幅の頭打ち（確定事項30）と、透明グループを不透明度 1 未満に限ること（確定事項31）。
- パレットの色の読み上げ名は値（`#RRGGBB`）にする。
- スライダーの刻みは 1（数値欄と同じにして、つまみの位置と数字が食い違わないように）。
- 〔H〕破線の間隔は線の太さの 3:2 倍（見比べて、普通の破線に見えるもの）。端は切りっぱなしにし、矢印の矢じりは破線にしない。角合わせは
  入れない（画面と保存をそろえる手間に見合わない。他の作図ソフトも角は合わせない）。
- 〔H〕雲は箱の内側に収める（今の四角・丸と同じく、ドラッグした箱が外形になる。選択の枠・当たり判定・`/Rect` を今のまま使える）。
- 〔H〕雲形の弧の式は慣習の値（PDFBox と同じ）を借り、コードは自前で書く。小さな箱では弧を縮め、半径が 1pt を切るなら雲形をやめる。
- 〔H〕`/RD` は 4 つとも同じ値で書く（左・上・右・下の順と、左・下・右・上の順のどちらで読まれても同じ意味になる）。
- 〔H〕読み込んだ破線は、間隔を線の太さの倍数で持つ（開いたときは元のまま、太さを変えると伸び縮み）。雲形の破線は表示のみ。
- 〔H〕線種を替えたら、読み込んだ間隔と強さは捨てる（雲形に戻すと強さ 1）。

### 既知の限界

- 口が答えないとき（100MB を超える文書・上限時間・読めない文書）、`/C` のある塗った四角は pdf.js の値のまま直せる形になる。塗りが
  分からないので、直すと塗りが落ちる（①-a 確定事項27 のまま）。線も塗りも無い形になるもの（`/C` の無い四角）は表示のみにそろえる。
