## 目的

編集の道具の段に「モザイク」を足し、紙の上を引いて囲んだ範囲を、下にある内容ごと消せるようにする。

引いた範囲は、その場でブロックの平均色で塗った下見になり、保存するまでは元に戻せる。保存するときに確認を出し、モザイクのあるページを丸ごと
画像 1 枚に置き換える（決定64 ⑤）。そのページの文字・絵の元の中身はファイルから消え、書き込み（注釈）は書き込みのまま残る（決定64 ⑥）。
見た目を塗るだけで中身を残す作りにはしない。古い中身・控えのファイル・構造ツリーなど、元の文字が残る所をすべて消す。

## 含めるもの / 含めないもの

| 含めるもの | 含めないもの（理由） |
|---|---|
| 道具の段の「モザイク」（ノートの後ろの区切りの中、トリミングの前）、アイコン・カーソル・ヒント | 文字を残したまま範囲の中の文字だけを消す墨消し（第 2 版。`docs/01` L160） |
| 引いて囲む破線の四角、離したら置く（1 世代）、粗さ 3 段、［このページのモザイクを外す］ | 置いたモザイクを 1 つずつ選んで動かす・大きさを変える・消すこと（Ctrl+Z と［このページのモザイクを外す］で足りる） |
| 下見（表示・サムネイル・印刷）。範囲に重なる行の文字を選択・検索・コピーの対象から外す | 差し込んだ未保存のページへのモザイク（注釈の道具・トリミングと同じく効かない。帯で断る） |
| 保存の確認、ページを画像 1 枚に置き換える、辿れない古い中身・構造ツリーの要素・ページの縮小画像などを消す、控え（.bak）を作らない・前の控えを消す | モザイクの無い保存で辿れない古い中身を消すこと（ページの削除で残る中身。今の保存の振る舞いを変えない。既知の限界） |

| 起動確認・保存したファイルに元の文字が無いことの確かめ | 他のビューアでの目視（Phase 5 塊③） |

## 事前調査（2026-10-06・Windows 11 実機・Electron 44・pdf.js 6.3.289・pdf-lib 1.17.1）

⑥-a のセッションの事前調査 A〜G（`docs/spec-4b-6a-trim.md`）に続けて H〜L を調べた。試作は `~/.claude/plans/phase-4b-6b-probe/`（`probe-i.js`・
`make-jp.js`・`probe.html`・`mock/scenes-6b.js`・`NOTES.md`）。

### E（⑥-a のセッション）の要点

- ページの中身を差し替えて保存しただけでは、古い中身（文字を描く流れ）がファイルに残る。trailer の Root・Info から辿れない間接オブジェクトを
  `context.delete` で消すと消える。上書き保存は毎回 `.bak`（元のファイルの写し）を作る。描くのはレンダラー（ワーカーに canvas が無い）。

### H. 保存の画像の細かさと形式

- 和文の A4（Noto Sans JP の 18pt・10.5pt・9pt の行）を pdf.js で描いて比べた。9pt の行を画面で 200%・400% に拡大すると、150dpi は 200% から輪郭が
  ぼやけ、200dpi は 400% で少しぼやけ、300dpi は 400% でもくっきり読める（`screenshots/phase4b-6b-dpi.png`）。
- 大きさ（pdf-lib で 1 ページの PDF に埋め込んだあと）: 和文のページは 300dpi の PNG が 133KB・JPEG（品質 0.9）が 214KB、英文の詰まったページは
  PNG 240KB・JPEG 415KB、写真の検体のページは PNG 286KB・JPEG 780KB。**pdf-lib は PNG を展開して流れに詰め直すので、埋め込んだ PNG は元の PNG の
  ファイルより小さくなる**（文字のページで 0.4〜0.6 倍）。不透明な PNG は透明度（SMask）を付けずに埋め込まれる（`png.js` は 255 未満の値があるときだけ付ける）。
- 本物の写真が全面に入ったページは PNG が JPEG の数倍になる（PNG は可逆のため）。→ PNG の大きさが JPEG の 2 倍以下なら PNG、超えるなら JPEG にする（確定事項 D18）。
- 1 ページの描画と塗りは 50ms 以内（A4・300dpi）。PNG・JPEG への変換は 1 ページ 0.1〜0.3 秒（spec-3-3 の実測）。

### I. 古い中身を消す範囲

検体（1 ページ目に消したい文字、2 ページ目に残す文字。2 ページで共有のフォント・画像・フォーム XObject、1 ページ目だけのフォーム XObject、ページの
`/Thumb`・`/PieceInfo`・`/Metadata`、構造ツリーの `/ActualText`・`/Alt`、外観つきの FreeText）の 1 ページ目を画像に差し替え、保存したバイト列の流れを
全部ほどいて文字列を数えた（`probe-i.js`）。

| 当てたもの | 本文 | 1 ページ目だけのフォーム | 縮小画像・私的なデータ・ページの XMP | 構造ツリーの ActualText・Alt |
|---|---|---|---|---|
| 差し替えだけ | 残る | 残る | 残る | 残る |
| ＋辿れない間接オブジェクトを消す | 消える | 消える | 残る | 残る |
| ＋ページの `/Thumb`・`/PieceInfo`・`/Metadata`・`/StructParents` を外す | 消える | 消える | 消える | 残る |
| ＋構造ツリーからそのページの要素を外す | 消える | 消える | 消える | 消える |

3 つを全部当てても、2 ページ目の文字・共有のフォーム・2 ページ目の構造の ActualText・書き込みの外観は残った。→ 3 つとも当てる（確定事項 D19〜21）。

### J. 画像のバイト列をワーカーへ渡す口

- レンダラー → main（`ipcRenderer.invoke`）→ ワーカー（`utilityProcess` の `postMessage`）のどこでも JSON にせず、構造化複製で渡している
  （`preload.js` の `taskAPI.run`・`main.js` の `task:run`・`task-runner.js`）。spec に `Uint8Array` を入れれば通る見込み。起動確認で実物を流して確かめる。

### K. 範囲の中の文字の層と検索

- pdf.js の `getTextContent` の項目は、ふつう 1 行が 1 つ。範囲に重なる項目の文字を空（`''`）にして `TextLayer` に渡すと、span の数は項目の数と同じ
  （33 対 33）のまま、残した span の位置も変わらなかった。→ 項目を消さずに文字だけ空にする（検索のハイライトとマーカーの四角が、項目と span の
  1 対 1 に頼っているため）。重なった行は、範囲の外の部分も選べなくなる（決定66 ③。既知の限界）。

### L. 表示のみの書き込みの下見

- 編集できる書き込みはアプリの層が描くが、表示のみの書き込み（記入済みのフォーム欄・スタンプなど）は pdf.js が canvas に描く。描いた canvas を
  そのまま塗ると、表示のみの書き込みも塗られて隠れて見える。保存したあとはその書き込みが上に残るので、**「隠れた」と思ったものが保存後に見える**。
- 書き込みを描かない絵（`annotationMode: DISABLE`）をもう 1 枚描き、2 枚の画素が違う所（＝pdf.js が描いた書き込み）は塗らずに残すと、書き込みが
  モザイクの上に見え、保存後の見え方と一致した（`screenshots/phase4b-6b-annot-over.png`）。手間はモザイクのあるページだけ 2 回描くこと。

`screenshots/phase4b-6-mosaic-preview.png`（引いている破線と下見）・`-mosaic-coarse.png`（粗さ 3 段）・`-mosaic-confirm.png`（上書き保存の確認）は

## 確定事項

### A. 持ち方（`renderer/page-plan.js`・新 `renderer/page-mosaic.js`）

1. plan の元ファイルのページの要素 `{ src, rotate }` に、モザイクの並び `mosaic: [{ box: [x1, y1, x2, y2], block }]` を足せる。`box` は紙の座標
   （回す前・pt。x1 < x2・y1 < y2・小数 2 桁）、`block` はブロックの一辺（pt。4・8・14 のどれか）。置いた順に並べる。**欄が無ければモザイク無し**。
   空の配列にはしない（外したら欄を消す）。差し込んだページ（`{ insert }`）には付けない。
2. `copyPage`・`clonePlan` は `mosaic` を写す（配列と箱は新しく作る）。回転・並べ替え・削除でページに付いて回る。`samePlan` は `mosaic` も
   並び順まで比べる。`isDirty` は `mosaic` があれば変更ありとする。page-plan.js は `crop` と `mosaic` を「元ファイルのページに付く欄」の表で
   まとめて写し・比べる（起草者の判断）。
3. 純関数は `renderer/page-mosaic.js` に置く: 粗さ 3 段（細かい 4pt・ふつう 8pt・粗い 14pt。既定ふつう）、置いた写し・外した写し・数、
   範囲のブロックの割り方（範囲の左上〔x1, y2〕から block ごと。右と下の端は半端なブロック）。
4. 範囲は、引いたページの今の見える範囲（`crop` があればその中）に収める。収めて幅か高さが 0 なら置かない。

### B. 下見（新 `renderer/mosaic-paint.js`・`renderer/mosaic-text.js`）

5. `paint(ctx, viewport, mosaic, { base })`: 範囲ごとに、確定事項 3 のブロックを viewport の画素の四角にし（端は四捨五入）、ブロックごとに
   `base` の画素（無ければ `ctx` 自身）の平均色で塗る。**ブロックの区切りは紙の座標で決める**ので、倍率・回転・保存の画像（300dpi）でも同じ所で区切る。
6. `base` を渡したときは、`ctx` と `base` で色が違う画素（pdf.js が描いた表示のみの書き込み）は塗らずに残す（事前調査 L）。
7. 表示（`page-render.js` の `drawCanvas`）・サムネイル（`thumbnails.js`）・印刷（`page-image.js` の `renderToCanvas` に `mosaic`）は、モザイクのある
   ページだけ、書き込みを描かない絵（`annotationMode: DISABLE`）をもう 1 枚描いて `base` にし、描き終えた canvas に `paint` を当てる。
   canvas が無い環境（jsdom）では何もしない。
8. 重なりは、紙の絵 → モザイク → 書き込み（アプリの層・pdf.js が描いた表示のみの書き込み）の順。保存したあとの見え方と同じ（決定64 ⑥）。
9. **文字の層と検索**（決定66 ③）: `blankItems(items, mosaic)` は、範囲に重なる項目（pdf.js の `getTextContent` の 1 項目。ふつう 1 行）の文字を
   空にした写しを返す（項目は消さない。事前調査 K）。重なりは項目の `transform` と幅・高さから求めた四角で見る。文字の層（`text-layer.js`。選択と
   コピー）と検索（`find.js`）が通す。plan が変わると、今の作りどおり文字の層と検索の写しが作り直される（`viewer.applyPlan`）。

### C. 道具（新 `renderer/annotate-mosaic.js`・`mosaic-props.js`。見本 `phase4b-6-mosaic-preview.png`・`phase4b-6b-mosaic-remove.png`）

10. 道具の段のノートの後ろの区切りの中、トリミングの前に「モザイク」を置く（`index.html`。アイコンは角の丸い四角 4 つ〔`assets/icons.js` の
    `mosaic`〕）。描かない道具（`annotate-tools.js` の `POINTER_TOOLS`）に足す。段に入りきらなければ「その他」に入る（1024px でノート・モザイク・
    トリミング、944px で消しゴム・ノート・モザイク・トリミング。⑥-a の事前調査 F）。
11. モザイクを持って紙の上を左ボタンで引くと、アクセント色の破線の四角（1.5px・`6 4`・薄い塗り）で範囲を見せる（3px を超えて動かしてから）。四角は
    そのページの今の見える範囲の中に収める。**離したら、その範囲にモザイクを置く**（1 世代。今の粗さ）。四角を残して整える段は無い（CheckListMaker
    と同じ）。書き込みは選ばず掴まない。カーソルは紙の上で十字。
12. Esc・道具やモードを替える・左＋右・取り消しとやり直しの前・保存と印刷の前・窓のフォーカスが外れたときは、引いている途中をやめる（置かない）。
    倍率が変わったら、引いている途中をやめる。
13. 差し込んだ未保存のページで引いたら、四角を出さずに帯（黄）「差し込んだページは、保存してからモザイクを入れてください。」を出す。
14. 右パネル（道具を持っている間）: 種類「モザイク」、粗さ［細かい］［ふつう］［粗い］（選んだ粗さを覚える。設定 `annotMosaicBlock`）、今のページ
    （ページ番号の欄のページ）の「モザイク ○ か所（まだ保存していません）」か「モザイクはありません」、［このページのモザイクを外す］（無ければ押せない）、
    ヒント「紙の上を引いて、隠す範囲を囲んでください。保存するまでは元に戻せます。保存すると、モザイクを入れたページは丸ごと画像に置き換わり、
    そのページの文字は検索・選択・コピーできなくなります。」。ほかの行と［削除］は隠す。書き込みを選んだら、その書き込みの右パネルに任せる（⑥-a と同じ）。
15. 粗さを替えても、置いたモザイクは変わらない（次に置くものから）。
16. ［このページのモザイクを外す］（決定66 ④）: 今のページの `mosaic` を消す。1 世代（Ctrl+Z で戻せる）。

### D. 保存（新 `renderer/mosaic-save.js`・`confirm-mosaic.js`・`worker/op-mosaic.js`・`worker/orphan-objects.js`）

18. 上書き保存・名前を付けて保存（閉じるときの［保存］も上書き保存を通る）で、plan にモザイクがあれば、ワーカーへ渡す前に確認を出す
    （`confirm-mosaic.js`。見本 `phase4b-6-mosaic-confirm.png`・`phase4b-6b-mosaic-saveas.png`）。題「モザイクを入れて保存しますか」、
    ［キャンセル］［置き換えて保存］（危険色。既定のフォーカスはキャンセル）。
    - 上書き: 「モザイクを入れた ○ ページ（1・3 ページ目）を、丸ごと画像に置き換えて「<名前>」に上書き保存します。」「そのページの文字は検索・選択・
      コピーできなくなり、モザイクの下の内容は元に戻せません。書き込みは書き込みのまま残ります。」「元の内容が残らないよう、このときは控えのファイル
      （.bak）を作りません。前に作った控えがあれば消します。」
    - 名前を付けて保存: 「…丸ごと画像に置き換えて「<名前>」に保存します。元のファイル「<元の名前>」は変わりません。」「保存したファイルでは、そのページの
      文字は検索・選択・コピーできず、モザイクの下の内容は元に戻せません。書き込みは書き込みのまま残ります。」
    - ページ番号は今の並びの番号。4 ページを超えたら「1・3・5・7 ページ目ほか」とする。
    - キャンセルなら何も書かず、帯（青）「保存を取りやめました。」。下見はそのまま残る。
19. **画像にする**（決定66 ①）: 確認のあと、モザイクのあるページを順に、紙全体（MediaBox。`page-boxes.js` で読む。読めなければ `page.view`）・
    回転 0・書き込みを描かずに **300dpi** で描き、確定事項 5 で塗る（`base` は要らない）。1 ページが 4,000 万画素を超えるなら、収まる細かさまで下げる
    （A1 の 300dpi は約 6,960 万画素）。PNG と JPEG（品質 0.9）にして、**PNG が JPEG の 2 倍以下なら PNG、超えるなら JPEG**（事前調査 H）。
    描く間は帯「モザイクのページを画像にしています（n / N ページ）」と［中止］（`save.runLocal` の枠）。中止なら何も書かない。
20. spec に `mosaics: [{ src, kind, bytes, box }]`（`box` は描いた紙全体）を足してワーカーへ渡す。ワーカーは `applyPlan` の前（`src` が元の番号のうち）に、
    そのページの `/Contents` を「`box` に画像 1 枚を置く」流れ 1 本に、`/Resources` をその画像だけに差し替える。`/Annots`・`/Rotate`・`/MediaBox`・
    `/CropBox`・`/UserUnit` はそのまま（書き込み・回転・トリミングは変わらない）。
21. 同じページの `/Thumb`・`/PieceInfo`・`/Metadata`・`/StructParents` を外し、構造ツリーから、そのページの要素（`/Pg` がそのページで、子に
    ほかのページの要素を持たないもの）と、そのページを指す内容の参照（MCR）を外し、`/ParentTree` のそのページの項を消す。そのページを指しつつ
    ほかのページの子を持つ要素は、`/ActualText`・`/Alt`・`/E` だけを外して残す（事前調査 I）。
22. モザイクのある保存では、書き出す直前に、trailer の Root・Info から辿れない間接オブジェクトを消す（`orphan-objects.js`。事前調査 E・I）。
23. **控え**（決定64 ⑧）: モザイクのある上書き保存では `.bak` を作らず（`makeBackup: false`）、書き込みが成功したら前からある `.bak` を消す
    （`pdf-write.js` の `writeDocument` に `dropBackup`）。消せなかったら、保存は成功のまま帯（黄）「控えのファイル（.bak）を消せませんでした。元の内容が
    残っているので、手で消してください。」を出す。名前を付けて保存では元のファイルにも控えにも触れない。
24. 保存したあとは今の作りどおり保存先を開き直す。モザイクのページは画像 1 枚になり、plan の `mosaic` は無くなる（Ctrl+Z では戻らない）。
25. **抽出**（決定66 ②）: 選んだページにモザイクがあれば、抽出の確認に「モザイクを入れた ○ ページは、画像に置き換えて書き出します。」を足し、

## 起草者の判断で決めたもの

- 持ち方は plan の要素の欄（`mosaic`）にした。トリミングと同じく「いまの状態」で、元に戻す・やり直す・未保存の判定・タブの退避がそのまま効くため。
  page-plan.js は `crop` と `mosaic` を 1 つの表で写し・比べる（欄が増えるたびに 3 か所を直さずに済む）。
- ブロックの区切りは紙の座標（範囲の左上から block pt ごと）で決める。倍率・回転・保存の 300dpi の画像で、区切りが同じ所に来るため。
- 引いて離したら置く（四角を残して整える段を設けない）。CheckListMaker と同じで、モザイクは何度でも重ねて置けるため。
- 表示のみの書き込みは、2 枚の絵を比べて下見でもモザイクの上に残す（事前調査 L）。保存後に見えるものが、下見で隠れて見えるのを防ぐ。
- 画像の形式は、PNG が JPEG の 2 倍以下なら PNG（文字がにじまない）、超えるなら JPEG（写真のページが大きくなりすぎない）。
- 1 ページが 4,000 万画素（差し込み・PDF→画像と同じ上限）を超えるなら、細かさを下げて収める。
- 古い中身を消すのは、モザイクのある保存と抽出のときだけ。モザイクの無い保存の振る舞いは変えない。
- 名前を付けて保存の確認は、上書きと同じダイアログで文面だけ変える。
- 差し込んだ未保存のページには置かない（帯で断る）。注釈の道具・トリミングと同じ扱い。
- `.bak` を消せなかったときは、保存は成功のまま黄色の帯で知らせる（保存したファイルは正しいため）。

## 既知の限界

### 既知の限界（実装で分かったもの）

- 半透明の表示のみの書き込み（文字の上に押したスタンプなど）の下では、下見と印刷に元の文字が透けて見えることがある（書き込みの画素は `base` と
  色が違うので、まるごと残すため）。保存したファイルでは透けない（画像の上に書き込みが乗る）。印刷する前に保存すれば避けられる。
- モザイクを置く・外すたびに検索バーが閉じ、検索語が消える（plan を変える操作で検索結果を捨てる今の作り。spec-1-5 確定事項47）。
- 下見の 2 枚目（書き込みを描かない絵）は、範囲が小さくても紙全体を表示の細かさで描く（高い倍率では重い）。
- 紙全体（MediaBox）を読めないときは見える範囲（`page.view`）で描くので、トリミングの外の紙は保存で白くなる（元の中身は残らない）。
- 細かい（4pt）モザイクでは、大きな文字の形が読み取れることがある（粗さは利用者が選ぶ）。画像のページのサムネイルには縮小のギザギザが出ることがある。
- 知らない圧縮でほどけない内容の流れを持つページは `/Resources` を絞らない（そのページと共有している中身は残り得る）。
- `renderer/save.js` は前から 200 行を超えている（339 → 377 行）。分けるのは保存の部品の作り替えになるので、別の機会に回した。
