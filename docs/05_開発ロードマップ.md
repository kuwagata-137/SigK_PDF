# SigK PDF 開発ロードマップ

作成日: 2026-08-29
関連: `docs/01_製品要件定義.md`（機能ID）／`docs/02_アーキテクチャ設計.md`（モジュール）

各フェーズは「終わったら動くものが手元に残る」単位で切る。フェーズの終わりにはインストーラーを1本作り、実機で触れる状態にする。着手前に仕様を確定させる進め方は `.claude/CLAUDE.md` 領域1に従う。

## Phase 3 — 変換

**目的**: 画像と PDF を相互に変換できる。

| # | 作業 | 対応要件 |
|---|---|---|
| 3-1 | 画像 → PDF（用紙サイズ・向き・余白・1つにまとめる／個別） | F-04-1〜F-04-3 |
| 3-2 | PDF → 画像（ページ指定・解像度指定） | F-04-4 |

PDF → 画像は pdf.js でキャンバスに描いたものを書き出す。ワーカーは Node 側であり `canvas` を持たないため、この処理だけはレンダラーで行い、書き出しをメインへ渡す。**この非対称は設計の例外である**ため、`worker/op-convert.js` に理由をコメントで残す。

## 第2版以降（未着手）

`docs/01_製品要件定義.md` 第3-2章の機能群。着手の前に、それぞれ単独で仕様を確定させる。

| 機能 | 先に決めるべきこと |
|---|---|
| 圧縮 | Ghostscript の同梱可否。AGPL であるため、配布形態によってはソース公開義務が生じる。**ユーザーの判断が要る** |
| OCR | Tesseract と日本語学習データの同梱。インストーラーのサイズが数十MB増える |
| パスワード保護 | pdf-lib は暗号化した書き出しに対応しない。代替ライブラリの選定が要る |
| 墨消し | テキストオブジェクトの確実な削除を、どう検証するか |
| フォーム入力 | AcroForm の対応範囲 |
| Windows 11 の新メニュー | `docs/03` 第6章 |

## 進め方についての注記

- 各フェーズの着手前に、そのフェーズの仕様書を `docs/spec-<phase>-<id>-<name>.md` として書き、確定させてから実装に入る（CheckListMaker と同じ命名）。
- フェーズをまたいで機能を先取りしない。Phase 1 の途中で注釈を作り始めない。
- 各フェーズの終わりにインストーラーを1本作り、実機で触る。触ってからでないと分からない問題（右クリックの挙動、日本語の描画、大きなファイルの体感速度）が多いためである。
