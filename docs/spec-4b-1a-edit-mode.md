## 目的

Phase 4B 塊①（見た目の設定）は、画面の組み替えと雲形が加わって過去の塊の 2 倍を超える見込みになったので、2 本に分けた（決定47）。
この ①-a はその前半で、**①-b の見た目の設定を載せる土台を作る**。終えた時点で、新しい画面で今までの機能がすべて使え、見つけた不具合も
直っている。色・太さ・不透明度を選ぶ右パネルの行は今のままで、①-b で作り替える。

1. **画面の組み替え**: 編集の道具を、ツールバーの下のもう 1 段（道具の段）に並べる。四角いボタンの下に名前を置く、CheckListMaker の
   画像エディタと同じ作りである。図形は矢印・直線・四角・丸の 4 つの道具に分ける。レールは 閲覧・ページ編集・編集・ツール にして道具を外し、
   左のサイドパネルは編集モードでも既定でサムネイルを出して、見出しの切り替えで注釈一覧に替える。
2. **呼び名**: 画面に出る「注釈」を「書き込み」に替える。PDF 特有の言葉で伝わりにくいためで、一覧の名前「注釈一覧」だけは残す。
3. **読み戻しの口**: pdf.js が返さない欄（ハイライトとペン以外の不透明度 `/CA`、塗り `/IC`、雲形 `/BE`、`/RD`）を、ワーカーで注釈の
   辞書から直接読む。①-a では不透明度を当て、SigK PDF がまだ同じ見た目に描けないもの（塗り・線なし・破線・雲形・`/RD`）を表示のみに
   して、直したときに見た目が変わるのを防ぐ。①-b と塊②以降は、この口に欄を足して読む（`docs/05` Phase 4B「塊をまたいで守ること」）。
4. **見つけた不具合 5 つの修正**: 次に付ける不透明度が図形・ペン・テキストに効かない、描いている途中の下書きが不透明で描かれる、読み込んだ
   太い線が 1pt に戻る、テキストの色が保存のたびに 1 段ずれる、`/Annots` に直に置かれた注釈を消すと保存ごと断られる。
5. **振る舞いを変えない分割**: 200 行の目安を大きく超えたファイルのうち、①-a と ①-b が触るもの。

## 事前調査（2026-09-28・Windows 11 実機・Node 24・Electron 44・pdf.js 6.3.289・pdf-lib 1.17.1・fixtures と scratchpad の検体のみ）

塊①をまとめて起草していたときに事前調査 A〜F を行った。①-a にかかわる A・B・E をここに置き、C（画面）・D（塗りと不透明度の見え方）・
F（設定の移し替え）は ①-b の仕様書に置く。使い捨てのプローブは scratchpad に置いた（静的サーバーと Browser パネルの pdf.js、Node の
pdf-lib、窓を出さない起動確認）。G は 2026-09-29 にコードを読んで確かめた、画面の組み替えにかかわる事実である。

### A. pdf.js が返すもの — 不透明度は Ink とハイライトだけ、塗りは返さない、太い線は 1pt、テキストの色は 1 段ずれる

`three-pages.pdf` に、自前の保存経路（`applyAnnotations`）で 12 件（矩形・楕円・水平な 2pt と 8pt の直線・10pt 角に 8pt の矩形・
矢印・ペン・テキスト 2 つ（`#d92c2c`・`#ff8844`）・ノート・ハイライト・30pt 角に 40pt の矩形。多くは不透明度 35%）、他のツールを
想定して 8 件（`/IC`＋`/CA` の矩形、`/C` が無く `/IC` だけの矩形、`/C []` の楕円、破線の矩形、`/BE`・`/RD` の楕円、外観の無い
`/CA`＋`/IC` の矩形、3 点の PolyLine、塗った Polygon）、参照の形が違うもの 2 件（世代 1 の参照、`/Annots` に直に置いた辞書）を
書き、pdf.js の `getAnnotations()` で読んだ。

| 欄 | 返り方 | 帰結 |
|---|---|---|
| `opacity` | Ink とハイライトだけ（0.35）。矩形・楕円・直線・矢印・テキスト・ノートには欄が無い | 読み込むと 1 扱いになる（決定39 に書いた限界）。口で `/CA` を読む |
| `/IC`（塗り） | どの種類でも返らない | 口で読む |
| `borderStyle.width` | 線の太さが `/Rect` の幅か高さの半分を超えると 1 に置き換わり、元の値は `rawWidth` に残る。水平な 2pt の直線（`/Rect` の高さ 2）・8pt の直線・10pt 角に 8pt・30pt 角に 40pt はどれも 1。`/BS /W 0` は width 0 | **今は保存して開き直すと 1pt に戻る（既存の不具合）**。width が正なら `rawWidth` を使えば、口を待たずに直る |
| `color` | `/C` が無いか空の配列なら null | 今は表示のみになる（`importedShape` が断る） |
| テキストの文字色 | `/DA` ではなく外観の `rg`（小数 2 桁で書いている）から読む。`#d92c2c` → [217,43,43]（`#d92b2b`）、`#ff8844` → [255,135,69]（`#ff8745`） | **保存するたびに 1 段ずれる（既存の不具合）**。成分を小数 3 桁で書けば 8bit で往復する（誤差は最大 0.13） |
| 破線 | `borderStyle.style` 2・`dashArray` [3, 2] | 見分けられる |
| 雲形（`/BE`）・`/RD` | 返らない | 口で読む |
| `id` | 世代 0 は `"13R"`、世代 1 は `"52R1"`、`/Annots` に直に置いた辞書は `"annot_p2_1"` | 口が読めるのは参照の形の id だけ |

あわせて、`/Annots` に直に置いた辞書（規格は参照を並べることを求めており、まれな形）の矩形は、今は直せる注釈として読み込まれて
いた。これを選んで消して保存すると、ワーカーが id を参照に直せず「消す注釈の指定が読めません。」で保存ごと断る（起動確認で再現）。

破線・`/BE`・`/RD`・`/IC` を持つ矩形・楕円も、今は直せる注釈として読み込まれ、`noView` で pdf.js の外観を隠したうえで SigK PDF が
実線・塗りなしで描き直している。開いただけで見た目が変わり、直して保存すると元の見た目は失われる（コードから読んだもの。確定事項24・26 で直す）。

### B. 読み戻しの口 — 小さな文書で数 ms、注釈 1,000 件で 130ms。暗号化 PDF も数の欄は読める

Node で pdf-lib（vendor と同じ版）の試作を回した。読む・開く・辞書を集める、の時間と RSS。

| 検体 | 開く（`load`） | 集める | RSS |
|---|---|---|---|
| `three-pages.pdf`（1.5KB） | 4.1ms | 0.2ms | 56MB |
| `sigk-annotated.pdf` | 4.6ms | 0.2ms | 57MB |
| `many-pages.pdf` | 7.3ms | 0.2ms | 57MB |
| `huge-pages.pdf`（252KB） | 289ms | 0.2ms | 68MB |
| `perf-10mb-50p.pdf`（10MB） | 16.3ms | 0.2ms | 68MB |
| 注釈 10 件 | 3.6ms | 0.4ms | 56MB |
| 注釈 1,000 件 | 130ms | 4.3ms | 67MB（返す JSON は 134KB） |

これにワーカーを起こす時間が足される（保存の経路は起動込みで 221ms。`spec-1-6`。透かしは 301〜498ms。`spec-4-5`）。

- `/CA`・`/IC`・`/C`・`/BS`（`/W`・`/S`・`/D`）・`/BE`・`/RD` を正しく読めた。世代 1 の参照も読めた。
- 暗号化 PDF は `ignoreEncryption: true` で開けば数の欄が読める（数は暗号化されない。文字列とストリームは読めない）。付けないと
  `load` が断る。オブジェクトストリームに入った辞書は読めない見込み（推測）。そのときは答えが無く、pdf.js の値で読む。
- 注釈の読み込みが走るのは、開いたときと保存して開き直したときだけ（`renderer/viewer.js` の `open`・`reopen`）。タブの切り替えでは走らない。
- **読み込みは、表示中の文書でなくなったら結果を捨てる**（`isCurrent`）。複数のファイルを続けて開くと、前のタブの読み込みが
  次のタブを開いた時点で捨てられ、そのタブの注釈は一覧に出ず直せない（コードから読んだもので、今は読み込みが速いので起きにくい。
  推測）。口を待つ時間（数百 ms、順番待ちなら秒）が加わると起きやすくなるので、結果をその文書のタブへ入れる形に改める（確定事項29）。

### E. 既存の不具合の再現

起動確認で、図形・ペン・テキスト・ノートの道具を持ち、それぞれ不透明度 50% を選んでから置いた。付いた不透明度は
[1, 1, 1, 0.5] で、図形・ペン・テキストは 1 のまま、ノートだけ 0.5 だった。右パネルの「不透明度」は 50% を示していた。

### G. 画面の組み替え（2026-09-29・コードを読んで確かめたこと）

- レールの道具は `index.html` の `.rail-item.tool`（7 つ）と区切り線で、`annotate.js` がクリックと押している印を持つ。道具を
  無効にする処理は無い（`shell.css` に `aria-disabled` の規則だけが残っている）。
- 「図形の種類」の行は、図形の道具を持って何も選んでいないときだけ出る（`annotation-props.js` の `setShapeRow`）。決めるのは次に描く
  種類だけで、描いた図形の種類は変えない（決定37、`annotate-shape.js` の `setShapeKind`）。4 つの道具に分けても、失う操作は無い。
- 注釈モードのサイドパネルは注釈一覧だけで、サムネイルは閲覧・ページのモードでしか描かない（`thumbnails.js` の `isVisible`）。
- モードを替えても倍率を計算し直す処理が無い。`shell.setMode` は `viewer.refit` を呼ばず、呼ぶのはサイドパネルの開閉と幅、窓の
  大きさの変更だけである。今も「幅に合わせる」で開いてから注釈モードへ入ると、右パネル（260px）の分だけ紙がはみ出たままになる
  見込み（コードから読んだもの。実装の前に起動確認で確かめる）。道具の段で縦も約 62px 縮むので、「全体」でも同じことが起きる。
- 画面に出る「注釈」は、`index.html` に 9 か所、画面のコードに 18 行、ワーカーの文言に 5 行ある（確定事項12 の表）。これを見ている
  テストと、レール・左の見出し・図形の種類の行を見ているテストは「テストの範囲」に挙げた。

## 確定事項

### A. 道具の段（モック `screenshots/phase4b-style.png`）

1. ツールバー（`#toolbar`）の下、本体（`#body`）の上に 1 段置く（`#edit-bar`）。編集モードのときだけ出し、ほかのモードでは場所も
   取らない。
2. 見た目はモックのとおりにする。高さ 35px の四角いボタン（枠線・角丸 7px）の下に 10.5px の名前を置き、押している道具はボタンを青
   （`--primary`）で塗ってアイコンを白、名前も青にする。アイコンは 19px・線 1.7。ボタンの間は 5px、区切り線は縦 1px。段の高さは約 62px。
3. 並びは ハイライト・下線・取り消し線｜テキスト｜矢印・直線・四角・丸｜ペン・ノート とし、グループの間に区切り線を 3 本引く。
4. 押すと道具を持ち、同じボタンをもう一度押すと離す（今のレールと同じ）。ハイライト・下線・取り消し線は、文字を選んでいればその場で
   付く（今のまま。決定33）。
5. 図形の 4 つのボタンは「図形の道具＋種類」を持つ。図形の道具を持っているときに別の図形のボタンを押すと、道具を持ったまま種類だけ
   替わる。
6. ボタンは `<button type="button">` にする（キーボードで押せる）。`title` と `aria-label` に名前を入れ、押している間は
   `aria-pressed="true"` を付ける。段は `role="toolbar"`・`aria-label="書き込みの道具"`。文書が無くても押せる（今のレールと同じ）。

### B. 図形の 4 つの道具

7. 中の道具は今の `shape` のまま、種類（`square`・`circle`・`line`・`arrow`）で描き分ける。色・太さ・不透明度は 4 つで共有する

8. 右パネルの「図形の種類」の行をなくす。図形の道具を持っているときの種類の見出しは「四角（次に付ける）」のように種類の名前にする。
9. 種類の呼び名を 矩形 → 四角、楕円 → 丸 に替える（`TOOL_LABELS`・`READONLY_LABELS`。右パネル・注釈一覧・ツールチップに出る）。
10. 設定の `annotShapeKind`（最後に使った図形の種類）は今のまま残す。図形のボタンを押すと書き換わる。

### F. 読み戻しの口（ワーカー・メイン・preload）

20. preload に `annotationAPI = { available: true, readDetails(spec) }` を足す。IPC は `annotation:readDetails`。
21. メインは `source` が実在するファイルのパスかを確かめ、そうでなければ `{ ok: false, reason: 'invalid' }` を返す。
    `taskRunner.run('annotation-details-<連番>', { kind: 'annotation-details', source, expect, refs }, { timeoutMs: 10000 })` で回し、
    10 秒で答えが無ければ中止して `{ ok: false, reason: 'timeout' }`、ワーカーが失敗すれば `{ ok: false, reason: 'unreadable' }` を返す。
    帯も「実行中」の表示も出さない。`task-runner.js` の `run` に `timeoutMs` の口を足す（時間が来たら `cancel` と同じ手で落とし、
    `{ canceled: true, timedOut: true }` を返す）。
22. ワーカー（`worker/annotation-dict-reader.js`。`worker/tool-tasks.js` の `TOOL_TASKS` に `'annotation-details'`）は、次の順に進める。
    - spec の形を確かめる。`expect` は `{ size, mtimeMs }` の数、`refs` は `数字R` か `数字R数字` の文字列の配列で 1〜10,000 件。崩れて
      いれば `{ ok: false, reason: 'invalid' }`。
    - ファイルの大きさと更新時刻を `expect` と照らし（`pdf-write.js` の `readSignature`・`signaturesMatch`）、違えば
      `{ ok: false, reason: 'changed' }`。
    - 読んで `ignoreEncryption: true` で開き、`refs` を参照に直して辞書を引く（`annotation-remove.js` の参照の読み方と同じ）。辞書で
      ないもの・`/Subtype` の無いものは飛ばす。
    - `{ ok: true, details: { '12R': { ca, interior, stroke, borderWidth, borderStyle, dash, cloudy, rectDifference } } }` を返す。
      読めなければ `{ ok: false, reason: 'unreadable' }`。
23. 欄の意味は次のとおり。色は PDF の成分（0〜1 の数の配列）のまま返し、画面側で変換する。無い欄は `null`（`cloudy` は `false`）にする。
    `ca` は `/CA`、`interior` は `/IC`、`stroke` は `/C`、`borderWidth` は `/BS /W`、`borderStyle` は `/BS /S` の名前（`'S'`・`'D'` など）、
    `dash` は `/BS /D`、`cloudy` は `/BE /S` が `/C` か、`rectDifference` は `/RD`。

### G. 読み込みへの当て方（`annotation-import.js`・`imported-entry.js`・`annotation-details.js`）

24. 1 件の組み立て（`imported-entry.js` へ移す）で、次の 3 つを改める。
    - id が参照の形（`12R`・`12R3`）でない注釈（`/Annots` に直に置いた辞書。pdf.js が `annot_…` と名付ける）は読み込まない。
      pdf.js が描き続け、注釈一覧には出さず、直すことも消すこともできない（決定47 論点11）。
    - 線幅は、`borderStyle.width` が正なら `rawWidth`（pdf.js が `/Rect` に合わせて 1 に置き換える前の値）を使う（事前調査 A）。
    - 四角・丸・直線・矢印・ペンのうち、線幅が 0 のもの、線の形（`borderStyle.style`）が実線でないもの（破線など）は表示のみにする。
      SigK PDF がまだ同じ見た目に描けないためで、①-b で四角・丸の線なしと破線を直せるようにする。
25. 口が要るのは、表示のみでない 四角・丸・直線・矢印・テキスト・ノート（pdf.js が不透明度を返さない種類）である。これが 1 件でもあり、
    文書にファイルの置き場所・大きさ・更新時刻の控えがあり、ファイルが 100MB 以下で、件数が 10,000 以下なら、口を 1 回呼ぶ
    （決定47 論点7）。呼び出しは 1 本ずつ順番に回す。
26. 答えの当て方（`applyDetails`）は次のとおり。
    - `ca` が 0〜1 の数なら `opacity` にする。
    - 四角・丸で、`interior` が 1 成分以上の配列（塗りあり）、`cloudy` が真、`rectDifference` に 0 でない数がある、のどれかなら表示のみに
      する。①-b で塗り・雲形・`/RD` を直せるようにする。
27. 口が使えなかったとき（呼べない・`invalid`・`changed`・`unreadable`・`timeout`・その注釈の答えが無い）は、pdf.js の値で読む。
    今までどおりで、不透明度は 1 になる。
28. 流れは、全ページを集める → 口に頼む → 答えを当てる → 表示のみでないものに pdf.js に描かせない印（`noView`）を付ける → 映す、の順に
    する。口を待つ間（数百 ms）は pdf.js が描いたままで、注釈一覧に出ず、選べない。
29. 読み終えたとき、その文書が別のタブへ退避していれば、結果を捨てずにそのタブの退避分へ入れる（タブへ戻ると映る）。表示中ならすぐ映す。
    文書が閉じられていれば捨てる。事前調査 B の、続けて開くと前のタブの注釈が失われ得る件をこれで直す。
30. 読み込みが終わるのを待つ口 `annotationImport.settled()` を足す（起動確認とテストが待つ）。

## 起草者の判断で決めたもの

- 図形の 4 つの道具は、中の道具を `shape` のまま種類で描き分ける。設定・保存・起動確認の `tool:shape` を変えずに済み、色・太さ・不透明度も
  今と同じく 4 つで共有できる。
- 道具の段のボタンは `<button>` にした。レールの道具は `<div>` で、キーボードでは押せなかった。
- 左の切り替えは設定に覚える（`ui.editSide`）。モード・サイドパネルの開閉と幅・見開きも覚えているので、同じ扱いにした。
- 編集モードでは左の見出しの文字を隠し、切り替えだけを出す（`MODE_TITLES` から外す）。
- フラット化の節の見出し「焼き込む注釈」は「焼き込むもの」にした。「焼き込む書き込み」は読みにくく、同じ節の「焼き込まずに残すもの」と対になる。
- 表示のみのヒントは「他のアプリで付けた書き込みです。…直すことはできません。」にした。「ツール」は SigK PDF の「ツール」モードと紛れる。
- テキストの入力欄の読み上げ名は「テキストの書き込み」。
- モードを替えたときの倍率の追従（確定事項19）。今も右パネルの出し入れで幅がずれる見込みで、道具の段で縦もずれるようになるため。
- ①-a では、SigK PDF がまだ同じ見た目に描けないもの（塗り・線幅 0・実線でない線・雲形・`/RD`）を表示のみにする。今は直せる注釈として
  読み込み、開いただけで見た目が変わっていた。①-b で直せるようにする。
- 口を呼ぶのは 四角・丸・直線・矢印・テキスト・ノートのときだけ。ハイライト・下線・取り消し線・ペンは pdf.js が不透明度を返す。
- 口の上限は 100MB・10,000 件・10 秒とし、1 本ずつ順番に回す。100MB を超えるファイルは、開くたびにワーカーが同じ大きさを読み直すのを避ける。
- 口は `taskAPI` を通さず専用の IPC にした。帯と「実行中」の表示を出さないためで、テストの偽の `taskAPI` は答えを先頭から返すので、開くたびに
  口が走ると既存のテストの順が崩れるのも避けられる。
- 時間切れは `task-runner.js` の `run` に `timeoutMs` の口を足して、メインで中止する。
- 外観の色の成分は、テキストだけでなくすべての種類で小数 3 桁にした。pdf.js が外観から色を読むのはテキストだけだが、書き方を 1 つに揃える。
