# PDF編集アプリ開発 調査要件レポート

## 1. 目的

PDF24（PDF24 Tools / PDF24 Creator）のような、PDFの結合・分割・変換・編集などを行えるアプリケーションを、Claude Codeを用いて開発する。

## 2. 実現可能性

PDF編集アプリはオープンソースライブラリが充実している技術領域であり、Claude Codeでの開発は十分に可能。ゼロからの独自設計よりも、既存OSSの構成を参考にしながら必要機能を絞り込んで実装する方が現実的。

## 3. 想定する実装アプローチ

### デスクトップアプリ（推奨）
- 構成: Electron + PDF.js（表示） + pdf-lib（編集）
- ローカルファイルへの直接アクセスが容易
- PDF24と同様、オフライン動作が可能

### Webアプリ
- ブラウザ内完結（PDF.js + pdf-lib）であればファイルをサーバーに送信せずセキュアに処理可能
- インストール不要で配布しやすい

## 4. 機能別の実装難易度

### 易しい（既存ライブラリで十分カバー可能）
- 結合・分割・回転・ページ削除（pdf-lib, PyPDF2 等）
- 画像⇔PDF変換
- 圧縮

### 中程度（既存ライブラリ＋工夫が必要）
- テキスト注釈・フォーム入力
- 透かし追加
- パスワード保護／解除

### 難しい（専用エンジンが必要、フル実装は重い）
- OCR（Tesseract.js等の外部エンジンに依存）
- PDF→Word等の高精度変換（レイアウト保持が難点）
- ページ内の既存テキストの直接書き換え（PDFの構造上、根本的に困難）

## 5. 参考になるオープンソース実装（GitHub）

PDF24に類する機能を持つOSSは複数公開されており、実装パターンの参考にできる。

### Stirling PDF（Stirling-Tools/Stirling-PDF）
- GitHubで人気の高いPDFアプリケーション。デスクトップアプリ・ブラウザUI・自前サーバーへのデプロイ（プライベートAPI付き）に対応
- 結合・分割・署名・墨消し・変換・OCR・圧縮など50種類以上のツールを搭載
- 機能面でPDF24に最も近い。Java（Spring Boot）ベース
- ライセンス: open-core（一部機能が商用ライセンス）

### PDF4QT（JakubMelka/PDF4QT）
- Qtフレームワークを用いたPDF編集ソフト
- C++ライブラリ、GUIアプリ、コマンドラインツールで構成
- ライセンス: LGPLv3

### KillerPDF（SteveTheKiller/KillerPDF）
- Windows向けの無料オープンソースPDFエディタ
- 閲覧・注釈・OCR・結合・分割・切り取り・回転・比較・テキスト編集・描画・署名・フォーム入力・印刷・フラット化・パスワード保護PDFの開封に対応

### PDFsam Basic
- 結合・分割に特化したシンプルなデスクトップアプリ
- PDF24の直接的なオープンソース代替としてよく挙げられる

### Open PDF Studio（OpenAEC-Foundation/open-pdf-studio）
- Tauri 2ベースの軽量デスクトップアプリ
- 注釈・マークアップ・測定・墨消し・ページ管理などを搭載

## 6. 検討すべき論点

- **スコープ**: PDF24はツール群が非常に多機能。全機能を再現するか、よく使う一部（結合・分割・圧縮・変換など）に絞るかで開発規模が大きく変わる
- **実行環境**: Claude Codeでのビルドはローカル開発が基本。配布形態（Electronパッケージ化、Web公開等）は別途検討が必要
- **既存ライブラリの制約**: 特にOCRや複雑なレイアウト変換は自作よりも、既存の専用ツール（Ghostscript, Tesseract, LibreOffice CLI等）を呼び出す設計の方が現実的
- **ライセンス**: 参考にするOSSのライセンス（Stirling PDFはopen-core、PDF4QTはLGPLv3等）により、コードの流用・商用配布時の扱いが異なるため、方針決定前に確認が必要

## 7. Adobeが保有する権利との抵触リスク

PDF編集アプリを開発・公開するにあたり、Adobeの権利（特許・商標・トレードドレス）に抵触しないための調査結果。大別すると「特許」はリスクが低く、「商標・見た目の模倣」は注意が必要という結論になる。

### 7-1. 特許（PDFフォーマット自体） — リスクは低い

- AdobeはPDF仕様を2008年にISOへ提供し、国際標準規格ISO 32000-1として標準化した
- Adobeは、ISO 32000-1に準拠した実装（PDFの読み取り・書き込み・変更・処理）であれば、世界中のあらゆる個人・組織に対しロイヤリティフリーで必須特許（Essential Claim）を実施許諾すると公式に宣言している（Adobe Systems Incorporated Public Patent License）
- 線形化（linearization）のような高度な機能についても、第三者が実装した場合に特許侵害のリスクを負うことはないとPDF Associationが確認している

**留意点**
- この特許ライセンスには防御的停止条項があり、実施許諾を受けた側がAdobe（または他社）に対しこの特許に関する侵害訴訟を提起した場合、Adobeはその許諾を取り消せる
- ライセンスの対象は「ISO 32000-1に準拠した実装」に限られる。仕様書に明記されていない独自拡張や、Adobe製品固有の非公開機能を模倣する場合は、この特許ライセンスの保護範囲外になる可能性がある
- 一般に、PDFフォーマットへの参入障壁は特許よりも実装の複雑さと市場でのAcrobatの普及度によるところが大きいという指摘もある

### 7-2. 商標 — 名称・表記に注意が必要

- 「Acrobat」はAdobeの商標であり、Adobeの書面による事前許諾なしに、関連するソフトウェア製品・サービスの名称に使用することはできない
- 自社のPDF生成・編集ソフトが作成するファイルについて、「Adobe Acrobat file」「Adobe PDF」といった用語や、Adobe PDFロゴを自社製品の識別に使うことは認められていない
- 「PostScript」も同様にAdobeの商標であり、Adobeからライセンスを受けていない企業がソフトウェアや関連製品にこの商標を使うことは許可されない
- Adobeの商標は、第三者の会社名・製品名・サービス名・ドメイン名・商号の一部として、書面による明示の合意なしに使用してはならない

**アプリ開発における実務上の注意**
- アプリ名や製品名に「Acrobat」「Adobe」「PDF24」（他社商標でもあるため同様に注意）などの語を含めない
- 「Adobe Acrobat互換」「Adobe PDF形式に対応」等、Adobe製品との関連性を誤認させる訴求表現を避ける
- 自社が独自にISO 32000準拠を主張する場合の文言にも注意する（Adobeのライセンサーであるかのような誤解を与えない）

### 7-3. トレードドレス・UI/UXの模倣 — 注意が必要

- Adobe製品の視覚的語彙（ブランドの配色、タイポグラフィ、グラフィックデザイン、製品アイコン、ルック＆フィール）を模倣することは禁止されている
- Adobeのロゴ・シグネチャー・アイコンデザインを改変・追加して使用すること、またその一部を自社製品に組み込むことも禁止されている
- これは商標法だけでなく、意匠権や不正競争防止法上の「著名な商品等表示との混同惹起行為」にも関わりうる論点である

**アプリ開発における実務上の注意**
- Acrobatのツールバー配置・アイコンデザイン・配色を意図的に模倣しない（機能として同種のボタンを配置すること自体は問題にならないが、見た目まで似せるとリスクが生じる）
- UIデザインはPDF4QTやStirling PDFなど、OSSプロジェクト独自のデザインを参考にする方が安全

### 7-4. 総合評価と推奨対応

| 観点 | リスク水準 | 対応方針 |
|---|---|---|
| PDF形式の読み書き（ISO 32000準拠） | 低い | Adobeの公式パテントライセンスの対象内。通常の実装であれば問題なし |
| Adobe独自の非公開拡張機能の模倣 | 中〜要確認 | 該当機能を実装する場合は個別に仕様の出所を確認する |
| 製品名・商標の使用 | 要対応 | 「Adobe」「Acrobat」「PostScript」等の語を製品名・訴求文言に含めない |
| UIデザイン・配色・アイコンの模倣 | 要対応 | Adobe製品の見た目を模倣せず、独自またはOSS由来のデザインを採用する |
| OSSコードの流用 | ライセンス次第 | 参考にするOSS（第5章）のライセンス条項（LGPLv3, open-core等）を個別に確認する |
