## 目的

ユーザーの依頼（2026-11-13）による。

> 印刷のダイアログをアクロバットリーダーと全く同じにしてください。

依頼には、Acrobat Reader の［印刷］ダイアログの画面写真が 2 枚付いていた（ページサイズ処理で［サイズ］を選んだ状態と、［複数］を選んだ状態）。
画面写真には社内のプリンター名と文書が写っているので、リポジトリには入れない（このリポジトリは公開）。

「ダイアログ」は、SigK PDF の印刷画面（Ctrl+P とツールバーの印刷ボタンで開く `#print-dialog`）と読んだ。
構成・文言・配置・見た目・動きを Acrobat と同じにする。Electron で同じ動きにできない所は、質問 PR1〜PR3 で決めた。

## 用語

| 用語 | 指すもの |
|---|---|
| 印刷画面 | SigK PDF の印刷の画面（`#print-dialog`。ツールチップ「印刷画面を開きます。」と同じ） |
| Windows の印刷画面 | `webContents.print({ silent: false })` が表示する Windows 標準の画面。この改修の後は使わない |
| Acrobat の［印刷］ダイアログ | Acrobat Reader の画面。この文書の「Acrobat」は Acrobat Reader（日本語版・Windows）を指す |
| 印刷設定 | Windows のプリンターの「印刷設定」画面（プリンターの会社が作った画面） |
| シート | プリンターへ送る 1 ページ分の面（両面印刷では紙の片面）。Acrobat の「各シート内でページを自動回転」と同じ言葉 |
| 書き込み | SigK PDF の用語（ユーザーが決めた）。Acrobat の「注釈」と同じもの。印刷画面の文言は「注釈」を使う（質問 PR2） |

## 事前調査（2026-11-13）

| 調べたこと | 分かったこと |
|---|---|
| Electron 44 の印刷 | `webContents.print` は silent・deviceName・copies・collate・color・duplexMode・landscape・pageSize・margins・pageRanges・pagesPerSheet・usePrinterDefaultPageSize を受け付ける（`node_modules/electron/electron.d.ts`）。`getPrintersAsync()` は name・displayName・description・options を返し、既定のプリンター・用紙サイズ・両面の可否は返さない |
| Electron でできないこと | プリンタードライバーの設定画面を「この印刷だけ」に使う形で開く API、Windows の「ページ設定」画面を開く API、給紙トレイを指定するオプションはない |
| プリンターの既定の設定 | Windows の PowerShell の `Get-PrintConfiguration` で、プリンターごとに PaperSize・DuplexingMode・Color・Collate と、PrintTicketXML（用紙の寸法 µm）・PrintCapabilitiesXML（印刷可能領域・用紙サイズ一覧・両面の可否）を取得できる。実測で 1 台 61〜1031 ms。取得できないプリンターもある（アクセス拒否 1 台） |
| 既定のプリンター | レジストリ `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Windows` の Device に「プリンター名,winspool,ポート」の形で入っている |
| 社内のプリンター | このパソコンには 30 台が登録されている。既定の用紙が A5・B5・A3 のもの、既定が両面のもの、手差し用のものがある。用紙を A4 に固定すると、これらの既定を壊す |
| Acrobat の文言の出所 | ①ユーザーの画面写真 2 枚 ②Adobe 日本語ヘルプ（「印刷設定」「1 枚に複数のページを印刷」「小冊子の印刷」「大判文書の印刷」「Acrobat Reader での PDF の印刷」「用紙の両面に印刷」） ③ASCII.jp の Acrobat DC 連載の画面写真（2017〜2018 年）。版によって文言が違う所がある |
| 注釈の一覧 | ASCII.jp の画面写真（2017 年）: ［注釈の一覧(T)］を押すと「印刷する文書に注釈の一覧テキストを含めますか？」［はい(Y)］［いいえ(N)］を表示し、はいなら、書き込みのあるページの後ろに一覧ページ（番号・作成者・タイトル・日付・本文）を印刷する |
| インク / トナーを節約 | Adobe の資料（Customization Wizard の説明）: コンテンツを最適化して印刷し、最大で 15% 節約する。通常、印刷品質に影響しない。Adobe のコミュニティの回答: インクを減らす専用の ICC プロファイルで色を変換する |
| pdf.js の印刷 | pdf.js 6.3.289 の `render` は `printAnnotationStorage` を受け付ける。SigK は `annotationStorage` の noView で、pdf.js に描かせない書き込みを決めている（`renderer/annotation-import.js`）。ページの内容と書き込みの差分を取る方法は `renderer/mosaic-paint.js` にある |

## 配置の計算（Claude の案）

- 印刷可能領域: プリンターの PrintCapabilitiesXML の PageImageableSize。取得できない時は用紙の四辺から 4.23 mm 内側。
- サイズ: 合わせる＝印刷可能領域に収まる最大の倍率（拡大もする）。実際のサイズ＝100%（用紙の中央。はみ出た所はプリンターが切る）。特大ページを縮小＝印刷可能領域より大きいページだけ縮小。カスタム倍率＝1〜1000%。
  プレビューの「倍率」は、表示しているページの倍率。
- 向き: 自動＝ページの縦横に合わせて用紙の向きを決める（印刷する画像は、用紙の向きに合わせて回して作る）。縦・横＝用紙の向きを固定する。
- 複数: 1 枚あたりのページ数 2・4・6・9・16 は、用紙の向きに合わせて列と行を決める（例 縦の用紙の 2 ページは 1 列 2 行）。カスタムは列と行を 1〜99 で指定する。
  ページの順序は、横＝左から右・上から下、横 (右から左)、縦＝上から下・左から右、縦 (右から左)。ページ境界線を印刷は、各ページの範囲に細い線を描く。各シート内でページを自動回転は、枠に合う向きにページを回す。
- 小冊子: ページ数を 4 の倍数にして（足りない分は白紙）、中綴じの順番に並べる（左綴じの 1 枚目の表＝最後のページと 1 ページ、裏＝2 ページと最後から 2 番目）。
  両面で印刷は短辺を綴じる両面印刷で送る。片面で印刷 (表側)・(裏側) は、表だけ・裏だけを送る。開始ページ・終了ページは、印刷する紙の範囲（1〜紙の枚数）。縦長左・縦長右は、用紙を回さずに上下に 2 ページを並べる。
- ポスター: 倍率をかけたページを、印刷可能領域の大きさのタイルに分ける。隣のタイルと「重なり」の幅だけ重ねる。タイルマークは、重なりの端を示す線。ラベルは「ファイル名 日時 ページ 番号 (列,行)」。大きいページのみを分割は、倍率をかけても印刷可能領域に収まるページを分割しない。
- 偶数または奇数ページと逆順に印刷は、印刷するページの一覧に当ててから配置する。小冊子では使えない（灰色）。
- 注釈とフォーム: 文書と注釈＝今と同じ（未保存の書き込みも印刷）。文書＝書き込みを印刷しない（フォームフィールドは印刷する）。文書とスタンプ＝スタンプだけ印刷する。フォームフィールドのみ＝ページの内容を印刷せず、フォームフィールドだけを印刷する。
- 注釈の一覧(T): 確認画面で［はい(Y)］を選ぶと、この印刷では、書き込みのあるページの後ろに一覧ページを入れる。一覧ページの形は「注釈の一覧 :ファイル名」「ページ :番号」と、書き込みごとの「番号 : n 作成者 : 名前 タイトル : 種類 日付 : 年/月/日 時:分:秒」と本文。
- PDF のページサイズに合わせて用紙を選択: ページごとに、プリンターの用紙サイズ一覧から、ページが倍率 100% で収まる最小の用紙を選ぶ。用紙サイズが変わる所で印刷を分ける。

## 手で確かめる筋書き（ユーザーの実機。用紙に印刷するので自動化しない）

1. 1 ページ: 文書を開き、ツールバーの［印刷］で印刷画面を開く。現在のページ(U) を選んで［印刷］を押す。進行状況画面が表示され、プレビューと同じ向き・倍率で 1 枚印刷される。

4. ポスター: ［ポスター］で倍率を 200% にし、タイルマーク(K) とラベルをオンにして［印刷］を押す。タイルを貼り合わせると、元のページになる。
5. 両面: ［サイズ(I)］で 用紙の両面に印刷(B) をオンにし、長辺を綴じる(L) で 4 ページを印刷する。裏表の向きが、長辺で綴じた向きになる。
6. ［プロパティ(P)］: プリンターの印刷設定が開く。用紙サイズか両面を変えて閉じると、印刷画面の用紙サイズ・用紙の両面に印刷(B)・グレースケール (白黒) で印刷(Y) の表示が変わる。

7. 用紙選択: A4 と A3 のページが混ざった文書で、PDF のページサイズに合わせて用紙を選択(Z) をオンにして印刷する（A3 の用紙があるプリンター）。ページごとに用紙が切り替わる。

8. インク / トナーを節約: オンにして印刷すると、オフの時より少し薄く（15%）印刷される。
9. 画質: 小さい文字の多いページを印刷すると、文字の輪郭が滲まない（決定97 ⑤。300 dpi）。

### ④ ユーザーごとの設定値を読む（確定事項C3・PR1 の改訂）

- 原因: `Get-PrintConfiguration` はプリンター全体の既定値（System.Printing の `DefaultPrintTicket` と同じ値）を返し、印刷設定で変更されるユーザーごとの設定値（`UserPrintTicket`）を返さない。［プロパティ(P)］で A3 にして閉じ、取得し直しても A4 のままで、A4 で配置を計算して 67% の画像を作っていた。このパソコンのネットワークプリンター 1 台で、ユーザーごとの設定値が A3、`Get-PrintConfiguration` が A4 であることを実測した。
- 修正: `printer-config.js` の `CONFIG_SCRIPT` は、System.Printing の `PrintQueue.UserPrintTicket`（無ければ `DefaultPrintTicket`）の XML と、その印刷チケットに対する能力情報（`GetPrintCapabilitiesAsXml`）を読む。`\\サーバー\名前` の形のプリンター名は `PrintServer`、それ以外は `LocalPrintServer` から取得する。例外が起きたら、同じ PowerShell の中で `Get-PrintConfiguration` に戻す。出力に読み取り元（`source`: user・default・printconfig）を追加した。カラーと部単位は、印刷チケットに指定が無い時に `Get-PrintConfiguration` と同じ値（白黒・部単位）にする。`printer-xml.js` の読み取りは変えていない。
- `renderer/print-printers.js` の `openProperties`: 取得し直しに失敗した時（`config.ok` が true でない時）は、直前の設定のままにする。修正前は A4 の初期値に戻っていた。
- このパソコンのプリンター 30 台で確認した（読み取りだけ。プリンター名は記録しない）。29 台で取得でき、ユーザーごとの設定値が A3 の 1 台は A3 を返した（修正前は A4）。ほかの 28 台は、用紙・両面・カラー・部単位が修正前と同じ値になった。ローカルプリンター 2 台は、ユーザーごとの設定値に対する能力情報を読むので、印刷可能領域が修正前と変わった。残りの 1 台は、修正前と同じく権限が無く取得できない。所要時間は 1 台 0.8〜3.1 秒（平均 1.4 秒）で、修正前は 1.4〜3.2 秒（平均 2.0 秒）だった。
- 既知の限界: 接続できないネットワークプリンター（存在しないサーバー名で確認）は、System.Printing と `Get-PrintConfiguration` の両方の接続を待つので、取得に失敗するまで 12〜14 秒かかる（修正前は 7〜9 秒。取得の上限 20 秒の内）。

### ③ 決まった 8 種の用紙は Windows の用紙番号でも渡す（確定事項C17 の改訂）

- 原因: 既定と違う用紙で送る時、寸法だけ（`pageSize`）を Electron に渡していた。Chromium は DEVMODE の dmPaperWidth・dmPaperLength だけを書き換え、用紙番号 dmPaperSize は既定の用紙（A4）のまま残すので、用紙番号で用紙を選ぶドライバーでは A4 に印刷される。このパソコンの 1 台のドライバーで、用紙番号 A4・寸法 A3 の指定が、印刷チケットの「ISOA4」になることを確認した。プレビューの用紙寸法を決める処理（C9）は動いていた（このパソコンのプリンター 30 台の能力情報で、A3 のページには A3 を選ぶ）。
- 修正: `print-job-options.js` の `buildPrintSettings` は、寸法が 8 種の用紙（レター・タブロイド・リーガル・A3・A4・A5・B4 (JIS)・B5 (JIS)）と縦横とも ±1 mm で一致する時、`pageSize` の代わりに、Windows の用紙番号（`vendor_id`。レター 1・タブロイド 3・リーガル 5・A3 8・A4 9・A5 11・B4 (JIS) 12・B5 (JIS) 13）を入れた `mediaSize` を渡す。Chromium は `vendor_id` を dmPaperSize に設定する（Chrome の印刷画面と同じ方法）。寸法は 8 種の決まった値にする（A5 を 148.5 × 210 mm で返すプリンターでも A5 として渡す）。一致しない時は、今までどおり寸法を `pageSize` で渡す。レンダラー（`renderer/print-send.js`）は変えていない。
- Electron 44.0.0 の確認（2026-11-17）: ウインドウを表示しないスクリプトで、存在しないプリンター名を指定して `webContents.print` を呼び、`mediaSize`（`vendor_id` 付き）・用紙の指定なし・`pageSize`・`usePrinterDefaultPageSize` のどれも、例外を出さずに「Invalid deviceName provided」まで進むことを確認した（実際には印刷していない）。`electron.exe` に入っている JavaScript の文字列から、`pageSize` がある時だけ `mediaSize` を組み立て直すことも確認した（`pageSize` を一緒に渡すと `vendor_id` が消える）。
- **Electron を更新する時の確認事項**: `mediaSize` は Electron の非公開オプションなので、`pageSize` を渡さない時に `mediaSize` がそのまま Chromium へ渡ることを確認する（`docs/02` 第5章の `window.printAPI` の行にも書いた）。
- 実際のプリンターで用紙が切り替わるかは、手で確かめる筋書き 7 で確認していただく（自動の試験と起動確認では、用紙に印刷しない）。

### ② プレビューの滲み（確定事項C27 の補足）

- 原因 1: `renderer/print-preview.js` は、用紙幅から解像度を決めて canvas を描き、CSS（`width:100%; height:100%`）で黒い枠の内側いっぱいに広げていた。高さは丸め方の違いで 1 画素ずれることがあり、画像全体が引き伸ばされて滲んだ（例: A4 縦を拡大率 125% で表示すると、描いた画像は 240 × 339 画素、表示は 240 × 340 画素。B5 (JIS) 縦は拡大率 100% でもずれた）。
- 原因 2: `renderer/print-sheet-render.js` の `paste` は、ページ画像を小数の位置とサイズでシート画像に貼っていた。貼る時にもう一度補間されて滲んだ（印刷するシート画像も同じ）。
- 修正 1: `paperLayout(sheet, devicePixelRatio)` で、枠に収める倍率に devicePixelRatio を掛けた解像度で canvas を描き、canvas の表示サイズと黒い枠の内側を「画素数 ÷ devicePixelRatio」にする（インラインの style。`renderer/print-dialog.css` の `width:100%; height:100%` は削除した）。描いた画素を拡大縮小せずに表示する。devicePixelRatio が 1 の時の枠の大きさは修正前と同じ。
- 修正 2: `snapRect` で貼り付け先の四辺を画素単位にそろえ、ページ画像（`renderToCanvas` が画素数を四捨五入して描く。差は 1 画素以内）を拡大縮小せずに `drawImage(画像, 0, 0)` で貼る。差が 1 画素を超える時（画素数の上限で倍率を下げて描いた時）だけ伸ばす。90 度の回転は、回転行列の成分（0, 1, −1, 0）を直接指定する（`rotate(Math.PI / 2)` では cos が 0 にならず、画素の位置がわずかにずれるため）。
- 修正 3: 印刷画面の題名バーをドラッグした位置を、デバイスピクセル単位にそろえる（`renderer/print-dialog-keys.js` の `snapToDevicePixel`）。開いた時の中央配置は変えていない（位置が 0.5 px ずれても、Chromium は canvas を描く時に位置と大きさをデバイスピクセルにそろえる。canvas の表示サイズがデバイスピクセルの整数になったので、拡大縮小はされない）。
- 限界: プレビューは用紙を 210 × 276 px の枠に縮小した絵なので、小さい文字は読めない。修正したのは、縮小に加えて起きていた滲み。

### ⑤ 印刷の解像度を 300 dpi にする（確定事項C5・C14 の改訂。spec-1-4 確定事項31・32）

- 原因: シート画像を 150 dpi（pdf.js の印刷と同じ値）で作っていた。600 dpi のプリンターでは縦横 4 倍に拡大され、文字の輪郭が滲んだ。② の原因 2 も重なっていた。
- 修正: `renderer/print-job.js` の `PRINT_DPI` を 300 にした（A4 1 枚 2480 × 3508 画素、A3 1 枚 3508 × 4961 画素）。`renderer/print.js` の重複定数をやめ、`SigK.print.PRINT_DPI`・`PRINT_SCALE` は `print-job.js` の値を返す。
- シート画像の画素数に上限を付けた（1 枚 4,000 万画素・1 辺 16,384 画素。`renderer/mosaic-save.js` と同じ値）。上限を超える大きな用紙は、その用紙だけ解像度を下げる（`print-sheet-render.js` の `cappedDpi`。A2 までは 300 dpi のまま）。
- シート画像は、PNG の data URL（base64 で 1.33 倍の文字列）ではなく、Blob の URL にした（`renderer/page-image.js` の `toObjectUrl`）。送り終えた時・中止した時・失敗した時に `revokeUrl` で解放する（`print-job.js` の `releaseImages`、`print.js` の `run`・`abandon`）。`SigK.print.prepare`（試験と起動確認）で並べた画像は、次の準備・［印刷］・中止の時に解放する。
- ［印刷］で最初の印刷分を `#print-area` に 2 回並べていた（準備と送信）のを、送信の 1 回にした（`prepareImages` の `place: false`）。
- 600 dpi にしない理由: 画素数・時間・メモリーが 300 dpi の 4 倍になる。
- ツールモードの「PDF → 画像」の解像度の説明を、150 dpi「標準解像度」・300 dpi「印刷時と同じ解像度・細かい文字用」に変更した（既定の 150 dpi は変えない。`spec-3-3`）。
